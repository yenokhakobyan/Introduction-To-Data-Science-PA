## 📊 DESCRIPTIVE STATISTICS: The Foundation of Data Understanding

### Central Tendency Measures

**Arithmetic Mean (μ or x̄)**
```
Population Mean: μ = (Σx_i) / N
Sample Mean: x̄ = (Σx_i) / n

Where:
- Σx_i = sum of all observations
- N = population size
- n = sample size
```

**Why this matters:** The mean gives you the "center of gravity" of your data distribution. However, it's sensitive to outliers, which is why understanding when to use alternatives is crucial. In retail data, for example, a few very large purchases can skew the mean customer spending, making it less representative of typical customer behavior.

**Median (M or x̃)**
```
For odd n: Median = x_(n+1)/2
For even n: Median = (x_n/2 + x_(n+2)/2) / 2

Where x_i represents the i-th value in sorted order
```

**Mathematical insight:** The median is the 50th percentile, making it robust to outliers. When your data is skewed (which is common in real-world datasets), the median often provides a better sense of "typical" values than the mean.

**Mode**
```
Mode = value that appears most frequently in dataset

For continuous data, use:
Mode ≈ 3 × Median - 2 × Mean (empirical relationship for unimodal distributions)
```

### Variability Measures

**Variance and Standard Deviation**
```
Population Variance: σ² = Σ(x_i - μ)² / N
Sample Variance: s² = Σ(x_i - x̄)² / (n-1)

Population Standard Deviation: σ = √(σ²)
Sample Standard Deviation: s = √(s²)
```

**Deep understanding:** The division by (n-1) instead of n in sample variance is called Bessel's correction. This adjustment compensates for the fact that we're using the sample mean instead of the true population mean, which tends to underestimate variance. This correction becomes less important as sample size increases, but it's crucial for small samples.

**Coefficient of Variation (CV)**
```
CV = (σ/μ) × 100% for population
CV = (s/x̄) × 100% for sample
```

**Practical application:** CV is unitless, making it perfect for comparing variability across different scales. For instance, comparing the variability of daily sales (in dollars) versus customer visit counts (in people) requires CV rather than standard deviation.

**Interquartile Range (IQR)**
```
IQR = Q3 - Q1

Where:
Q1 = 25th percentile
Q3 = 75th percentile

Outlier detection:
Lower bound = Q1 - 1.5 × IQR
Upper bound = Q3 + 1.5 × IQR
```

**Why IQR matters:** Unlike standard deviation, IQR is resistant to outliers. This makes it invaluable for understanding the spread of your "typical" data points, excluding extreme values that might distort your analysis.

### Distribution Shape Measures

**Skewness**
```
Sample Skewness: g₁ = [n/(n-1)(n-2)] × Σ[(x_i - x̄)/s]³

Interpretation:
- g₁ = 0: Symmetric distribution
- g₁ > 0: Right-skewed (positive skew)
- g₁ < 0: Left-skewed (negative skew)
- |g₁| > 2: Highly skewed
```

**Business interpretation:** In business data, positive skew is extremely common. Think about income distribution, where most people earn moderate amounts but a few earn extremely high amounts, creating a long right tail.

**Kurtosis**
```
Sample Kurtosis: g₂ = [n(n+1)/((n-1)(n-2)(n-3))] × Σ[(x_i - x̄)/s]⁴ - [3(n-1)²/((n-2)(n-3))]

Interpretation:
- g₂ = 0: Normal kurtosis (mesokurtic)
- g₂ > 0: Heavy tails (leptokurtic)
- g₂ < 0: Light tails (platykurtic)
```

**Practical insight:** High kurtosis indicates that your data has more extreme values than a normal distribution would suggest. This is crucial for risk assessment and outlier detection strategies.

## 📈 CORRELATION AND RELATIONSHIPS: Understanding Data Connections

### Pearson Correlation Coefficient

**Formula**
```
Population: ρ = Σ[(x_i - μₓ)(y_i - μᵧ)] / [√(Σ(x_i - μₓ)²) × √(Σ(y_i - μᵧ)²)]

Sample: r = Σ[(x_i - x̄)(y_i - ȳ)] / [√(Σ(x_i - x̄)²) × √(Σ(y_i - ȳ)²)]

Alternative computational form:
r = [n(Σx_i y_i) - (Σx_i)(Σy_i)] / [√(n(Σx_i²) - (Σx_i)²) × √(n(Σy_i²) - (Σy_i)²)]
```

**Critical understanding:** Pearson correlation measures linear relationships only. A correlation of 0 doesn't mean no relationship exists; it means no linear relationship exists. This is why visualizing your data is crucial before relying on correlation coefficients.

**Interpretation guidelines:**
- |r| < 0.3: Weak relationship
- 0.3 ≤ |r| < 0.7: Moderate relationship  
- |r| ≥ 0.7: Strong relationship

### Spearman Rank Correlation

**Formula**
```
ρₛ = 1 - (6 × Σd_i²) / [n(n² - 1)]

Where:
- d_i = difference between ranks of x_i and y_i
- n = number of observations

General formula (handles ties):
ρₛ = Σ[(R(x_i) - R̄(x))(R(y_i) - R̄(y))] / [√(Σ(R(x_i) - R̄(x))²) × √(Σ(R(y_i) - R̄(y))²)]
```

**When to use Spearman:** Use Spearman correlation when you suspect non-linear but monotonic relationships, or when your data contains outliers that might distort Pearson correlation. Spearman is also appropriate for ordinal data.

### Covariance

**Formula**
```
Population: σₓᵧ = Σ[(x_i - μₓ)(y_i - μᵧ)] / N
Sample: s_xy = Σ[(x_i - x̄)(y_i - ȳ)] / (n-1)

Relationship to correlation:
r = s_xy / (s_x × s_y)
```

**Understanding covariance:** While correlation is standardized (always between -1 and 1), covariance retains the units of your original variables. This makes covariance useful for certain calculations but correlation better for interpretation.

## 🔄 PROBABILITY FUNDAMENTALS: Understanding Uncertainty

### Basic Probability Rules

**Addition Rule**
```
P(A ∪ B) = P(A) + P(B) - P(A ∩ B)

For mutually exclusive events:
P(A ∪ B) = P(A) + P(B)
```

**Multiplication Rule**
```
P(A ∩ B) = P(A) × P(B|A) = P(B) × P(A|B)

For independent events:
P(A ∩ B) = P(A) × P(B)
```

**Bayes' Theorem**
```
P(A|B) = [P(B|A) × P(A)] / P(B)

Expanded form:
P(A|B) = [P(B|A) × P(A)] / [P(B|A) × P(A) + P(B|A') × P(A')]
```

**EDA application:** Bayes' theorem is fundamental for understanding conditional relationships in your data. For example, what's the probability a customer makes a large purchase given they've visited multiple product categories?

### Common Probability Distributions

**Normal Distribution**
```
Probability Density Function:
f(x) = (1/σ√(2π)) × e^(-½((x-μ)/σ)²)

Standardization:
Z = (X - μ) / σ

Where Z ~ N(0,1)
```

**Practical importance:** Many statistical methods assume normality. Understanding when your data deviates from normality helps you choose appropriate analysis techniques.

**Binomial Distribution**
```
P(X = k) = C(n,k) × p^k × (1-p)^(n-k)

Where:
- C(n,k) = n! / [k!(n-k)!]
- n = number of trials
- k = number of successes
- p = probability of success on each trial

Mean: μ = np
Variance: σ² = np(1-p)
```

**EDA application:** Perfect for analyzing binary outcomes in your data, such as conversion rates, success rates, or any yes/no phenomena.

**Poisson Distribution**
```
P(X = k) = (λ^k × e^(-λ)) / k!

Where:
- λ = average rate of occurrence
- k = number of events

Mean: μ = λ
Variance: σ² = λ
```

**Business application:** Excellent for modeling count data such as number of customers per hour, defects per batch, or website visits per day.

## 🔢 LINEAR ALGEBRA ESSENTIALS: Transformations and Relationships

### Matrix Operations for Data Analysis

**Matrix Multiplication for Data Transformation**
```
For matrices A(m×n) and B(n×p):
C = AB where c_ij = Σ(k=1 to n) a_ik × b_kj

Data matrix X(n×p): n observations, p variables
Correlation matrix: R = (1/(n-1)) × X'X (for standardized data)
```

**Understanding data matrices:** Think of your dataset as a matrix where each row represents an observation and each column represents a variable. Matrix operations allow you to transform your entire dataset systematically.

**Eigenvalues and Eigenvectors (for PCA)**
```
For square matrix A:
Av = λv

Where:
- v = eigenvector
- λ = eigenvalue

Characteristic equation: det(A - λI) = 0
```

**PCA Application:**
```
Steps for Principal Component Analysis:
1. Standardize data: X_std = (X - μ) / σ
2. Calculate covariance matrix: C = X_std' × X_std / (n-1)
3. Find eigenvalues and eigenvectors of C
4. Sort by eigenvalue magnitude
5. Project data: Y = X_std × V

Where V contains the eigenvectors (principal components)
```

**Why PCA matters:** PCA helps you reduce dimensionality while preserving the most important variance in your data. The eigenvalues tell you how much variance each principal component captures.

### Distance Measures

**Euclidean Distance**
```
d(x,y) = √[Σ(x_i - y_i)²]

For standardized variables:
d_std(x,y) = √[Σ((x_i - μ_x)/σ_x - (y_i - μ_y)/σ_y)²]
```

**Manhattan Distance**
```
d(x,y) = Σ|x_i - y_i|
```

**Cosine Similarity**
```
cos(θ) = (x · y) / (||x|| × ||y||) = Σ(x_i × y_i) / [√(Σx_i²) × √(Σy_i²)]

Cosine Distance = 1 - cos(θ)
```

**Choosing distance measures:** Euclidean distance works well for continuous variables of similar scales. Manhattan distance is more robust to outliers. Cosine similarity focuses on the angle between vectors, making it ideal for high-dimensional sparse data.

## 📊 STATISTICAL INFERENCE: Making Data-Driven Conclusions

### Confidence Intervals

**For Population Mean (σ known)**
```
CI = x̄ ± z_(α/2) × (σ/√n)

Where z_(α/2) is the critical value from standard normal distribution
```

**For Population Mean (σ unknown, small sample)**
```
CI = x̄ ± t_(α/2,n-1) × (s/√n)

Where t_(α/2,n-1) is the critical value from t-distribution
```

**For Population Proportion**
```
CI = p̂ ± z_(α/2) × √[p̂(1-p̂)/n]

Where p̂ = sample proportion = x/n
```

**Practical interpretation:** A 95% confidence interval means that if you repeated your sampling process many times, about 95% of the intervals you construct would contain the true population parameter.

### Hypothesis Testing Framework

**General Structure:**
```
H₀: Null hypothesis (status quo)
H₁: Alternative hypothesis (what we want to prove)

Test statistic = (Sample statistic - Hypothesized parameter) / Standard error

P-value = P(observing test statistic or more extreme | H₀ is true)

Decision rule:
- If p-value ≤ α: Reject H₀
- If p-value > α: Fail to reject H₀
```

**t-test for Population Mean**
```
t = (x̄ - μ₀) / (s/√n)

Degrees of freedom: df = n - 1
```

**Chi-square Test for Independence**
```
χ² = ΣΣ[(O_ij - E_ij)²/E_ij]

Where:
- O_ij = observed frequency in cell (i,j)
- E_ij = expected frequency = (Row_i total × Column_j total) / Grand total

Degrees of freedom: df = (rows - 1) × (columns - 1)
```

**EDA application:** Use chi-square tests to determine if categorical variables in your dataset are independent of each other.

## 🔍 ADVANCED EDA TECHNIQUES: Sophisticated Pattern Detection

### Information Theory Measures

**Entropy**
```
H(X) = -Σ p(x_i) × log₂(p(x_i))

Where p(x_i) = probability of outcome x_i
```

**Mutual Information**
```
I(X;Y) = ΣΣ p(x,y) × log₂[p(x,y)/(p(x) × p(y))]

Normalized Mutual Information:
NMI(X,Y) = 2 × I(X;Y) / [H(X) + H(Y)]
```

**Why mutual information matters:** Unlike correlation, mutual information can capture non-linear relationships between variables. It's particularly useful for feature selection and understanding dependencies in categorical data.

### Robust Statistics

**Median Absolute Deviation (MAD)**
```
MAD = median(|x_i - median(x)|)

Robust standard deviation estimate:
σ_robust = 1.4826 × MAD
```

**Trimmed Mean**
```
Trimmed Mean (α% trimmed) = mean of middle (100-2α)% of ordered data

For 20% trimmed mean: remove 10% from each tail
```

**When to use robust statistics:** When your data contains outliers or follows non-normal distributions, robust statistics provide more reliable measures of central tendency and spread.

### Time Series Decomposition

**Additive Model**
```
Y(t) = Trend(t) + Seasonal(t) + Error(t)

Moving Average Trend:
T̂(t) = Σ(k=-m to m) Y(t+k) / (2m+1)
```

**Multiplicative Model**
```
Y(t) = Trend(t) × Seasonal(t) × Error(t)

Log transformation converts to additive:
log(Y(t)) = log(Trend(t)) + log(Seasonal(t)) + log(Error(t))
```

**Autocorrelation Function**
```
r_k = Σ(t=1 to n-k)[(y_t - ȳ)(y_(t+k) - ȳ)] / Σ(t=1 to n)(y_t - ȳ)²

Where k = lag
```

**Understanding autocorrelation:** This measures how correlated a time series is with itself at different time lags. It's crucial for understanding temporal patterns and determining appropriate forecasting models.

## 🎯 FEATURE ENGINEERING MATHEMATICS: Creating Predictive Variables

### Scaling and Normalization

**Min-Max Scaling**
```
x_scaled = (x - min(x)) / (max(x) - min(x))

Result: values between 0 and 1
```

**Z-score Standardization**
```
x_standardized = (x - μ) / σ

Result: mean = 0, standard deviation = 1
```

**Robust Scaling**
```
x_robust = (x - median(x)) / IQR(x)

Where IQR = Q3 - Q1
```

**When to use each:** Min-max scaling preserves relationships but is sensitive to outliers. Z-score standardization assumes normality. Robust scaling is best when you have outliers.

### Polynomial Features

**Polynomial Expansion**
```
For degree d and features [x₁, x₂]:
Degree 1: [1, x₁, x₂]
Degree 2: [1, x₁, x₂, x₁², x₁x₂, x₂²]
Degree 3: [1, x₁, x₂, x₁², x₁x₂, x₂², x₁³, x₁²x₂, x₁x₂², x₂³]

Number of features = C(n+d, d) where n = original features
```

### Binning Strategies

**Equal-Width Binning**
```
Bin width = (max(x) - min(x)) / number_of_bins
Bin edges = [min(x) + i × bin_width for i in range(number_of_bins + 1)]
```

**Equal-Frequency Binning (Quantile-Based)**
```
For k bins:
Bin edges = quantiles at [0, 1/k, 2/k, ..., (k-1)/k, 1]
```

**Optimal Binning (Sturges' Rule)**
```
Number of bins = ⌈log₂(n) + 1⌉

Where n = number of observations
```

## 🧮 PRACTICAL APPLICATION GUIDE

### Choosing the Right Mathematical Tool

**For Understanding Central Tendency:**
- Use mean when data is roughly symmetric and you need to preserve mathematical properties
- Use median when data is skewed or contains outliers
- Use mode for categorical data or to understand most common values

**For Measuring Relationships:**
- Use Pearson correlation for linear relationships between continuous variables
- Use Spearman correlation for monotonic relationships or ordinal data
- Use chi-square for relationships between categorical variables
- Use mutual information for non-linear relationships

**For Detecting Outliers:**
- Use IQR method (Q1 - 1.5×IQR, Q3 + 1.5×IQR) for robust detection
- Use z-score method (|z| > 3) when data is approximately normal
- Use modified z-score with MAD for non-normal data

**For Feature Engineering:**
- Use polynomial features when you suspect non-linear relationships
- Use interaction terms when variables might have multiplicative effects
- Use binning when relationships are non-monotonic or you need interpretability

### Common Mathematical Pitfalls in EDA

**Simpson's Paradox:** A trend that appears in different groups disappears or reverses when groups are combined. Always examine relationships both within groups and across the entire dataset.

**Correlation vs Causation:** High correlation doesn't imply causation. Use your domain knowledge and consider confounding variables.

**Multiple Testing Problem:** When conducting many statistical tests, the probability of finding false positives increases. Consider adjusting significance levels using methods like Bonferroni correction.

**Sample Size Effects:** Very large samples can make trivial differences statistically significant, while very small samples might miss important relationships. Always consider practical significance alongside statistical significance.

This mathematical foundation provides the quantitative rigor necessary for professional-quality EDA. Remember that these formulas are tools to help you understand patterns in your data. The key to effective EDA is knowing which mathematical tool to apply in each situation and understanding what the results mean in the context of your specific business problem.

Practice applying these concepts to real datasets, and you'll develop the mathematical intuition that distinguishes expert data analysts from those who simply know how to use software tools.

## 1. Introduction to EDA & Dataset Overview

### What is Exploratory Data Analysis and Why Does It Matter?

Exploratory Data Analysis is fundamentally about having a conversation with your data before you start building models or making business decisions. Think of EDA as being similar to getting to know a new city before you try to navigate it. You wouldn't jump straight into the subway system without first understanding the layout of the neighborhoods, the main transportation hubs, and the general patterns of how people move around.

In the context of machine learning and business analytics, EDA serves four interconnected purposes that build upon each other. First, you need to understand the structure of your data - this means knowing what variables you have, what types they are, and how they relate to each other conceptually. This is like learning the basic geography of your new city. Second, you assess the quality of your data by identifying missing values, outliers, inconsistencies, and potential errors. This is equivalent to identifying which roads might be under construction or which areas might be unsafe to travel through.

Third, you discover patterns in your data by exploring distributions, relationships between variables, trends over time, and other systematic behaviors. This is like learning the rhythm of the city - when rush hour happens, which areas are busiest at different times, and how different neighborhoods have different characteristics. Finally, you generate hypotheses about what might be driving the patterns you observe, which gives you direction for deeper analysis and modeling. This is like forming theories about why certain areas are more popular or what factors influence traffic patterns.

The beauty of EDA is that it's an iterative process. Each discovery leads to new questions, and each question leads to new analyses. This iterative nature is especially important when working with complex datasets like time series data, where patterns can exist at multiple time scales and interactions between variables can be subtle and non-obvious.

### Understanding Correlation in Retail Context

Correlation analysis in retail data requires careful interpretation because of the complex causal relationships involved. Unlike experimental data where you might expect simple relationships, retail data involves feedback loops, confounding variables, and multiple causal pathways operating simultaneously.

For example, if you find a correlation between temperature and sales, it could be because temperature affects customer behavior directly, because temperature is correlated with seasonality which affects demand, because temperature affects supply chain operations, or because temperature interacts with other variables like holidays or promotions in complex ways.

from pyspark.sql.window import Window

# Create windows for temporal analysis
store_product_window = Window.partitionBy("store_id", "product_id").orderBy("date")

# Calculate stockout impact
stockout_analysis = df.withColumn(
    "had_stockout", when(col("stock_hour6_22_cnt") > 0, 1).otherwise(0)
).withColumn(
    # Sales before stockout (5-day average)
    "sales_before_stockout", avg("sale_amount").over(
        store_product_window.rowsBetween(-5, -1)
    )
).withColumn(
    # Sales after stockout returns to normal
    "sales_after_stockout", avg("sale_amount").over(
        store_product_window.rowsBetween(1, 5)
    )
).withColumn(
    # Estimated lost sales (simple approximation)
    "estimated_lost_sales", 
    when(col("had_stockout") == 1, 
         col("sales_before_stockout") * (col("stock_hour6_22_cnt") / 16.0)
    ).otherwise(0)
)

# Aggregate stockout impact by product
stockout_impact = stockout_analysis.groupBy("product_id", "management_group_id") \
    .agg(
        sum("estimated_lost_sales").alias("total_estimated_lost_sales"),
        mean("stock_hour6_22_cnt").alias("avg_stockout_hours"),
        sum("had_stockout").alias("stockout_days"),
        count("*").alias("total_days")
    ) \
    .withColumn("stockout_rate", col("stockout_days") / col("total_days")) \
    .filter(col("total_days") > 30) \
    .orderBy(desc("total_estimated_lost_sales"))

print("Products with highest estimated lost sales due to stockouts:")

).withColumn(

# Advanced time series feature engineering
def create_advanced_time_features(df):
    """Create comprehensive time series features"""
    
    # Define window specifications
    store_product_window = Window.partitionBy("store_id", "product_id").orderBy("date")
    
    # Lag features
    df_advanced = df.withColumn("sales_lag1", lag("sale_amount", 1).over(store_product_window)) \
                   .withColumn("sales_lag3", lag("sale_amount", 3).over(store_product_window)) \
                   .withColumn("sales_lag7", lag("sale_amount", 7).over(store_product_window)) \
                   .withColumn("sales_lag14", lag("sale_amount", 14).over(store_product_window)) \
                   .withColumn("sales_lag30", lag("sale_amount", 30).over(store_product_window))
    
    # Rolling statistics (multiple windows)
    for window_size in [3, 7, 14, 30]:
        window_spec = store_product_window.rowsBetween(-window_size, -1)
        
        df_advanced = df_advanced.withColumn(f"rolling_mean_{window_size}d", 
                                           avg("sale_amount").over(window_spec)) \
                                .withColumn(f"rolling_std_{window_size}d",
                                          stddev("sale_amount").over(window_spec)) \
                                .withColumn(f"rolling_min_{window_size}d",
                                          min("sale_amount").over(window_spec)) \
                                .withColumn(f"rolling_max_{window_size}d", 
                                          max("sale_amount").over(window_spec))
    
    # Trend direction features
    df_advanced = df_advanced.withColumn(
        "trend_3d", 
        when(col("sale_amount") > col("rolling_mean_3d"), 1)
        .when(col("sale_amount") < col("rolling_mean_3d"), -1)
        .otherwise(0)
    ).withColumn(
        "trend_7d",
        when(col("sale_amount") > col("rolling_mean_7d"), 1) 
        .when(col("sale_amount") < col("rolling_mean_7d"), -1)
        .otherwise(0)
    )
    
    # Seasonality strength (deviation from longer-term average)
    df_advanced = df_advanced.withColumn(
        "seasonality_strength_7d",
        abs(col("sale_amount") - col("rolling_mean_7d")) / (col("rolling_mean_7d") + 0.001)
    ).withColumn(
        "seasonality_strength_30d", 
        abs(col("sale_amount") - col("rolling_mean_30d")) / (col("rolling_mean_30d") + 0.001)
    )
    
    # Cyclical encodings for temporal variables
    df_advanced = df_advanced.withColumn("day_of_week", dayofweek("date")) \
                           .withColumn("month", month("date")) \
                           .withColumn("day_of_month", dayofmonth("date"))
    
    # Cyclical encoding using trigonometric functions
    df_advanced = df_advanced.withColumn("dow_sin", sin(2 * pi() * col("day_of_week") / 7)) \
                           .withColumn("dow_cos", cos(2 * pi() * col("day_of_week") / 7)) \
                           .withColumn("month_sin", sin(2 * pi() * col("month") / 12)) \
                           .withColumn("month_cos", cos(2 * pi() * col("month") / 12)) \
                           .withColumn("dom_sin", sin(2 * pi() * col("day_of_month") / 31)) \
                           .withColumn("dom_cos", cos(2 * pi() * col("day_of_month") / 31))
    
    # Anomaly detection features
    df_advanced = df_advanced.withColumn(
        "z_score_7d",
        (col("sale_amount") - col("rolling_mean_7d")) / (col("rolling_std_7d") + 0.001)
    ).withColumn(
        "is_anomaly_7d", 
        when(abs(col("z_score_7d")) > 2.5, 1).otherwise(0)
    )
    
    # Relative performance features
    df_advanced = df_advanced.withColumn(
        "relative_to_7d_avg", 
        col("sale_amount") / (col("rolling_mean_7d") + 0.001)
    ).withColumn(
        "relative_to_30d_avg",
        col("sale_amount") / (col("rolling_mean_30d") + 0.001)
    )
    
    return df_advanced

def create_business_intelligence_dataset(df):
    """Create comprehensive BI dataset with KPIs and insights"""
    
    # 1. Daily KPIs
    daily_kpis = df.groupBy("date") \
        .agg(
            sum("sale_amount").alias("total_daily_revenue"),
            mean("sale_amount").alias("avg_product_sales"),
            count("*").alias("total_transactions"),
            countDistinct("store_id").alias("active_stores"),
            countDistinct("product_id").alias("active_products"),
            sum("stock_hour6_22_cnt").alias("total_stockout_hours"),
            avg("discount").alias("avg_discount_rate"),
            sum(when(col("holiday_flag") == 1, 1).otherwise(0)).alias("holiday_transactions"),
            sum(when(col("activity_flag") == 1, 1).otherwise(0)).alias("promo_transactions")
        ) \
        .withColumn("stockout_rate", col("total_stockout_hours") / (col("total_transactions") * 16)) \
        .withColumn("avg_revenue_per_transaction", col("total_daily_revenue") / col("total_transactions")) \
        .withColumn("day_of_week", dayofweek("date")) \
        .withColumn("is_weekend", when(dayofweek("date").isin([1, 7]), 1).otherwise(0))
    
    # 2. Store performance analysis
    store_performance = df.groupBy("store_id", "city_id") \
        .agg(
            sum("sale_amount").alias("total_store_revenue"),
            mean("sale_amount").alias("avg_product_sales"),
            count("*").alias("total_transactions"),
            countDistinct("product_id").alias("unique_products_sold"),
            avg("stock_hour6_22_cnt").alias("avg_stockout_hours"),
            avg("discount").alias("avg_discount_rate"),
            stddev("sale_amount").alias("sales_volatility")
        ) \
        .withColumn("revenue_per_product", col("total_store_revenue") / col("unique_products_sold")) \
        .withColumn("sales_efficiency", col("avg_product_sales") / (col("avg_stockout_hours") + 1))
    
    # Add store performance rankings
    store_rankings = store_performance.withColumn(
        "revenue_rank", 
        row_number().over(Window.orderBy(desc("total_store_revenue")))
    ).withColumn(
        "efficiency_rank",
        row_number().over(Window.orderBy(desc("sales_efficiency")))
    ).withColumn(
        "performance_tier",
        when(col("revenue_rank") <= 50, "Top_Performers")
        .when(col("revenue_rank") <= 200, "Above_Average")
        .when(col("revenue_rank") <= 500, "Average")
        .otherwise("Below_Average")
    )
    
    # 3. Product performance categories
    product_performance = df.groupBy("product_id", "management_group_id", 
                                   "first_category_id", "second_category_id") \
        .agg(
            sum("sale_amount").alias("total_product_revenue"),
            mean("sale_amount").alias("avg_daily_sales"),
            count("*").alias("total_selling_days"),
            countDistinct("store_id").alias("stores_carrying_product"),
            avg("stock_hour6_22_cnt").alias("avg_stockout_hours"),
            stddev("sale_amount").alias("sales_volatility"),
            avg("discount").alias("avg_discount_needed")
        ) \
        .withColumn("revenue_per_store", col("total_product_revenue") / col("stores_carrying_product")) \
        .withColumn("availability_score", (16 - col("avg_stockout_hours")) / 16) \
        .withColumn("velocity_score", col("avg_daily_sales") / (col("avg_discount_needed") + 0.001))
    
    # Product categorization based on performance metrics
    product_categories = product_performance.withColumn(
        "performance_category",
        when((col("total_product_revenue") > 1000) & (col("sales_volatility") < 0.5), "Star_Performer")
        .when((col("total_product_revenue") > 500) & (col("availability_score") > 0.8), "Steady_Seller") 
        .when((col("avg_stockout_hours") > 8) & (col("total_product_revenue") > 200), "High_Demand_Constrained")
        .when(col("total_product_revenue") < 50, "Low_Performer")
        .when(col("sales_volatility") > 1.5, "Volatile_Product")
        .otherwise("Average_Performer")
    ).withColumn(
        "inventory_recommendation",
        when(col("performance_category") == "High_Demand_Constrained", "Increase_Stock")
        .when(col("performance_category") == "Low_Performer", "Consider_Discontinuation")
        .when(col("performance_category") == "Volatile_Product", "Dynamic_Inventory")
        .when(col("performance_category") == "Star_Performer", "Maintain_Premium_Stock")
        .otherwise("Standard_Inventory")
    )
    
    # 4. Revenue impact analysis
    # Weather impact on revenue
    weather_impact = df.groupBy("city_id") \
        .agg(
            corr("sale_amount", "avg_temperature").alias("temperature_correlation"),
            corr("sale_amount", "precpt").alias("precipitation_correlation"), 
            corr("sale_amount", "avg_humidity").alias("humidity_correlation")
        ) \
        .withColumn("weather_sensitivity_score",
                   abs(col("temperature_correlation")) + 
                   abs(col("precipitation_correlation")) + 
                   abs(col("humidity_correlation")))
    
    # Discount effectiveness analysis
    discount_effectiveness = df.groupBy("product_id") \
        .agg(
            corr("sale_amount", "discount").alias("discount_elasticity"),
            avg(when(col("discount") < 1.0, col("sale_amount"))).alias("avg_sales_with_discount"),
            avg(when(col("discount") == 1.0, col("sale_amount"))).alias("avg_sales_without_discount")
        ) \
        .withColumn("discount_lift", 
                   (col("avg_sales_with_discount") - col("avg_sales_without_discount")) / 
                   col("avg_sales_without_discount")) \
        .withColumn("discount_effectiveness",
                   when(col("discount_lift") > 0.2, "Highly_Effective")
                   .when(col("discount_lift") > 0.05, "Moderately_Effective")
                   .when(col("discount_lift") > -0.05, "Neutral")
                   .otherwise("Counterproductive"))
    
    # 5. Comprehensive insights summary
    insights_summary = {
        'daily_kpis': daily_kpis,
        'store_performance': store_rankings,
        'product_categories': product_categories, 
        'weather_impact': weather_impact,
        'discount_effectiveness': discount_effectiveness
    }
    
    return insights_summary

## 5. Creating New Features from Raw Data

### Feature Engineering Philosophy for Retail Data

Feature engineering is where domain knowledge meets data science. In retail, successful feature engineering requires understanding customer behavior, business operations, and market dynamics. The goal is to create variables that capture the underlying business logic that drives demand.

For time series retail data like FreshRetailNet-50K, feature engineering operates at multiple levels: we can create features within individual time series (trends, seasonality, lags), across time series (relative performance, market share), and by incorporating external information (weather effects, calendar effects).

The features we create should serve two purposes: they should be interpretable from a business perspective (so stakeholders can understand and trust the model), and they should be predictive (so the model performs well). Sometimes these goals are in tension, but in retail, interpretable features often turn out to be predictive because retail behavior follows logical patterns.

## 6. Wrap-Up & Resources

### How to Present EDA Findings Effectively

Your EDA should tell a coherent story about your data. Here's a framework for organizing your findings:

**1. Executive Summary (2-3 key insights)**
- Start with the most important findings that impact business decisions
- Use specific numbers: "20% of product-days experience stockouts, correlating with 15% lower sales"
- Connect insights to business value: "Improving stock availability could increase revenue by X%"

**2. Data Quality Assessment** 
- Document any data quality issues and how you handled them
- Explain the impact of missing data or anomalies on downstream analysis
- Provide confidence levels in your findings

**3. Key Patterns and Relationships**
- Present visualizations that support your main insights
- Explain both what you found and what you didn't find (negative results are valuable)
- Connect statistical findings to business logic

**4. Recommendations for Next Steps**
- Based on your EDA, what analyses should be done next?
- What additional data would be valuable to collect?
- What modeling approaches are suggested by your findings?

#!/usr/bin/env python3
"""
FreshRetailNet-50K EDA Pipeline
Production-ready exploratory data analysis pipeline with comprehensive testing

import os

# PySpark imports

# Data and visualization imports

# Configure logging

logger = logging.getLogger(__name__)

class FreshRetailEDAConfig:
    """Configuration class for EDA pipeline"""
    
    def __init__(self, config_path: Optional[str] = None):

        self.analysis_config = {

            "outlier_threshold": 2.5,     # Z-score threshold for outliers
            "min_observations_for_analysis": 50,
            "rolling_window_days": 7,
            "output_directory": "eda_output"
        }
        
        # Load custom config if provided
        if config_path and os.path.exists(config_path):
            with open(config_path, 'r') as f:
                custom_config = json.load(f)
                self.analysis_config.update(custom_config.get('analysis', {}))
                self.spark_config.update(custom_config.get('spark', {}))

class FreshRetailEDAEngine:
    """Main EDA engine for FreshRetailNet-50K dataset"""
    
    def __init__(self, config: FreshRetailEDAConfig):
        self.config = config
        self.spark = None
        self.df = None
        self.results = {}
        
    def initialize_spark(self) -> SparkSession:
        """Initialize Spark session with optimized configuration"""
        try:
            builder = SparkSession.builder
            for key, value in self.config.spark_config.items():
                builder = builder.config(key, value)
            
            self.spark = builder.getOrCreate()

            return self.spark
            
        except Exception as e:
            logger.error(f"Failed to initialize Spark session: {e}")
            raise
    
    def load_data(self) -> None:
        """Load and prepare the FreshRetailNet-50K dataset"""
        try:
            logger.info("Loading FreshRetailNet-50K dataset from Hugging Face...")
            
            # Load dataset
            ds = load_dataset("Dingdong-Inc/FreshRetailNet-50K", split="train")
            ds.to_parquet("train.parquet")

            # Convert to Spark DataFrame
            self.df = self.spark.read.parquet("train.parquet")
            
            # Basic data preparation
            self.df = self.df.withColumn("date", F.to_date(F.col("dt"), "yyyy-MM-dd"))
            
            # Cache for performance
            self.df.cache()
            
            # Validate data loading
            row_count = self.df.count()
            col_count = len(self.df.columns)
            
            logger.info(f"✓ Dataset loaded: {row_count:,} rows, {col_count} columns")
            self.results['data_loading'] = {
                'row_count': row_count,
                'column_count': col_count,
                'load_timestamp': datetime.now().isoformat()
            }
            
        except Exception as e:
            logger.error(f"Failed to load data: {e}")
            raise
    
    def run_data_quality_checks(self) -> Dict[str, Any]:
        """Comprehensive data quality assessment"""
        logger.info("Running data quality checks...")
        
        quality_results: Dict[str, Any] = {}
        
        try:
            total_rows = self.df.count()
            
            # --- Missing value analysis ---
            missing_analysis: List[Dict[str, Any]] = []
            for col_name in self.df.columns:
                # Skip arrays for simple null counting
                if col_name not in ['hours_sale', 'hours_stock_status']:
                    null_count = self.df.filter(F.col(col_name).isNull()).count()
                    missing_pct = (null_count / total_rows) * 100 if total_rows else 0.0
                    missing_analysis.append({
                        'column': col_name,
                        'null_count': int(null_count),
                        'missing_percentage': float(missing_pct),
                    })
            quality_results['missing_values'] = missing_analysis
            
            # --- Duplicate analysis ---
            duplicate_count = self.df.count() - self.df.dropDuplicates().count()
            quality_results['duplicates'] = {
                'duplicate_rows': int(duplicate_count),
                'duplicate_percentage': float((duplicate_count / total_rows) * 100) if total_rows else 0.0
            }
            
            # --- Temporal coverage ---
            date_stats = self.df.select(
                F.min("date").alias("min_date"),
                F.max("date").alias("max_date"),
                F.countDistinct("date").alias("unique_dates")
            ).collect()[0]
            quality_results['temporal_coverage'] = {
                'start_date': str(date_stats.min_date),
                'end_date': str(date_stats.max_date),
                'unique_dates': int(date_stats.unique_dates)
            }
            
            # --- Outlier detection (z-score approx) ---
            numeric_cols = [c for (c, t) in self.df.dtypes
                            if t in ('double', 'float', 'int', 'bigint', 'long', 'decimal')]
            prefer = ['sale_amount', 'stock_hour6_22_cnt', 'precpt',
                      'avg_temperature', 'avg_humidity', 'avg_wind_level', 'discount']
            ordered_numeric = [c for c in prefer if c in numeric_cols] + [c for c in numeric_cols if c not in prefer]
            
            outlier_analysis: Dict[str, Any] = {}
            threshold = float(self.config.analysis_config['outlier_threshold'])
            for col_name in ordered_numeric:
                stats = self.df.select(
                    F.mean(col_name).alias('mean'),
                    F.stddev(col_name).alias('std')
                ).collect()[0]
                col_mean = stats['mean']
                col_std = stats['std']
                if col_std is not None and col_std > 0:
                    z = F.abs((F.col(col_name) - F.lit(col_mean)) / F.lit(col_std))
                    outlier_count = self.df.filter(z > threshold).count()
                    outlier_analysis[col_name] = {
                        'outlier_count': int(outlier_count),
                        'outlier_percentage': float((outlier_count / total_rows) * 100) if total_rows else 0.0,
                        'mean': float(col_mean) if col_mean is not None else None,
                        'std': float(col_std)
                    }
                else:
                    outlier_analysis[col_name] = {
                        'outlier_count': 0,
                        'outlier_percentage': 0.0,
                        'mean': float(col_mean) if col_mean is not None else None,
                        'std': float(col_std) if col_std is not None else None
                    }
            quality_results['outliers'] = outlier_analysis
            
            logger.info("✓ Data quality checks completed")
            self.results['data_quality'] = quality_results
            return quality_results
            
        except Exception as e:
            logger.error(f"Data quality checks failed: {e}")
            raise
    
    def run_statistical_profiling(self) -> Dict[str, Any]:
        """Comprehensive statistical analysis of the dataset"""
        logger.info("Running statistical profiling...")

        profiling_results: Dict[str, Any] = {}

        try:
            # Sales distribution analysis
            sales_stats = self.df.select(
                F.count("sale_amount").alias("count"),
                F.mean("sale_amount").alias("mean"),
                F.stddev("sale_amount").alias("std"),
                F.min("sale_amount").alias("min"),
                F.max("sale_amount").alias("max"),
                F.expr("percentile_approx(sale_amount, array(0.25, 0.5, 0.75, 0.95))").alias("percentiles")
            ).collect()[0]

            # IMPORTANT: use dict-style access to avoid .count()/.index() collisions
            cnt = sales_stats["count"]
            mean_val = sales_stats["mean"]
            std_val = sales_stats["std"]
            min_val = sales_stats["min"]
            max_val = sales_stats["max"]
            percentiles = sales_stats["percentiles"]

            # Safe numeric conversions
            mean_val = float(mean_val) if mean_val is not None else 0.0
            std_val = float(std_val) if std_val is not None else 0.0
            min_val = float(min_val) if min_val is not None else None
            max_val = float(max_val) if max_val is not None else None
            cv = (std_val / mean_val) if mean_val else 0.0

            profiling_results["sales_distribution"] = {
                "count": int(cnt) if cnt is not None else 0,
                "mean": mean_val,
                "std": std_val,
                "min": min_val,
                "max": max_val,
                "q25": float(percentiles[0]) if percentiles else None,
                "median": float(percentiles[1]) if percentiles else None,
                "q75": float(percentiles[2]) if percentiles else None,
                "p95": float(percentiles[3]) if percentiles else None,
                "cv": float(cv),
            }

            # Stockout analysis
            stockout_stats = self.df.select(
                F.mean("stock_hour6_22_cnt").alias("mean_stockout"),
                F.sum(F.when(F.col("stock_hour6_22_cnt") > 0, 1).otherwise(0)).alias("stockout_days"),
                F.count("*").alias("total_days")
            ).collect()[0]

            profiling_results["stockout_patterns"] = {
                "avg_stockout_hours": float(stockout_stats["mean_stockout"]) if stockout_stats["mean_stockout"] is not None else 0.0,
                "stockout_days": int(stockout_stats["stockout_days"]) if stockout_stats["stockout_days"] is not None else 0,
                "total_days": int(stockout_stats["total_days"]) if stockout_stats["total_days"] is not None else 0,
                "stockout_rate": (
                    float(stockout_stats["stockout_days"]) / float(stockout_stats["total_days"])
                    if stockout_stats["total_days"] else 0.0
                ),
            }

            # Correlation analysis with target variable
            correlation_vars = [
                "stock_hour6_22_cnt", "discount", "precpt",
                "avg_temperature", "avg_humidity", "avg_wind_level",
                "holiday_flag", "activity_flag"
            ]

            correlations: Dict[str, float] = {}
            for var in correlation_vars:
                if var in self.df.columns:
                    corr_row = self.df.select(F.corr("sale_amount", var)).collect()[0]
                    corr_val = list(corr_row)[0]  # the single unnamed field
                    if corr_val is not None:
                        correlations[var] = float(corr_val)

            profiling_results["correlations_with_sales"] = correlations

            logger.info("✓ Statistical profiling completed")
            self.results["statistical_profiling"] = profiling_results
            return profiling_results

        except Exception as e:
            logger.error(f"Statistical profiling failed: {e}")
            raise
   
    def run_temporal_analysis(self) -> Dict[str, Any]:
        """Comprehensive temporal pattern analysis"""
        logger.info("Running temporal analysis...")
        
        temporal_results: Dict[str, Any] = {}
        
        try:
            # Add temporal features
            df_temporal = self.df.withColumn("day_of_week", F.dayofweek("date")) \
                                 .withColumn("month", F.month("date")) \
                                 .withColumn("is_weekend", F.when(F.dayofweek("date").isin([1, 7]), 1).otherwise(0))
            
            # Daily patterns
            daily_patterns = df_temporal.groupBy("day_of_week") \
                .agg(
                    F.mean("sale_amount").alias("avg_sales"),
                    F.stddev("sale_amount").alias("std_sales"),
                    F.count("*").alias("observations")
                ).collect()
            
            temporal_results['daily_patterns'] = [
                {
                    'day_of_week': int(row.day_of_week),
                    'avg_sales': float(row.avg_sales),
                    'std_sales': float(row.std_sales),
                    'observations': int(row.observations)
                } for row in daily_patterns
            ]
            
            # Monthly patterns
            monthly_patterns = df_temporal.groupBy("month") \
                .agg(
                    F.mean("sale_amount").alias("avg_sales"),
                    F.mean("avg_temperature").alias("avg_temp"),
                    F.mean("precpt").alias("avg_precip")
                ).collect()
            
            temporal_results['monthly_patterns'] = [
                {
                    'month': int(row.month),
                    'avg_sales': float(row.avg_sales),
                    'avg_temperature': float(row.avg_temp),
                    'avg_precipitation': float(row.avg_precip)
                } for row in monthly_patterns
            ]
            
            # Weekend vs weekday comparison
            weekend_comparison = df_temporal.groupBy("is_weekend") \
                .agg(
                    F.mean("sale_amount").alias("avg_sales"),
                    F.mean("stock_hour6_22_cnt").alias("avg_stockout")
                ).collect()
            
            temporal_results['weekend_comparison'] = [
                {
                    'is_weekend': bool(row.is_weekend),
                    'avg_sales': float(row.avg_sales),
                    'avg_stockout': float(row.avg_stockout)
                } for row in weekend_comparison
            ]
            
            logger.info("✓ Temporal analysis completed")
            self.results['temporal_analysis'] = temporal_results
            return temporal_results
            
        except Exception as e:
            logger.error(f"Temporal analysis failed: {e}")
            raise
    
    def run_feature_engineering(self) -> None:
        """Create engineered features for downstream analysis"""
        logger.info("Running feature engineering...")
        
        try:
            # Create window specifications
            store_product_window = Window.partitionBy("store_id", "product_id").orderBy("date")
            
            # Engineer comprehensive features
            self.df = self.df.withColumn("day_of_week", F.dayofweek("date")) \
                             .withColumn("month", F.month("date")) \
                             .withColumn("quarter", F.quarter("date")) \
                             .withColumn("is_weekend", F.when(F.dayofweek("date").isin([1, 7]), 1).otherwise(0)) \
                             .withColumn("discount_intensity", 1 - F.col("discount")) \
                             .withColumn("stock_availability", (16 - F.col("stock_hour6_22_cnt")) / 16.0) \
                             .withColumn("sales_lag1", F.lag("sale_amount", 1).over(store_product_window)) \
                             .withColumn("sales_lag7", F.lag("sale_amount", 7).over(store_product_window)) \
                             .withColumn("rolling_avg_7d", F.avg("sale_amount").over(store_product_window.rowsBetween(-6, -1))) \
                             .withColumn("weather_comfort", 
                                         F.when((F.col("avg_temperature") >= 18) & (F.col("avg_temperature") <= 25) & 
                                                (F.col("precpt") < 1.0), 1).otherwise(0)) \
                             .withColumn("high_discount_flag", F.when(F.col("discount") < 0.9, 1).otherwise(0))
            
            # Create interaction features
            self.df = self.df.withColumn("weather_discount_interaction", 
                                         F.col("weather_comfort") * F.col("discount_intensity")) \
                             .withColumn("weekend_discount_interaction",
                                         F.col("is_weekend") * F.col("discount_intensity"))
            
            logger.info("✓ Feature engineering completed")
            
        except Exception as e:
            logger.error(f"Feature engineering failed: {e}")
            raise
