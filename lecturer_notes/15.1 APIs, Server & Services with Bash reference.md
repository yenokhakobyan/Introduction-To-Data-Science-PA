## Understanding APIs

### What is an API?

An API (Application Programming Interface) is like a **waiter in a restaurant**. You (the client) don't go directly to the kitchen (the server) to get your food. Instead, you tell the waiter (API) what you want, they communicate with the kitchen, and bring back your order. APIs define how different software components should communicate with each other.

### Core API Concepts

**Endpoints**: Specific URLs where you can access resources
**HTTP Methods**: Different ways to interact with resources (GET, POST, PUT, DELETE)
**Request/Response**: The conversation between client and server
**Status Codes**: Numbers that tell you if your request succeeded or failed

### Types of APIs

#### 1. REST APIs (Most Common)
REST (Representational State Transfer) APIs use standard HTTP methods and are easy to understand and use.

**Basic REST API Structure**:
```
GET    /api/customers        # Get all customers
GET    /api/customers/123    # Get customer with ID 123
POST   /api/customers        # Create new customer
PUT    /api/customers/123    # Update customer 123
DELETE /api/customers/123    # Delete customer 123
```

**Example REST API Call**:
```bash
# Get customer information
curl -X GET "https://api.example.com/customers/123" \
     -H "Authorization: Bearer your-token-here" \
     -H "Content-Type: application/json"

# Create new customer
curl -X POST "https://api.example.com/customers" \
     -H "Authorization: Bearer your-token-here" \
     -H "Content-Type: application/json" \
     -d '{
       "name": "John Doe",
       "email": "john@example.com",
       "phone": "+1-555-0123"
     }'
```

#### 2. GraphQL APIs
GraphQL lets you request exactly the data you need, nothing more, nothing less.

**GraphQL Query Example**:
```graphql
# Request specific fields
query GetCustomer($id: ID!) {
  customer(id: $id) {
    name
    email
    orders {
      id
      total
      date
    }
  }
}
```

**GraphQL with curl**:
```bash
curl -X POST "https://api.example.com/graphql" \
     -H "Content-Type: application/json" \
     -d '{
       "query": "query { customers { name email } }"
     }'
```

#### 3. WebSocket APIs
For real-time, bidirectional communication (like chat applications or live data feeds).

**WebSocket Connection Example**:
```javascript
// Connect to WebSocket API
const socket = new WebSocket('wss://api.example.com/live-data');

socket.onopen = function(event) {
    console.log('Connected to WebSocket');
    socket.send('{"action": "subscribe", "channel": "orders"}');
};

socket.onmessage = function(event) {
    const data = JSON.parse(event.data);
    console.log('New order:', data);
};
```

### API Authentication Methods

#### 1. API Keys
Simple but less secure - like a password that identifies your application.

```bash
# API key in header
curl -H "X-API-Key: your-api-key-here" \
     "https://api.example.com/data"

# API key in query parameter
curl "https://api.example.com/data?api_key=your-api-key-here"
```

#### 2. Bearer Tokens (JWT)
More secure tokens that can contain user information and expire.

```bash
# Get token first (login)
TOKEN=$(curl -X POST "https://api.example.com/auth/login" \
       -H "Content-Type: application/json" \
       -d '{"username": "user", "password": "pass"}' \
       | jq -r '.access_token')

# Use token for API calls
curl -H "Authorization: Bearer $TOKEN" \
     "https://api.example.com/protected-data"
```

#### 3. OAuth 2.0
Complex but secure - used by Google, Facebook, GitHub, etc.

```bash
# OAuth flow (simplified)
# 1. Get authorization code
https://api.example.com/oauth/authorize?client_id=your-client-id&response_type=code&redirect_uri=your-callback-url

# 2. Exchange code for token
curl -X POST "https://api.example.com/oauth/token" \
     -d "client_id=your-client-id" \
     -d "client_secret=your-client-secret" \
     -d "code=authorization-code-from-step-1" \
     -d "grant_type=authorization_code"
```

### Common HTTP Status Codes

```
200 OK                   # Success

400 Bad Request         # Client error - check your request

404 Not Found          # Resource doesn't exist
429 Too Many Requests   # Rate limit exceeded
500 Internal Server Error # Server-side problem
502 Bad Gateway         # Server received invalid response
```

## Services and Microservices

### What are Services?

A **service** is a self-contained piece of software that performs a specific business function and can communicate with other services. Think of services like **specialized workers in a factory** - each has a specific job, and they work together to create the final product.

### Monolithic vs Microservices Architecture

#### Monolithic Application
One large application that contains all functionality.

```
┌─────────────────────────────────────┐
│           Monolithic App            │
├─────────────────────────────────────┤
│  User Management                    │
│  Order Processing                   │
│  Payment Handling                   │
│  Inventory Management              │
│  Notification System               │
│  Reporting                         │
└─────────────────────────────────────┘
```

**Pros**: Simple to develop, test, and deploy initially
**Cons**: Hard to scale, technology lock-in, single point of failure

#### Microservices Architecture
Multiple small, independent services that communicate via APIs.

```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│   User      │  │   Order     │  │  Payment    │
│  Service    │  │  Service    │  │  Service    │
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       │                │                │
       └────────────────┼────────────────┘
                        │
┌─────────────┐  ┌──────┴──────┐  ┌─────────────┐
│ Inventory   │  │   API       │  │Notification │
│  Service    │  │  Gateway    │  │  Service    │
└─────────────┘  └─────────────┘  └─────────────┘
```

**Pros**: Scalable, flexible technology choices, fault isolation
**Cons**: Complex deployment, network communication overhead, data consistency challenges

### Service Communication Patterns

#### 1. Synchronous Communication (HTTP/REST)
Services communicate in real-time, waiting for responses.

```bash
# User Service calls Order Service
curl -X POST "http://order-service:8080/orders" \
     -H "Content-Type: application/json" \
     -d '{
       "user_id": 123,
       "items": [
         {"product_id": 456, "quantity": 2}
       ]
     }'
```

**Python Service Example**:
```python
# order_service.py
from flask import Flask, request, jsonify
import requests

app = Flask(__name__)

@app.route('/orders', methods=['POST'])
def create_order():
    order_data = request.get_json()
    
    # Call User Service to validate user
    user_response = requests.get(
        f"http://user-service:8080/users/{order_data['user_id']}"
    )
    
    if user_response.status_code != 200:
        return jsonify({"error": "Invalid user"}), 400
    
    # Call Inventory Service to check stock
    inventory_response = requests.post(
        "http://inventory-service:8080/check-stock",
        json={"items": order_data['items']}
    )
    
    if inventory_response.status_code != 200:
        return jsonify({"error": "Insufficient stock"}), 400
    
    # Create order logic here
    order_id = create_order_in_database(order_data)
    
    return jsonify({
        "order_id": order_id,
        "status": "created"
    }), 201

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=8080)
```

Services communicate via messages, don't wait for immediate responses.

**Using Redis as Message Broker**:

#### 3. Event-Driven Architecture
Services communicate by publishing and consuming events.

**Event Bus Example**:
```python
# event_bus.py
class EventBus:
    def __init__(self):
        self.subscribers = {}
    
    def subscribe(self, event_type, handler):
        if event_type not in self.subscribers:
            self.subscribers[event_type] = []
        self.subscribers[event_type].append(handler)
    
    def publish(self, event_type, event_data):
        if event_type in self.subscribers:
            for handler in self.subscribers[event_type]:
                handler(event_data)

# Usage
event_bus = EventBus()

# Notification Service subscribes to events
def handle_order_created(event_data):
    send_email(event_data['user_email'], "Order confirmed!")

event_bus.subscribe('order_created', handle_order_created)

# Order Service publishes events
def create_order(order_data):
    # Create order logic
    order_id = save_order(order_data)
    
    # Publish event
    event_bus.publish('order_created', {
        'order_id': order_id,
        'user_email': order_data['user_email']
    })
```

### Service Discovery and Load Balancing

#### Service Discovery
How services find and communicate with each other.

**Using Consul for Service Discovery**:
```bash
# Register service with Consul
curl -X PUT "http://consul:8500/v1/agent/service/register" \
     -d '{
       "ID": "order-service-1",
       "Name": "order-service",
       "Port": 8080,
       "Address": "10.0.0.5",
       "Check": {
         "HTTP": "http://10.0.0.5:8080/health",
         "Interval": "10s"
       }
     }'

# Discover services
curl "http://consul:8500/v1/health/service/order-service?passing"
```

**Python Service Discovery Client**:
```python
import consul
import requests
import random

class ServiceClient:
    def __init__(self):
        self.consul = consul.Consul(host='consul-server')
    
    def get_service_url(self, service_name):
        # Get healthy instances of the service
        _, services = self.consul.health.service(service_name, passing=True)
        
        if not services:
            raise Exception(f"No healthy instances of {service_name}")
        
        # Simple load balancing - pick random instance
        service = random.choice(services)
        return f"http://{service['Service']['Address']}:{service['Service']['Port']}"
    
    def call_service(self, service_name, endpoint, method='GET', **kwargs):
        service_url = self.get_service_url(service_name)
        url = f"{service_url}{endpoint}"
        
        return requests.request(method, url, **kwargs)

# Usage
client = ServiceClient()
response = client.call_service('user-service', '/users/123')
```

#### Load Balancing Strategies

**Round Robin Load Balancer**:
```python
class RoundRobinBalancer:
    def __init__(self, services):
        self.services = services
        self.current = 0
    
    def get_next_service(self):
        service = self.services[self.current]
        self.current = (self.current + 1) % len(self.services)
        return service

# Usage
services = ['http://service1:8080', 'http://service2:8080', 'http://service3:8080']
balancer = RoundRobinBalancer(services)

for _ in range(10):
    service_url = balancer.get_next_service()
    # Make request to service_url
```

## Servers and Infrastructure

### Types of Servers

#### 1. Physical Servers
Dedicated hardware machines in data centers.

**Pros**: Maximum performance, full control
**Cons**: High cost, maintenance overhead, scaling challenges

#### 2. Virtual Servers (VPS)
Multiple virtual machines running on physical hardware.

**Pros**: Cost-effective, flexible, good isolation
**Cons**: Resource sharing, limited by host hardware

#### 3. Cloud Servers
On-demand virtual servers from cloud providers.

**Major Cloud Providers**:
- **AWS**: EC2, Lambda, ECS, EKS
- **Google Cloud**: Compute Engine, Cloud Run, GKE
- **Microsoft Azure**: Virtual Machines, Container Instances, AKS
- **DigitalOcean**: Droplets, App Platform
- **Linode**: Linodes, Kubernetes

### Web Server Configuration

#### Nginx Configuration

**Basic Nginx Config (/etc/nginx/sites-available/myapp)**:
```nginx
server {
    listen 80;
    server_name example.com www.example.com;
    
    # Redirect HTTP to HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name example.com www.example.com;
    
    # SSL Configuration
    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    
    # Security headers
    add_header X-Frame-Options DENY;
    add_header X-Content-Type-Options nosniff;
    add_header X-XSS-Protection "1; mode=block";
    
    # Static files
    location /static/ {
        alias /var/www/myapp/static/;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
    
    # API proxy
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # Timeouts
        proxy_connect_timeout 5s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }
    
    # Load balancing
    location /balanced/ {
        proxy_pass http://backend_servers;
    }
    
    # Rate limiting
    location /limited/ {
        limit_req zone=api burst=10 nodelay;
        proxy_pass http://127.0.0.1:8000;
    }
}

# Upstream servers for load balancing
upstream backend_servers {
    least_conn;  # Load balancing method
    server 127.0.0.1:8001 weight=3;
    server 127.0.0.1:8002 weight=2;
    server 127.0.0.1:8003 backup;  # Only use if others fail
}

# Rate limiting zone
http {
    limit_req_zone $binary_remote_addr zone=api:10m rate=1r/s;
}
```

```bash
#!/bin/bash
# comprehensive_monitor.sh

ALERT_EMAIL="admin@example.com"
LOG_FILE="/var/log/system_monitor.log"

log_message() {
    echo "$(date '+%Y-%m-%d %H:%M:%S'): $1" >> "$LOG_FILE"
}

check_disk_space() {
    local usage=$(df / | grep / | awk '{print $5}' | sed 's/%//')
    if [ "$usage" -gt 85 ]; then
        log_message "WARNING: Disk usage is ${usage}%"
        echo "Disk usage critical: ${usage}%" | mail -s "Disk Space Alert" "$ALERT_EMAIL"
    fi
}

check_memory_usage() {
    local mem_usage=$(free | grep Mem | awk '{printf "%.0f", $3/$2 * 100}')
    if [ "$mem_usage" -gt 90 ]; then
        log_message "WARNING: Memory usage is ${mem_usage}%"
        echo "Memory usage critical: ${mem_usage}%" | mail -s "Memory Alert" "$ALERT_EMAIL"
    fi
}

check_cpu_load() {
    local load=$(uptime | awk -F'load average:' '{print $2}' | cut -d, -f1 | xargs)
    local cores=$(nproc)
    local threshold=$(echo "$cores * 2" | bc)
    
    if (( $(echo "$load > $threshold" | bc -l) )); then
        log_message "WARNING: High CPU load: $load"
        echo "High CPU load: $load (threshold: $threshold)" | mail -s "CPU Load Alert" "$ALERT_EMAIL"
    fi
}

check_services() {
    local services=("nginx" "postgresql" "redis-server" "ssh")
    
    for service in "${services[@]}"; do
        if ! systemctl is-active --quiet "$service"; then
            log_message "ERROR: $service is not running"
            echo "$service is down" | mail -s "Service Down: $service" "$ALERT_EMAIL"
            
            # Attempt restart
            log_message "Attempting to restart $service"
            systemctl restart "$service"
            sleep 5
            
            if systemctl is-active --quiet "$service"; then
                log_message "Successfully restarted $service"
            else
                log_message "Failed to restart $service"
            fi
        fi
    done
}

check_website_availability() {
    local urls=("http://localhost" "http://localhost:8080/health")
    
    for url in "${urls[@]}"; do
        if ! curl -f -s "$url" > /dev/null; then
            log_message "ERROR: $url is not responding"
            echo "$url is not responding" | mail -s "Website Down" "$ALERT_EMAIL"
        fi
    done
}

check_ssl_certificates() {
    local domains=("example.com" "api.example.com")
    
    for domain in "${domains[@]}"; do
        local expiry_date=$(echo | openssl s_client -servername "$domain" -connect "$domain:443" 2>/dev/null | openssl x509 -noout -dates | grep notAfter | cut -d= -f2)
        local expiry_epoch=$(date -d "$expiry_date" +%s)
        local current_epoch=$(date +%s)
        local days_until_expiry=$(( (expiry_epoch - current_epoch) / 86400 ))
        
        if [ "$days_until_expiry" -lt 30 ]; then
            log_message "WARNING: SSL certificate for $domain expires in $days_until_expiry days"
            echo "SSL certificate for $domain expires in $days_until_expiry days" | mail -s "SSL Certificate Expiring" "$ALERT_EMAIL"
        fi
    done
}

# Run all checks
log_message "Starting system monitoring checks"
check_disk_space
check_memory_usage
check_cpu_load
check_services
check_website_availability
check_ssl_certificates
log_message "System monitoring checks completed"

# Log system statistics
{
    echo "=== System Statistics ==="
    echo "Date: $(date)"
    echo "Uptime: $(uptime)"
    echo "Memory: $(free -h | grep Mem)"
    echo "Disk: $(df -h | grep -E '^/dev')"
```

```bash
#!/bin/bash
# backup_system.sh

# Configuration
BACKUP_ROOT="/backup"
DATE=$(date +%Y%m%d_%H%M%S)
RETENTION_DAYS=30
S3_BUCKET="my-backups"  # Optional: upload to S3

# Create backup directories
mkdir -p "$BACKUP_ROOT/databases"
mkdir -p "$BACKUP_ROOT/files"
mkdir -p "$BACKUP_ROOT/configs"

log_backup() {
    echo "$(date): $1" >> "$BACKUP_ROOT/backup.log"
}

# Database backups
backup_databases() {
    log_backup "Starting database backups"
    
    # PostgreSQL backup
    pg_dump -h localhost -U user myapp > "$BACKUP_ROOT/databases/myapp_$DATE.sql"
    gzip "$BACKUP_ROOT/databases/myapp_$DATE.sql"
    
    # Redis backup
    cp /var/lib/redis/dump.rdb "$BACKUP_ROOT/databases/redis_$DATE.rdb"
    gzip "$BACKUP_ROOT/databases/redis_$DATE.rdb"
    
    log_backup "Database backups completed"
}

# File system backups
backup_files() {
    log_backup "Starting file backups"
    
    # Application files
    tar -czf "$BACKUP_ROOT/files/app_$DATE.tar.gz" /var/www/myapp
    
    # User uploads
    tar -czf "$BACKUP_ROOT/files/uploads_$DATE.tar.gz" /var/uploads
    
    log_backup "File backups completed"
}

# Configuration backups
backup_configs() {
    log_backup "Starting configuration backups"
    
    # System configurations
    tar -czf "$BACKUP_ROOT/configs/system_$DATE.tar.gz" \
        /etc/nginx \
        /etc/postgresql \
        /etc/redis \
        /etc/ssl \
        /etc/cron.d
    
    log_backup "Configuration backups completed"
}

# Upload to cloud storage (optional)
upload_to_cloud() {
    if command -v aws &> /dev/null; then
        log_backup "Uploading backups to S3"
        aws s3 sync "$BACKUP_ROOT" "s3://$S3_BUCKET/$(hostname)/"
        log_backup "Cloud upload completed"
    fi
}

# Clean old backups
cleanup_old_backups() {
    log_backup "Cleaning old backups"
    
    find "$BACKUP_ROOT" -name "*.sql.gz" -mtime +$RETENTION_DAYS -delete
    find "$BACKUP_ROOT" -name "*.tar.gz" -mtime +$RETENTION_DAYS -delete
    find "$BACKUP_ROOT" -name "*.rdb.gz" -mtime +$RETENTION_DAYS -delete
    
    log_backup "Cleanup completed"
}

# Verify backup integrity
verify_backups() {
    log_backup "Verifying backup integrity"
    
    # Check if backup files exist and are not empty
    for file in "$BACKUP_ROOT"/*/*_$DATE.*; do
        if [[ -f "$file" && -s "$file" ]]; then
            log_backup "✓ $file - OK"
        else
            log_backup "✗ $file - FAILED"
            echo "Backup verification failed for $file" | mail -s "Backup Alert" admin@example.com
        fi
    done
    
    log_backup "Verification completed"
}

# Main backup process
main() {
    log_backup "=== Starting backup process ==="
    
    backup_databases
    backup_files
    backup_configs
    verify_backups
    upload_to_cloud
    cleanup_old_backups
    
    log_backup "=== Backup process completed ==="
    
    # Send success notification
    echo "Backup completed successfully on $(date)" | mail -s "Backup Success" admin@example.com
}

# Run with error handling
if main; then
    exit 0
else
    log_backup "Backup process failed"
    echo "Backup process failed on $(date)" | mail -s "Backup Failed" admin@example.com
    exit 1
fi
```

#### Disaster Recovery Plan

```bash
#!/bin/bash
# disaster_recovery.sh

# This script helps restore from backups in case of disaster

BACKUP_ROOT="/backup"
RESTORE_DATE=""

show_help() {
    echo "Usage: $0 [OPTIONS]"
    echo ""
    echo "Options:"
    echo "  -d DATE     Restore from specific date (YYYYMMDD_HHMMSS)"
    echo "  -l          List available backups"
    echo "  -h          Show this help"
    echo ""
    echo "Examples:"
    echo "  $0 -l                           # List backups"
    echo "  $0 -d 20241201_120000          # Restore from specific backup"
}

list_backups() {
    echo "Available backups:"
    echo "=================="
    
    echo "Databases:"
    ls -lh "$BACKUP_ROOT/databases/" | grep -E "\.(sql|rdb)\.gz$"
    
    echo -e "\nFiles:"
    ls -lh "$BACKUP_ROOT/files/" | grep "\.tar\.gz$"
    
    echo -e "\nConfigurations:"
    ls -lh "$BACKUP_ROOT/configs/" | grep "\.tar\.gz$"
}

restore_database() {
    echo "Restoring database from backup..."
    
    if [ ! -f "$BACKUP_ROOT/databases/myapp_$RESTORE_DATE.sql.gz" ]; then
        echo "Database backup not found for date: $RESTORE_DATE"
        exit 1
    fi
    
    # Stop application
    systemctl stop myapp
    
    # Create backup of current state
    pg_dump -h localhost -U user myapp > "/tmp/myapp_before_restore_$(date +%Y%m%d_%H%M%S).sql"
    
    # Restore database
    gunzip -c "$BACKUP_ROOT/databases/myapp_$RESTORE_DATE.sql.gz" | psql -h localhost -U user myapp
    
    echo "Database restored successfully"
}

restore_files() {
    echo "Restoring files from backup..."
    
    if [ ! -f "$BACKUP_ROOT/files/app_$RESTORE_DATE.tar.gz" ]; then
        echo "File backup not found for date: $RESTORE_DATE"
        exit 1
    fi
    
    # Create backup of current files
    tar -czf "/tmp/app_before_restore_$(date +%Y%m%d_%H%M%S).tar.gz" /var/www/myapp
    
    # Restore files
    tar -xzf "$BACKUP_ROOT/files/app_$RESTORE_DATE.tar.gz" -C /
    
    # Set correct permissions
    chown -R www-data:www-data /var/www/myapp
    
    echo "Files restored successfully"
}

restore_configs() {
    echo "Restoring configurations from backup..."
    
    if [ ! -f "$BACKUP_ROOT/configs/system_$RESTORE_DATE.tar.gz" ]; then
        echo "Config backup not found for date: $RESTORE_DATE"
        exit 1
    fi
    
    # Restore configurations
    tar -xzf "$BACKUP_ROOT/configs/system_$RESTORE_DATE.tar.gz" -C /
    
    # Restart services
    systemctl restart nginx
    systemctl restart postgresql
    
    echo "Configurations restored successfully"
}

# Parse command line arguments
while getopts "d:lh" opt; do
    case $opt in
        d)
            RESTORE_DATE="$OPTARG"
            ;;
        l)
            list_backups
            exit 0
            ;;
        h)
            show_help
            exit 0
            ;;
        *)
            show_help
            exit 1
            ;;
    esac
done

if [ -z "$RESTORE_DATE" ]; then
    echo "Error: Please specify a restore date with -d option"
    show_help
    exit 1
fi

# Confirm restore operation
echo "WARNING: This will restore your system to backup from $RESTORE_DATE"
echo "Current data will be backed up to /tmp before restoration"
read -p "Are you sure you want to continue? (yes/no): " confirm

if [ "$confirm" != "yes" ]; then
    echo "Restore cancelled"
    exit 0
fi

# Perform restoration
echo "Starting disaster recovery for date: $RESTORE_DATE"
restore_database
restore_files
restore_configs

# Start application
systemctl start myapp

# Verify restoration
sleep 5
if curl -f http://localhost/health > /dev/null 2>&1; then
    echo "✓ Disaster recovery completed successfully"
    echo "Application is responding normally"
else
    echo "✗ Warning: Application may not be responding correctly"
    echo "Please check logs and verify manually"
fi
```

```python
@app.route('/api/users', methods=['GET'])
def get_users():
    """Get all users with caching"""
    try:
        # Try cache first
        cached_users = redis_client.get('users:all')
        if cached_users:
            return jsonify({
                'data': eval(cached_users.decode('utf-8')),
                'source': 'cache'
            })
        
        # Query database
        conn = get_db_connection()
        cursor = conn.cursor()
        cursor.execute('SELECT id, name, email, created_at FROM users ORDER BY created_at DESC')
        
        users = []
        for row in cursor.fetchall():
            users.append({
                'id': row[0],
                'name': row[1],
                'email': row[2],
                'created_at': row[3].isoformat()
            })
        
        cursor.close()
        conn.close()
        
        # Cache results for 5 minutes
        redis_client.setex('users:all', 300, str(users))
        
        return jsonify({
            'data': users,
            'count': len(users),
            'source': 'database'
        }), 200
        
    except Exception as e:
        logger.error(f"Error getting users: {str(e)}")
        return jsonify({'error': 'Internal server error'}), 500
```

```python
# JWT Authentication example
import jwt
from functools import wraps
from flask import request, jsonify

SECRET_KEY = os.getenv('JWT_SECRET', 'your-secret-key')

def token_required(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        token = request.headers.get('Authorization')
        
        if not token:
            return jsonify({'message': 'Token is missing'}), 401
        
        try:
            # Remove 'Bearer ' prefix
            token = token.split(' ')[1]
            data = jwt.decode(token, SECRET_KEY, algorithms=['HS256'])
            current_user = data['user_id']
        except:
            return jsonify({'message': 'Token is invalid'}), 401
        
        return f(current_user, *args, **kwargs)
    return decorated

@app.route('/api/protected', methods=['GET'])
@token_required
def protected_route(current_user):
    return jsonify({
        'message': 'This is a protected route',
        'user_id': current_user
    })
```
