## 1. Foundations: Images as Mathematical Objects

### 1.1 Digital Images as Tensors

When you load an image in Python, you're working with a 3D tensor of shape `(H, W, C)` where H is height, W is width, and C is the number of channels. This representation is fundamental to everything that follows.

A grayscale image is a 2D array where each element represents pixel intensity. Consider a tiny 3×3 grayscale image:

```
I = [[120, 150, 130],
     [110, 140, 125],
     [115, 135, 120]]
```

Each value typically ranges from 0 (black) to 255 (white) for 8-bit images. This is quantization—we discretize continuous light intensity into 256 levels because it's sufficient for human perception and computationally efficient.

For color images, we stack three such matrices. An RGB image has shape `(H, W, 3)` where the three channels represent red, green, and blue intensities. The value at position `I[y, x, :]` gives you the RGB triplet for that pixel. Note the coordinate system: `y` indexes rows (height, vertical position), and `x` indexes columns (width, horizontal position). This can be confusing because we often think of images as `(x, y)` in Cartesian coordinates, but arrays are row-major.

The mathematical representation of an image is thus a function `I: Ω → R^C` where `Ω ⊂ Z^2` is the discrete spatial domain and `C` is the number of channels. For grayscale, `C=1`. For RGB, `C=3`.

### 1.2 Color Spaces and Their Purpose

**RGB (Red-Green-Blue)** is additive—you mix light. Cameras and displays use RGB because that's how photoreceptors and screens work. However, RGB isn't perceptually uniform. The Euclidean distance between two RGB values doesn't correspond well to perceived color difference.

**HSV (Hue-Saturation-Value)** separates color information (hue) from intensity (value). This is incredibly useful for tasks like color-based segmentation. If you want to detect all red objects regardless of lighting, you can threshold the hue channel. The conversion from RGB to HSV involves finding the maximum and minimum RGB components and computing cylindrical coordinates.

**YCbCr** separates luminance (Y) from chrominance (Cb, Cr). JPEG compression exploits this—humans are more sensitive to brightness changes than color changes, so you can downsample the chrominance channels without noticeable quality loss. The Y channel is approximately `Y = 0.299R + 0.587G + 0.114B`, reflecting human sensitivity to green.

Understanding color spaces is crucial for preprocessing. Many models expect RGB input, but your problem might be easier in HSV space. Face detection often works better with skin tone detection in YCbCr space.

### 1.3 Normalization and Preprocessing

Neural networks train better when inputs are normalized. The standard ImageNet normalization subtracts the mean and divides by the standard deviation per channel:

```
I_normalized[c] = (I[c] - μ_c) / σ_c
```

For ImageNet: `μ = [0.485, 0.456, 0.406]` and `σ = [0.229, 0.224, 0.225]`. These values are computed over millions of images and center your data around zero with unit variance, making gradient descent more stable.

You might also rescale pixel values from `[0, 255]` to `[0, 1]` by dividing by 255. Some architectures expect `[-1, 1]` instead, which you achieve via `(I/127.5) - 1`. The key principle is consistency—normalize your training and test data identically, and match the normalization scheme of pretrained models you use.

### 1.4 The Convolution Operation: Building Intuition

Convolution is the fundamental operation in computer vision. It's a local operation that combines a kernel (small matrix) with each neighborhood of the image to produce a new value. Mathematically, 2D discrete convolution is:

```
(I * K)[y, x] = ΣΣ I[y+i, x+j] × K[i, j]
```

where the summation is over all positions `(i, j)` in the kernel.

Let's work through a concrete example. Consider a 5×5 grayscale image and a 3×3 edge detection kernel:

```
Image I:
[10  20  30  20  10]
[20  30  40  30  20]
[30  40  50  40  30]
[20  30  40  30  20]
[10  20  30  20  10]

Kernel K (vertical edge detector):
[-1  0  1]
[-2  0  2]
[-1  0  1]
```

To compute the output at position `(1, 1)` (remembering valid convolution without padding), we overlay the kernel on the 3×3 neighborhood centered at `(1, 1)`:

```
Neighborhood:
[10  20  30]
[20  30  40]
[30  40  50]

Calculation:
(-1×10) + (0×20) + (1×30) +
(-2×20) + (0×30) + (2×40) +
(-1×30) + (0×40) + (1×50)
= -10 + 0 + 30 - 40 + 0 + 80 - 30 + 0 + 50
= 80
```

This large positive value indicates a vertical edge—a transition from dark (left) to bright (right). The kernel acts as a template that responds strongly when it matches local structure.

### 1.5 Padding, Stride, and Dilation

**Padding** adds borders to your image. Without padding, a 5×5 image convolved with a 3×3 kernel produces a 3×3 output—you lose spatial resolution. With padding=1 (adding one layer of zeros around the image), you maintain the same size.

The output size formula for 2D convolution is:

```
H_out = floor[(H_in + 2×padding - kernel_size) / stride] + 1
W_out = floor[(W_in + 2×padding - kernel_size) / stride] + 1
```

**Stride** determines how much you shift the kernel between applications. Stride=1 means you slide by one pixel at a time. Stride=2 downsamples by a factor of 2, which is computationally cheaper than convolution followed by pooling.

For our 5×5 image with a 3×3 kernel, stride=1, and padding=0, we get:
```
H_out = floor[(5 + 0 - 3) / 1] + 1 = 3
W_out = floor[(5 + 0 - 3) / 1] + 1 = 3
```

**Dilation** (or atrous convolution) spaces out the kernel elements. A 3×3 kernel with dilation=2 covers a 5×5 area but only uses 9 parameters. The effective receptive field increases without adding parameters. This is valuable for capturing multi-scale context, which is why DeepLab uses dilated convolutions for semantic segmentation.

The dilated convolution formula modifies the standard one:

```
(I *_d K)[y, x] = ΣΣ I[y + d×i, x + d×j] × K[i, j]
```

where `d` is the dilation rate.

## 2. Classical Computer Vision: Handcrafted Features

Before deep learning, computer vision relied on carefully designed algorithms. These methods are still relevant—they're interpretable, require no training data, and can be more efficient for specific tasks. Understanding them builds intuition for why learned features work.

### 2.1 Edge Detection: Finding Discontinuities

Edges are places where intensity changes rapidly. They correspond to object boundaries, shadows, or texture changes. The simplest edge detector is the gradient.

For a continuous function, the gradient is `∇I = [∂I/∂x, ∂I/∂y]`. The gradient magnitude `||∇I||` gives edge strength, and the gradient direction `arctan(∂I/∂y, ∂I/∂x)` gives edge orientation.

In discrete images, we approximate derivatives with finite differences. The **Sobel operator** computes gradients using these kernels:

```
G_x = [-1  0  1]      G_y = [-1 -2 -1]
      [-2  0  2]            [ 0  0  0]
      [-1  0  1]            [ 1  2  1]
```

The Sobel kernel is separable: `G_x = [1, 2, 1]^T × [-1, 0, 1]`. This means you can implement it as two 1D convolutions, which is computationally cheaper. The center row weights `[1, 2, 1]` provide smoothing perpendicular to the gradient direction, reducing noise sensitivity.

Given an image, you compute:
```
I_x = I * G_x
I_y = I * G_y
Edge_magnitude = sqrt(I_x² + I_y²)
Edge_direction = arctan2(I_y, I_x)
```

The **Prewitt operator** is similar but uses uniform weights `[1, 1, 1]` instead of `[1, 2, 1]`, making it less smooth but simpler.

The **Canny edge detector** is more sophisticated and follows a multi-stage approach. First, it smooths the image with a Gaussian filter to reduce noise. Then it computes gradients using Sobel operators. The innovation is **non-maximum suppression**: along the gradient direction, it keeps only local maxima of edge strength. This thins edges to single-pixel width. Finally, it uses **hysteresis thresholding** with two thresholds—strong edges above the high threshold are kept, weak edges below the low threshold are discarded, and medium edges are kept only if connected to strong edges. This produces clean, connected edges.

Canny edges are still used in practice. For instance, in document scanning apps, Canny edges can detect page boundaries more reliably than a neural network when lighting varies significantly.

### 2.2 Corner Detection: Interest Points

Corners are distinctive points where two edges meet. They're useful for tracking, matching, and object recognition because they're repeatable across images.

The **Harris corner detector** looks for points where the image gradient changes significantly in all directions. The intuition is that flat regions have no gradient change, edges have change in one direction, and corners have change in two directions.

Mathematically, consider a window around pixel `(x, y)` and shift it by `(u, v)`. The intensity change is:

```
E(u, v) = ΣΣ w(x, y) [I(x+u, y+v) - I(x, y)]²
```

Using Taylor expansion: `I(x+u, y+v) ≈ I(x, y) + I_x × u + I_y × v`. This gives:

```
E(u, v) ≈ [u, v] M [u, v]^T
```

where the structure tensor M is:

```
M = Σ w(x,y) [I_x²    I_x×I_y  ]
              [I_x×I_y  I_y²    ]
```

The eigenvalues of M tell you about the local structure. If both eigenvalues are large, you have a corner. If one is large, you have an edge. If both are small, you have a flat region.

The Harris corner response is `R = det(M) - k×trace(M)²`, where `k` is typically 0.04-0.06. This avoids computing eigenvalues explicitly. You threshold R to find corners.

### 2.3 Feature Descriptors: SIFT and Beyond

Detecting keypoints is only half the battle—you need to describe them in a way that's invariant to transformations. **SIFT (Scale-Invariant Feature Transform)** was revolutionary because it handles scale, rotation, and partial illumination changes.

SIFT first detects keypoints at multiple scales using a Difference-of-Gaussians pyramid. For each keypoint, it assigns a canonical orientation based on the dominant gradient direction in the local neighborhood. Then it computes a descriptor: a 128-dimensional vector encoding gradient distributions in a 4×4 grid of 4×4 pixel sub-regions, with 8 orientation bins per sub-region.

The descriptor is normalized to unit length, making it illumination invariant. Clamping large values and renormalizing reduces the influence of strong gradients, improving robustness.

**SURF (Speeded-Up Robust Features)** approximates SIFT using box filters and integral images, making it faster. **ORB (Oriented FAST and Rotated BRIEF)** is even faster, using binary descriptors—each bit encodes whether one pixel is brighter than another. ORB is rotation-invariant and works well for real-time applications.

These classical descriptors are still used in SLAM (Simultaneous Localization and Mapping) systems where you need to match features across video frames in real time. While deep learning features from CNNs are more discriminative, they're also much slower to compute.

### 2.4 Image Transformations and Homography

Understanding geometric transformations is crucial for tasks like image stitching, augmented reality, and camera calibration.

**Affine transformations** preserve parallel lines and include translation, rotation, scaling, and shearing. They're represented by a 2×3 matrix or equivalently as a 3×3 matrix in homogeneous coordinates:

```
[x']   [a  b  t_x] [x]
[y'] = [c  d  t_y] [y]
[1 ]   [0  0  1  ] [1]
```

where `[a, b, c, d]` encode rotation, scaling, and shearing, and `[t_x, t_y]` encode translation.

**Projective transformations (homographies)** allow for perspective distortion. They're represented by a full 3×3 matrix with 8 degrees of freedom (9 parameters minus scale):

```
[x']   [h11 h12 h13] [x]
[y'] = [h21 h22 h23] [y]
[w ]   [h31 h32 h33] [1]
```

After transformation, you divide by w to get the actual coordinates: `x' = x'/w`, `y' = y'/w`.

Homographies are essential for image stitching. If you photograph a planar scene (like a document) from two angles, the relationship between the images is a homography. You can estimate it from four point correspondences using the Direct Linear Transform or from many points using RANSAC to reject outliers.

Here's a concrete example. Suppose you have four points in one image and their corresponding positions in another:

```
Image 1: (0,0), (100,0), (100,100), (0,100)
Image 2: (10,5), (120,10), (110,110), (5,105)
```

You set up a system of linear equations (two per point pair) and solve for the 8 unknown homography parameters. Once you have the homography matrix, you can warp one image to align with the other.

### 2.5 Why Classical Methods Matter

Handcrafted features have limitations—they don't generalize well across different visual domains, and choosing the right feature for a task requires expertise. Deep learning overcomes this by learning features from data. However, classical methods still offer value:

They provide interpretability. When a Canny edge detector fails, you can visualize intermediate steps and understand why. When a CNN fails, you see only high-dimensional activations.

They require no training data. If you need to detect edges in medical images but have no labeled data, Canny works immediately.

They're computationally efficient. Edge detection runs in real time on embedded devices where running a neural network isn't feasible.

They inform architecture design. The success of small receptive fields in CNNs echoes the success of local operators like Sobel. The Laplacian pyramid in classical vision inspired feature pyramid networks in modern object detection.

Understanding classical methods makes you a better deep learning practitioner because you appreciate what problems neural networks solve and what inductive biases they encode.

## 3. Deep Learning Fundamentals for Computer Vision

### 3.1 Convolutional Neural Networks: First Principles

A convolutional layer applies learnable filters to an input. Unlike fully connected layers, convolutions exploit three key ideas:

**Local connectivity**: Each output unit connects only to a local patch of the input. This reflects the intuition that nearby pixels are more related than distant ones.

**Parameter sharing**: The same filter is applied across all spatial positions. This drastically reduces parameters and encodes translation equivariance—if you shift the input, the output shifts correspondingly.

**Hierarchical representations**: Early layers detect edges and textures, middle layers detect parts, and deep layers detect objects. This happens naturally through composing local operations.

Mathematically, a convolutional layer with input `X ∈ R^(H_in × W_in × C_in)` and `C_out` filters of size `(k × k × C_in)` produces output `Y ∈ R^(H_out × W_out × C_out)`:

```
Y[i, j, c] = Σ_Σ_Σ X[i×s+m, j×s+n, d] × W[m, n, d, c] + b[c]
```

where the summations are over kernel positions `(m, n)` and input channels `d`, `s` is stride, `W` is the weight tensor, and `b` is the bias vector.

The number of parameters is `(k² × C_in × C_out) + C_out`. For a 3×3 convolution from 64 to 128 channels, that's `(9 × 64 × 128) + 128 = 73,856` parameters. Compare this to a fully connected layer between 224×224×64 and 128 outputs: `(224 × 224 × 64 × 128) + 128 ≈ 411 million` parameters. Convolution is dramatically more parameter-efficient.

### 3.2 Activation Functions: Introducing Nonlinearity

Without nonlinearity, stacking layers is pointless—the composition of linear functions is linear. Activation functions make deep networks powerful.

**ReLU (Rectified Linear Unit)**: `f(x) = max(0, x)`. It's simple, fast to compute, and avoids vanishing gradients for positive inputs. The gradient is 1 when `x > 0` and 0 when `x < 0`. ReLU can cause "dead neurons" if many inputs become negative, since gradients are zero and weights never update.

**Leaky ReLU**: `f(x) = x if x > 0 else α×x` where `α ≈ 0.01`. This prevents dead neurons by allowing small gradients for negative inputs.

**GELU (Gaussian Error Linear Unit)**: `f(x) = x × Φ(x)` where `Φ` is the standard Gaussian CDF. It's smooth and stochastic (in a probabilistic interpretation), and is used in transformers like BERT and GPT. The approximation `0.5 × x × (1 + tanh[√(2/π) × (x + 0.044715 × x³)])` is commonly used.

**Swish**: `f(x) = x × σ(βx)` where `σ` is the sigmoid function. It's smooth everywhere and performs well in deep networks. When `β=1`, it's called SiLU (Sigmoid Linear Unit).

In practice, ReLU remains the default for convolutional networks, while GELU and Swish are common in transformers and newer architectures. The choice matters less than you might think—architecture design and training procedures have a larger impact.

### 3.3 Pooling: Spatial Downsampling

Pooling reduces spatial dimensions, making representations more compact and providing translation invariance. There are two main types:

**Max pooling**: `Y[i, j, c] = max{X[i×s+m, j×s+n, c]}` over the pooling window. It keeps the strongest activation in each region, which is effective for detecting the presence of a feature regardless of its exact position.

**Average pooling**: `Y[i, j, c] = mean{X[i×s+m, j×s+n, c]}`. It smooths representations and is sometimes used in the final layers before classification.

A 2×2 max pooling with stride 2 halves both spatial dimensions. For an input of shape `(28, 28, 64)`, the output is `(14, 14, 64)`.

Modern architectures often replace pooling with strided convolutions, which are learnable. However, pooling remains useful—global average pooling is common before the classification head, reducing each feature map to a single value and eliminating fully connected layers.

### 3.4 Normalization: Stabilizing Training

**Batch Normalization** standardizes activations across the batch dimension. For a layer with activation `x`, it computes:

```
μ_batch = (1/N) Σ x_i
σ²_batch = (1/N) Σ (x_i - μ_batch)²
x̂_i = (x_i - μ_batch) / sqrt(σ²_batch + ε)
y_i = γ × x̂_i + β
```

where `γ` and `β` are learnable scale and shift parameters, and `ε` is a small constant for numerical stability.

BatchNorm addresses internal covariate shift—the distribution of layer inputs changes during training as earlier layers update. By normalizing, it stabilizes training, allows higher learning rates, and acts as regularization.

The catch is that BatchNorm behaves differently during training (using batch statistics) and inference (using running statistics accumulated during training). This can cause issues with small batch sizes or when batch statistics aren't representative.

**Layer Normalization** normalizes across the channel dimension instead of the batch dimension. For an activation of shape `(N, H, W, C)`, LayerNorm computes statistics over `(H, W, C)` independently for each sample. This makes it batch-size independent, which is why transformers use LayerNorm instead of BatchNorm.

**Group Normalization** is a middle ground—it divides channels into groups and normalizes within each group. It's effective for computer vision tasks and doesn't depend on batch size.

### 3.5 Receptive Field: How Much Does Each Neuron See?

The receptive field of a neuron is the region of the input image that influences it. Understanding receptive fields helps you design architectures appropriately.

For a single convolutional layer with kernel size `k`, each output neuron sees a `k × k` region of the input. When you stack layers, receptive fields grow. The formula for effective receptive field after `L` layers with kernel size `k` and stride `s=1` is:

```
RF = 1 + L × (k - 1)
```

Let's compute this step by step for three 3×3 convolutional layers:

Layer 1: `RF = 3` (the neuron sees a 3×3 region)  
Layer 2: Each neuron connects to a 3×3 region of Layer 1 outputs, each of which has RF=3. The total is `RF = 3 + 2×1 = 5`.  
Layer 3: `RF = 5 + 2×1 = 7`.

More generally:

```
RF_l = RF_{l-1} + (k - 1) × ∏(stride of layers 1 to l-1)
```

Pooling and strided convolutions expand receptive fields more aggressively. A 2×2 pooling with stride 2 doubles the receptive field in terms of input pixels.

Deep networks need sufficient receptive fields to capture contextual information. For image classification, the receptive field should eventually cover most of the image. For object detection, intermediate layers need receptive fields large enough to encompass objects at various scales.

### 3.6 Backpropagation Through Convolution

Understanding backpropagation through convolution deepens your intuition about how CNNs learn. During the forward pass, you convolve input `X` with kernel `W` to get output `Y`. During backpropagation, you receive gradient `dL/dY` from the next layer and need to compute `dL/dX` and `dL/dW`.

The gradient with respect to the weights is a convolution of the input with the gradient:

```
dL/dW[m, n, d, c] = Σ_Σ X[i+m, j+n, d] × dL/dY[i, j, c]
```

The gradient with respect to the input is a "full convolution" (technically, cross-correlation) of the gradient with the flipped kernel:

```
dL/dX[i, j, d] = Σ_Σ dL/dY[i-m, j-n, c] × W[m, n, d, c]
```

This is why convolution is such an elegant operation—the forward and backward passes are both convolutions (with some transposition and flipping). Modern deep learning frameworks handle this automatically, but knowing the math helps you debug issues and design custom layers.

## 4. Canonical Architectures: An Evolutionary Perspective

Understanding why each architecture was developed helps you choose the right model for your task and informs the design of new architectures. Let's trace the evolution of CNN architectures from simple to sophisticated.

### 4.1 LeNet-5: The Pioneer

LeNet-5, introduced by Yann LeCun in 1998 for handwritten digit recognition, was the first successful CNN. Its architecture seems simple today:

```
Input (32×32) → Conv(6 filters, 5×5) → AvgPool(2×2) → Conv(16 filters, 5×5) → AvgPool(2×2) → FC(120) → FC(84) → Output(10)
```

The key insight was that local receptive fields and weight sharing could learn spatial hierarchies. LeNet-5 achieved state-of-the-art accuracy on MNIST (Modified National Institute of Standards and Technology database of handwritten digits) and was used in production systems for reading checks.

**Numeric Example - LeNet-5 Forward Pass:**

Let's trace a 32×32 grayscale image through LeNet-5:

```
Input: 32×32×1

Layer 1 - Conv(6 filters, 5×5):
  Output size: (32 - 5 + 1) = 28
  Output shape: 28×28×6
  Parameters: 6 × (5×5×1 + 1) = 156

Layer 2 - AvgPool(2×2, stride=2):
  Output size: 28/2 = 14
  Output shape: 14×14×6
  Parameters: 0

Layer 3 - Conv(16 filters, 5×5):
  Output size: (14 - 5 + 1) = 10
  Output shape: 10×10×16
  Parameters: 16 × (5×5×6 + 1) = 2,416

Layer 4 - AvgPool(2×2, stride=2):
  Output size: 10/2 = 5
  Output shape: 5×5×16
  Parameters: 0

Layer 5 - FC(120):
  Input: 5×5×16 = 400 neurons flattened
  Output: 120 neurons
  Parameters: 400×120 + 120 = 48,120

Layer 6 - FC(84):
  Parameters: 120×84 + 84 = 10,164

Layer 7 - Output(10):
  Parameters: 84×10 + 10 = 850

Total parameters: 156 + 2,416 + 48,120 + 10,164 + 850 = 61,706
```

For a single pixel in the first conv output, the computation is:
```
output[0,0,0] = Σ(i=0 to 4) Σ(j=0 to 4) input[i,j] × kernel[i,j,0] + bias[0]
```

If the 5×5 input patch has values averaging 128 and the kernel weights sum to 0.1 with bias 0.5:
```
output ≈ 128 × 0.1 + 0.5 = 13.3 (before activation)
```

However, it was limited by computational resources and training data. Deep networks were known to be hard to train due to vanishing gradients and overfitting.

### 4.2 AlexNet: The Deep Learning Revolution

AlexNet, winning ImageNet 2012, proved that deep CNNs could learn powerful representations from large datasets. Its innovations included:

**ReLU activation**: Instead of tanh or sigmoid, ReLU trained much faster and mitigated vanishing gradients.

**Dropout**: Randomly zeroing neurons during training prevented overfitting, which was crucial given the network's 60 million parameters.

**Data augmentation**: Cropping, flipping, and color jittering artificially expanded the training set.

**GPU implementation**: Training on two GTX 580 GPUs made deeper networks feasible.

The architecture was:

```
Input (224×224×3) → Conv(96, 11×11, stride=4) → MaxPool → Conv(256, 5×5) → MaxPool → Conv(384, 3×3) → Conv(384, 3×3) → Conv(256, 3×3) → MaxPool → FC(4096) → FC(4096) → FC(1000)
```

AlexNet achieved 15.3% top-5 error on ImageNet, far better than the 26% error of the second-place method (which used handcrafted features). This result catalyzed the deep learning era.

**Numeric Example - AlexNet Dimension Tracking:**

Let's trace a 224×224×3 RGB image through AlexNet:

```
Input: 224×224×3

Layer 1 - Conv(96, 11×11, stride=4, padding=2):
  Output size: floor[(224 + 2×2 - 11) / 4] + 1 = floor[217/4] + 1 = 55
  Output shape: 55×55×96
  Parameters: 96 × (11×11×3 + 1) = 34,944
  FLOPs: 55 × 55 × 96 × 11 × 11 × 3 × 2 ≈ 211M

Layer 2 - MaxPool(3×3, stride=2):
  Output size: floor[(55 - 3) / 2] + 1 = 27
  Output shape: 27×27×96

Layer 3 - Conv(256, 5×5, padding=2):
  Output shape: 27×27×256
  Parameters: 256 × (5×5×96 + 1) = 614,656

Layer 4 - MaxPool(3×3, stride=2):
  Output shape: 13×13×256

Layer 5 - Conv(384, 3×3, padding=1):
  Output shape: 13×13×384
  Parameters: 384 × (3×3×256 + 1) = 885,120

Layer 6 - Conv(384, 3×3, padding=1):
  Output shape: 13×13×384
  Parameters: 384 × (3×3×384 + 1) = 1,327,488

Layer 7 - Conv(256, 3×3, padding=1):
  Output shape: 13×13×256
  Parameters: 256 × (3×3×384 + 1) = 884,992

Layer 8 - MaxPool(3×3, stride=2):
  Output shape: 6×6×256

Flatten: 6×6×256 = 9,216

FC1: 9,216 → 4,096 → Parameters: 9,216×4,096 + 4,096 = 37,752,832
FC2: 4,096 → 4,096 → Parameters: 4,096×4,096 + 4,096 = 16,781,312
FC3: 4,096 → 1,000 → Parameters: 4,096×1,000 + 1,000 = 4,097,000

Total: ~62 million parameters (most in FC layers!)
```

**Dropout Example:**
During training with dropout rate p=0.5 on FC1 output:
```
FC1 output (training): [2.1, 0, 1.5, 0, 3.2, 0, ...] (50% zeroed randomly)
FC1 output (inference): [1.05, 0.8, 0.75, 1.1, 1.6, 0.9, ...] (all values × 0.5)
```

### 4.3 VGGNet: Depth and Simplicity

VGG (Visual Geometry Group) from Oxford, introduced in 2014, showed that deeper networks with small filters outperform shallower networks with large filters. VGG-16 and VGG-19 use only 3×3 convolutions throughout, increasing depth to 16-19 layers.

The intuition is that two 3×3 convolutions have the same receptive field as one 5×5 convolution (receptive field of 5×5) but with fewer parameters: `2 × (3² × C²) = 18C²` versus `25C²` for a single 5×5. Additionally, two layers with ReLU in between introduce more nonlinearity, increasing representational power.

VGG's architecture is highly regular:

```
(Conv3×3 → Conv3×3 → MaxPool) → (Conv3×3 → Conv3×3 → MaxPool) → (Conv3×3 → Conv3×3 → Conv3×3 → MaxPool) → ...
```

This simplicity made VGG a popular choice for transfer learning and feature extraction. However, VGG is parameter-heavy (138 million parameters in VGG-16) and slow to train and run.

**Numeric Example - VGG-16 Architecture:**

Let's trace through VGG-16 with a 224×224×3 input:

```
Input: 224×224×3

Block 1:
  Conv3×3-64 → Conv3×3-64 → MaxPool
  224×224×64 → 224×224×64 → 112×112×64
```

### 4.4 ResNet: Solving the Degradation Problem

As networks got deeper, accuracy saturated and then degraded—not due to overfitting but because deeper networks became harder to optimize. The **residual learning** framework introduced by ResNet in 2015 solved this.

Instead of learning a mapping `H(x)`, ResNet layers learn the residual `F(x) = H(x) - x`. The output is `H(x) = F(x) + x`, implemented via a skip connection. Mathematically:

```
y = F(x, {W_i}) + x
```

where `F(x, {W_i})` represents stacked layers (typically two or three convolutional layers with BatchNorm and ReLU).

Why does this help? If the optimal mapping is close to the identity, it's easier to learn `F(x) ≈ 0` than to learn `H(x) = x` directly. Skip connections also provide gradient highways—during backpropagation, gradients flow directly through the identity path, mitigating vanishing gradients.

ResNet-50, ResNet-101, and ResNet-152 demonstrated that networks with 50, 101, or even 152 layers could be trained effectively, achieving top performance on ImageNet and other benchmarks. ResNet-50's architecture uses bottleneck blocks:

```
(1×1 Conv, 64 filters) → (3×3 Conv, 64 filters) → (1×1 Conv, 256 filters) + skip connection
```

The 1×1 convolutions reduce and then expand dimensionality, making the 3×3 convolution cheaper. This design allows deeper networks without excessive computation.

ResNet remains a workhorse architecture. Its variants are used for classification, object detection, segmentation, and as backbones in foundation models.

**Numeric Example - ResNet Residual Block:**

Let's trace through a basic residual block with concrete numbers:

```
Input x: shape (56×56×64), sample values at one position: [0.5, -0.3, 0.8, ...]

Basic Block (two 3×3 convs):
  Conv1: 3×3, 64 filters, padding=1
    Weights W1, Bias b1
    Output z1 = Conv(x, W1) + b1
    After ReLU: a1 = max(0, z1)
    Shape: 56×56×64
    Sample output: [0.2, 0.0, 0.6, ...]  (some values zeroed by ReLU)

  Conv2: 3×3, 64 filters, padding=1
    Output z2 = Conv(a1, W2) + b2
    Shape: 56×56×64
    Sample output: [0.1, -0.2, 0.3, ...]

Skip Connection:
    output = z2 + x  (element-wise addition)
    Sample: [0.1 + 0.5, -0.2 + (-0.3), 0.3 + 0.8, ...] = [0.6, -0.5, 1.1, ...]
    After ReLU: [0.6, 0.0, 1.1, ...]
```

**Bottleneck Block (ResNet-50/101/152):**
```
Input: 56×56×256

1×1 Conv (reduce): 256 → 64 channels
  Parameters: 1×1×256×64 + 64 = 16,448
  Output: 56×56×64

3×3 Conv: 64 → 64 channels
  Parameters: 3×3×64×64 + 64 = 36,928
  Output: 56×56×64

1×1 Conv (expand): 64 → 256 channels
  Parameters: 1×1×64×256 + 256 = 16,640
  Output: 56×56×256

Total block params: 16,448 + 36,928 + 16,640 = 70,016

Compare to basic block (two 3×3 convs, 256 channels):
  2 × (3×3×256×256 + 256) = 1,180,160 parameters

Bottleneck saves: 94% fewer parameters!
```

**Gradient Flow Example:**
```
Forward: y = F(x) + x
Backward: ∂L/∂x = ∂L/∂y × (∂F/∂x + 1)

The "+1" term means gradients flow directly through skip connections,
even if ∂F/∂x → 0 (vanishing gradients in F).

If ∂L/∂y = 0.01 and ∂F/∂x = 0.001:
  Without skip: ∂L/∂x = 0.01 × 0.001 = 0.00001 (vanishes!)
  With skip: ∂L/∂x = 0.01 × (0.001 + 1) = 0.01001 (preserved!)
```

### 4.5 DenseNet: Maximum Information Flow

DenseNet (Densely Connected Network) takes skip connections further—each layer connects to every subsequent layer within a dense block. If a block has `L` layers, there are `L(L+1)/2` connections.

Mathematically, the input to the `l`-th layer is the concatenation of all previous layers:

```
x_l = H_l([x_0, x_1, ..., x_{l-1}])
```

This design ensures maximal information flow and feature reuse. Gradients flow directly to all layers, and early features are accessible to later layers without passing through many transformations.

DenseNet has fewer parameters than ResNet for similar performance because each layer adds only a small number of feature maps (the growth rate, typically 32). However, memory consumption during training is high due to storing all intermediate activations for concatenation.

DenseNet showed that connectivity patterns matter as much as depth. It's particularly effective for tasks requiring fine-grained features, such as medical image segmentation.

### 4.6 EfficientNet: Compound Scaling

EfficientNet, introduced in 2019, addresses the question: how should you scale a network to balance accuracy and efficiency? Prior work scaled depth, width, or resolution independently, but EfficientNet shows that compound scaling works better.

The compound scaling formula scales depth, width, and resolution together:

```
depth: d = α^φ
width: w = β^φ
resolution: r = γ^φ
```

subject to `α × β² × γ² ≈ 2` (to double FLOPs) and `α ≥ 1, β ≥ 1, γ ≥ 1`. The parameter `φ` controls the scaling magnitude.

EfficientNet-B0 is the base model found via neural architecture search. EfficientNet-B1 through B7 are scaled versions. EfficientNet-B7 achieves 84.3% top-1 accuracy on ImageNet with 66 million parameters and 37 billion FLOPs—better accuracy than previous models with 8.4× fewer parameters.

The key insight is that scaling dimensions together is more effective than scaling any single dimension. Deeper networks need more width to capture increased complexity, and higher resolution inputs need more depth and width to process the additional information.

**Numeric Example - EfficientNet Compound Scaling:**

Starting from EfficientNet-B0 baseline (found via NAS):
```
EfficientNet-B0:
  Resolution: 224×224
  Width multiplier: 1.0
  Depth multiplier: 1.0
  Parameters: 5.3M
  Top-1 Accuracy: 77.1%
```

Grid search found optimal coefficients: α=1.2, β=1.1, γ=1.15

**Scaling to EfficientNet-B3 (φ=3):**
```

Width: w = β^φ = 1.1³ = 1.331 (1.3× wider)
Resolution: r = γ^φ = 1.15³ = 1.521 → 224 × 1.521 = 341 → rounded to 300

EfficientNet-B3:
  Resolution: 300×300
  Parameters: 12M
  Top-1 Accuracy: 81.6%
```

**Scaling to EfficientNet-B7 (φ=7):**
```

  Resolution: 600×600
```

**FLOPs Verification:**
```
FLOPs ∝ d × w² × r²
For φ=1: 1.2 × 1.1² × 1.15² ≈ 1.2 × 1.21 × 1.32 ≈ 1.92 ≈ 2
```


### 4.7 Vision Transformers: Breaking the CNN Paradigm

Vision Transformers (ViT), introduced in 2020, apply the transformer architecture (originally designed for NLP) directly to images. This was surprising because CNNs seemed tailor-made for vision with their inductive biases.

ViT splits an image into patches (e.g., 16×16 pixels), flattens each patch to a vector, and projects it to an embedding space. These patch embeddings are treated as tokens in a sequence, and a standard transformer encoder processes them.

The patch embedding layer is a convolution with kernel size and stride equal to the patch size:

```
Patch embedding: Conv(embed_dim, kernel=16, stride=16)
```

For a 224×224 image with 16×16 patches, you get (224/16)² = 196 patch tokens. A learnable class token is prepended, and positional embeddings are added:

```
z_0 = [x_class; x_patch_1; ...; x_patch_196] + E_pos
```

Then you apply `L` transformer blocks, each containing multi-head self-attention and a feed-forward network:

```
z'_l = MSA(LN(z_{l-1})) + z_{l-1}
z_l = MLP(LN(z'_l)) + z'_l
```

where MSA is multi-head self-attention, LN is layer normalization, and MLP is a two-layer feed-forward network.

Self-attention computes for each token a weighted combination of all other tokens:

```
Attention(Q, K, V) = softmax(QK^T / √d_k) V
```

where `Q`, `K`, `V` are query, key, and value matrices obtained by linearly projecting the input.

The key difference from CNNs is that self-attention has global receptive fields from the first layer—every token attends to every other token. This provides flexibility but removes the inductive bias of locality.

ViT trained on ImageNet alone underperforms ResNets. However, when pretrained on large datasets (300 million images), ViT outperforms CNNs on ImageNet and other benchmarks. This suggests that transformers are more data-hungry but have higher representation capacity.

Hybrid architectures like Swin Transformer introduce locality and hierarchy back into transformers by using shifted windows for attention, achieving state-of-the-art results more efficiently. ViT and its variants are now standard for vision tasks, especially when large-scale pretraining is feasible.

Let's trace a 224×224×3 image through ViT-Base:


## 5. Task-Specific Models and Architectures

Different vision tasks require different output structures and loss functions. Let's examine the major task categories and the architectures designed for them.

### 5.1 Image Classification: From Softmax to Metric Learning

Image classification assigns a single label from a fixed set to an image. It's the foundation of computer vision and serves as pretraining for other tasks.

The standard setup: Given an image `x`, a network produces a feature vector `f(x) ∈ R^d`. A final linear layer maps features to logits `z = Wf(x) + b ∈ R^C` where `C` is the number of classes. You apply softmax to get probabilities:

```
p(y=k | x) = exp(z_k) / Σ_j exp(z_j)
```

The cross-entropy loss measures the difference between predicted and true distributions:

```
L_CE = -log p(y=k | x) = -z_k + log Σ_j exp(z_j)
```

Let's work a numeric example. Suppose you have 3 classes and logits `z = [2.0, 1.0, 0.1]`. The true class is class 0. First, compute softmax:

```
exp(z) = [7.39, 2.72, 1.11]
Σ exp(z) = 11.22
p = [7.39/11.22, 2.72/11.22, 1.11/11.22] = [0.659, 0.242, 0.099]
```

Cross-entropy loss is `-log(0.659) = 0.417`. If the model were confident (e.g., `p = [0.99, 0.005, 0.005]`), the loss would be `-log(0.99) = 0.010`. Cross-entropy is minimized when the model assigns probability 1 to the correct class.

For evaluation, **top-k accuracy** measures whether the correct label is among the top k predictions. On ImageNet, top-5 accuracy is standard because many classes are similar (e.g., different dog breeds).

**Metric learning** approaches learn embeddings where similar images are close and dissimilar images are far. Triplet loss is common:

```
L_triplet = max(||f(anchor) - f(positive)||² - ||f(anchor) - f(negative)||² + margin, 0)
```

This encourages the distance to a positive example to be at least `margin` smaller than the distance to a negative example. Metric learning is valuable for tasks like face recognition where you need to verify identity rather than classify into predefined classes.

### 5.2 Object Detection: Localization and Classification

Object detection requires both classifying objects and localizing them with bounding boxes. This is significantly harder than classification because there can be multiple objects of varying sizes and aspect ratios.

**R-CNN (Regions with CNN features)** was the first successful deep learning detector. It generates region proposals using selective search (a classical method), warps each proposal to a fixed size, runs a CNN to extract features, and classifies each region with an SVM. Training is slow and multistage.

**Fast R-CNN** improved upon R-CNN by running the CNN once on the entire image and then pooling features for each region proposal using RoI (Region of Interest) pooling. This shares computation and speeds up training and inference.

**Faster R-CNN** introduced the **Region Proposal Network (RPN)**, making the entire pipeline end-to-end trainable. The RPN slides a small network over the feature map and predicts whether each location contains an object and how to adjust predefined anchor boxes to tightly fit objects.

Anchor boxes are predefined bounding boxes of various sizes and aspect ratios at each spatial location. For example, at each location, you might have 9 anchors (3 scales × 3 aspect ratios). The RPN predicts for each anchor:

- Object score (objectness): Does this anchor contain an object?
- Bounding box refinement: How to adjust the anchor to fit the object?

The refinement is parameterized as:

```
t_x = (x - x_a) / w_a
t_y = (y - y_a) / h_a
t_w = log(w / w_a)
t_h = log(h / h_a)
```

where `(x, y, w, h)` is the ground truth box, `(x_a, y_a, w_a, h_a)` is the anchor, and `(t_x, t_y, t_w, t_h)` are the regression targets. This parameterization is scale-invariant—shifts are normalized by anchor size, and scale changes are in log space.

During training, anchors are matched to ground truth boxes based on **Intersection over Union (IoU)**:

```
IoU(A, B) = Area(A ∩ B) / Area(A ∪ B)
```

Anchors with IoU > 0.7 are positive, IoU < 0.3 are negative, and others are ignored. The loss is:

```
L = L_cls + λ L_bbox
```

where `L_cls` is cross-entropy over object/background and `L_bbox` is smooth L1 loss for bounding box regression.

**YOLO (You Only Look Once)** takes a different approach: it frames detection as a regression problem. The image is divided into an S×S grid. Each grid cell predicts B bounding boxes and confidence scores, plus class probabilities. YOLO is extremely fast because it processes the image in a single pass.

YOLOv1 struggles with small objects because the grid is coarse. Later versions (YOLOv2, YOLOv3, up to YOLOv8 and beyond) introduce anchor boxes, multi-scale predictions, and better backbones. YOLOv3, for instance, predicts at three scales using a Feature Pyramid Network.

Modern YOLO variants are state-of-the-art in real-time detection. For production systems requiring low latency (e.g., autonomous vehicles, robotics), YOLO is often the default choice.

```
  NMS per class (IoU threshold 0.45): ~20 final detections
```

**Evaluating object detectors**: The standard metric is **mean Average Precision (mAP)**. Let's break this down:

For a single class, you rank all predicted boxes by confidence. As you go down the list, compute precision and recall at each position. **Precision** is the fraction of predicted boxes (so far) that are correct. **Recall** is the fraction of ground truth objects detected. A predicted box is correct if its IoU with a ground truth box exceeds a threshold (e.g., 0.5).

Plot precision vs. recall to get a P-R curve. **Average Precision (AP)** is the area under this curve. Compute AP for each class and average to get mAP.

On COCO (Common Objects in Context), mAP is averaged over multiple IoU thresholds (0.5, 0.55, ..., 0.95), making it stricter and more informative.

Example: Suppose for a class you have predictions with confidences [0.9, 0.8, 0.7, 0.6, 0.5] and correctness [True, False, True, True, False] based on IoU. There are 3 ground truth objects.

| Confidence | Correct | Precision | Recall |
|------------|---------|-----------|--------|
| 0.9        | True    | 1/1=1.0   | 1/3=0.33 |
| 0.8        | False   | 1/2=0.5   | 1/3=0.33 |
| 0.7        | True    | 2/3=0.67  | 2/3=0.67 |
| 0.6        | True    | 3/4=0.75  | 3/3=1.0  |
| 0.5        | False   | 3/5=0.6   | 3/3=1.0  |

AP is computed by interpolating precision at recall levels 0.0, 0.1, ..., 1.0 and averaging. This measures how well the model balances precision and recall across different confidence thresholds.

### 5.3 Semantic and Instance Segmentation

**Semantic segmentation** assigns a class label to every pixel. It's "semantic" because pixels with the same class are grouped regardless of object instances.

**Fully Convolutional Networks (FCN)** were the first successful deep learning approach. They replace fully connected layers with 1×1 convolutions, allowing arbitrary input sizes and producing spatial output. Upsampling layers (transposed convolutions) restore the original resolution.

The architecture is encoder-decoder: The encoder extracts features and downsamples via pooling. The decoder upsamples and combines features from multiple scales via skip connections. Skip connections from encoder to decoder help recover fine details lost during downsampling.

**U-Net**, developed for medical image segmentation, popularized this architecture. It has a symmetric encoder-decoder structure with skip connections at each resolution level. U-Net works well with small datasets because the skip connections provide strong gradients.

**DeepLab** introduced **atrous (dilated) convolutions** to capture multi-scale context without downsampling. Atrous Spatial Pyramid Pooling (ASPP) applies dilated convolutions with different rates in parallel and concatenates the results. This captures both fine details and global context.

The loss function for segmentation is typically pixel-wise cross-entropy:

```
L_CE = -(1/N) Σ_i Σ_k y_{i,k} log p_{i,k}
```

where `i` indexes pixels, `k` indexes classes, and `y_{i,k}` is the one-hot encoded ground truth.

**Dice loss** is common in medical imaging due to class imbalance. The Dice coefficient measures overlap between prediction and ground truth:

```
Dice = 2|X ∩ Y| / (|X| + |Y|)
```

Dice loss is `L_Dice = 1 - Dice`. It handles imbalance better than cross-entropy because it's ratio-based rather than absolute.

Let's compute Dice loss for a simple case. Suppose the prediction is `p = [0.9, 0.1, 0.8]` (class 1 probabilities for 3 pixels) and ground truth is `y = [1, 0, 1]`. The numerator is `2 × (0.9×1 + 0.1×0 + 0.8×1) = 2 × 1.7 = 3.4`. The denominator is `(0.9+0.1+0.8) + (1+0+1) = 1.8 + 2 = 3.8`. Dice = 3.4 / 3.8 = 0.895, so Dice loss = 0.105.

**Instance segmentation** distinguishes between different instances of the same class. **Mask R-CNN** extends Faster R-CNN by adding a mask prediction branch. For each RoI, it predicts a binary mask in addition to class and bounding box. The mask branch is a small FCN applied to the RoI feature.

Mask R-CNN decouples mask and class prediction—mask prediction is class-agnostic initially, and the class-specific mask is selected based on the predicted class. This improves performance because the mask branch focuses on shape.

The loss is:

```
L = L_cls + L_bbox + L_mask
```

where `L_mask` is binary cross-entropy averaged over the RoI.

### 5.4 Keypoint and Pose Estimation

Keypoint detection localizes specific points like joints in human pose estimation or facial landmarks. The standard approach represents each keypoint as a **heatmap**: a 2D Gaussian centered at the keypoint location.

During training, you generate ground truth heatmaps by placing a Gaussian at each keypoint with standard deviation σ (typically a few pixels). The network predicts heatmaps, and the loss is L2 or cross-entropy between predicted and ground truth heatmaps.

At inference, you find the maximum value in each predicted heatmap to locate the keypoint. More accurate localization uses sub-pixel refinement (e.g., fitting a quadratic around the maximum).

**Object Keypoint Similarity (OKS)** is the evaluation metric for pose estimation. It's analogous to IoU for bounding boxes:

```
OKS = Σ_i exp(-d_i² / (2 s² k_i²)) δ(v_i > 0) / Σ_i δ(v_i > 0)
```

where `d_i` is the Euclidean distance between predicted and ground truth keypoint i, `s` is the object scale (area), `k_i` is a per-keypoint constant (keypoints vary in localization difficulty), and `v_i` is the visibility flag.

OKS ranges from 0 to 1, with 1 being a perfect match. Average Precision is computed over multiple OKS thresholds (0.5, 0.55, ..., 0.95), similar to object detection.

**Numeric Example - Human Pose Estimation:**

Let's trace pose estimation for a person in a 256×192 image:

```
Step 1: Network Architecture (SimpleBaseline/HRNet)
  Input: 256×192×3

  Backbone (ResNet-50):
    Output feature map: 64×48×2048

  Deconv layers (upsample):
    64×48×2048 → 64×48×256 (deconv 4×4, stride 2, but same size due to padding)
    → 128×96×256 (deconv 4×4, stride 2)
    → 256×192×256 (deconv 4×4, stride 2 - but typically we stop at 64×48)

  Actually, typical output: 64×48×17 (COCO has 17 keypoints)

Step 2: Ground Truth Heatmap Generation
  For keypoint "right elbow" at pixel location (120, 95):

  Create 64×48 heatmap (4× downsampled):
    Keypoint in heatmap coords: (120/4, 95/4) = (30, 23.75)

  Generate 2D Gaussian (σ=2 in heatmap space):
    For each position (x, y):
      heatmap[y, x] = exp(-[(x-30)² + (y-23.75)²] / (2×2²))

    At (30, 24): heatmap = exp(-0.03) = 0.97 (peak)
    At (28, 24): heatmap = exp(-2.0) = 0.135
    At (26, 24): heatmap = exp(-8.0) = 0.0003

  17 such heatmaps, one per keypoint

Step 3: Prediction
  Network outputs: 64×48×17 heatmaps

  For "right elbow" channel:
    Find argmax: position (29, 24) with value 0.85

    Refine with sub-pixel accuracy:
      Look at neighbors: (28,24)=0.3, (30,24)=0.7
      Shift = 0.25 × sign(0.7 - 0.3) = 0.25
      Refined: (29.25, 24)

    Convert to image coords: (29.25×4, 24×4) = (117, 96)

Step 4: Loss Computation (MSE)
  For one heatmap:
    L = (1/64×48) × Σ_all_positions (pred - gt)²

  If gt peak = 0.97 and pred peak = 0.85:
    Contribution at peak: (0.97 - 0.85)² = 0.0144

  Total loss = sum over 17 keypoints

Step 5: OKS Evaluation
  Predicted keypoints (17 points):
    nose: (128, 45), left_eye: (135, 40), right_elbow: (117, 96), ...

  Ground truth:
    nose: (130, 44), left_eye: (137, 41), right_elbow: (120, 95), ...

  Person bounding box area: 150×300 = 45,000 pixels
  Scale s = √45000 = 212

  For right_elbow (k_elbow = 0.072 from COCO):
    d = √[(117-120)² + (96-95)²] = √10 = 3.16 pixels
    oks_elbow = exp(-3.16² / (2 × 212² × 0.072²))
              = exp(-10 / (2 × 44944 × 0.0052))
              = exp(-10 / 467)
              = exp(-0.021) = 0.979

  Average OKS over visible keypoints → AP calculation
```

## 6. Training and Optimization

Training deep networks for computer vision involves many practical considerations. You need to balance model capacity, regularization, and computational efficiency. Let's examine key techniques.

### 6.1 Data Augmentation: Expanding Your Dataset

Data augmentation artificially increases training data diversity by applying transformations that preserve labels. Mathematically, you're learning a model that's invariant to the augmentation distribution.

Common augmentations for classification:

**Geometric transformations**: Random cropping, flipping (horizontal, sometimes vertical), rotation (small angles). These exploit the fact that object identity doesn't depend on exact position or orientation.

**Color transformations**: Brightness, contrast, saturation, hue jittering. These make the model robust to lighting variations. For instance, adding random brightness: `I' = I + δ` where `δ ~ Uniform(-α, α)`.

**Cutout**: Randomly mask out rectangular regions of the image. This encourages the model to use multiple parts of the object rather than relying on a single discriminative feature.

**Mixup**: Blend two training examples: `x' = λx_1 + (1-λ)x_2` and `y' = λy_1 + (1-λ)y_2` where `λ ~ Beta(α, α)`. This creates synthetic training points and improves generalization. It also provides softer targets, acting as label smoothing.

**RandAugment** and **AutoAugment** automatically search for effective augmentation policies using reinforcement learning or grid search. They've achieved state-of-the-art results by finding combinations that maximize validation accuracy.

For object detection and segmentation, augmentations must transform both images and labels consistently. If you flip an image, you must flip bounding boxes and masks accordingly.

### 6.2 Transfer Learning: Standing on the Shoulders of Giants

Training from scratch requires enormous datasets and compute. Transfer learning leverages pretrained models to accelerate training and improve performance on small datasets.

The typical workflow:

1. Take a model pretrained on ImageNet (e.g., ResNet-50).
2. Remove the final classification layer.
3. Add a new classification layer for your task.
4. Fine-tune on your dataset.

You can freeze early layers (keep pretrained weights fixed) or fine-tune the entire network. The choice depends on dataset size and similarity to ImageNet:

- **Small dataset, similar to ImageNet**: Freeze most layers, train only the final layers. Early layers learn generic features (edges, textures) that transfer well.
- **Small dataset, different from ImageNet**: Still use pretrained weights for initialization, but you might need more aggressive fine-tuning or train from scratch if the domain is very different.
- **Large dataset**: Fine-tune the entire network. Pretrained weights provide better initialization than random weights, speeding up convergence.

Lower learning rates for pretrained layers and higher learning rates for new layers is a common strategy. This prevents catastrophic forgetting of learned features while allowing task-specific adaptation.

Transfer learning is why you almost never train image classifiers from scratch anymore. Even with thousands of labeled images, starting from ImageNet weights improves accuracy by 5-10%.

### 6.3 Learning Rate Schedules: Guiding Optimization

The learning rate is the most important hyperparameter. A constant learning rate rarely works well—you need to adjust it during training.

**Step decay**: Reduce the learning rate by a factor (e.g., 0.1) every few epochs. For example, start with 0.1, drop to 0.01 at epoch 30, and to 0.001 at epoch 60. This allows the model to make large updates initially and fine-tune later.

**Cosine annealing**: Smoothly decrease the learning rate following a cosine curve:

```
η_t = η_min + (η_max - η_min) × (1 + cos(πt/T)) / 2
```

where `t` is the current epoch and `T` is the total number of epochs. This provides a smooth decay and is easy to implement.

**Warmup**: Start with a very small learning rate and gradually increase it over the first few epochs. This is crucial when training from scratch or with large batch sizes. Warmup stabilizes training by preventing large gradients early on when the model is far from a good solution.

**Cyclical learning rates**: Cycle the learning rate between a minimum and maximum value. This can help escape local minima and saddle points, improving generalization.

**ReduceLROnPlateau**: Monitor a validation metric and reduce the learning rate when it plateaus. This is adaptive and doesn't require specifying a schedule in advance.

In practice, cosine annealing with warmup is a safe default. If you're training for 100 epochs, use 5-10 epochs of warmup and then cosine decay.

### 6.4 Handling Class Imbalance

Real-world datasets are often imbalanced—some classes have many more examples than others. This causes models to bias toward frequent classes.

**Resampling**: Oversample minority classes or undersample majority classes to balance the dataset. This changes the effective class distribution but can lead to overfitting (oversampling) or discarding data (undersampling).

**Class weighting**: Assign higher loss weights to minority classes:

```
L = Σ_i w_{y_i} × CE(y_i, ŷ_i)
```

where `w_c` is the weight for class `c`, often set to `w_c = N / (C × N_c)` where `N` is total samples, `C` is number of classes, and `N_c` is samples in class `c`.

**Focal loss**: Introduced for object detection, focal loss down-weights easy examples:

```
FL(p_t) = -(1 - p_t)^γ log(p_t)
```

where `p_t` is the predicted probability of the true class and `γ > 0` is a focusing parameter (typically 2). When an example is easy (`p_t` close to 1), `(1 - p_t)^γ` is small, reducing its contribution. When an example is hard (`p_t` close to 0), the loss is similar to standard cross-entropy.

Focal loss is particularly effective when the imbalance is extreme (e.g., 1:1000) and is standard in modern object detectors like RetinaNet.

### 6.5 Regularization Techniques

Regularization prevents overfitting by constraining the model's capacity or introducing noise.

**Dropout**: During training, randomly zero out activations with probability `p`. At test time, scale activations by `(1-p)` or use the training mode where dropout is automatically handled. Dropout forces the network to learn redundant representations and prevents co-adaptation of neurons.

**Weight decay (L2 regularization)**: Add a penalty to the loss:

```
L = L_task + λ Σ_w w²
```

This encourages small weights, reducing model complexity. Weight decay is implemented in optimizers like SGD and Adam by modifying the weight update: `w ← w - η(∇L_task + 2λw)`.

**Label smoothing**: Replace hard targets `y = [0, 0, 1, 0]` with soft targets `y = [ε/(C-1), ε/(C-1), 1-ε, ε/(C-1)]` where `ε` is small (e.g., 0.1). This prevents the model from becoming overconfident and improves calibration.

**Stochastic depth**: Randomly drop entire layers during training (similar to dropout but at the layer level). This is used in very deep networks like ResNets with hundreds of layers.

## 7. Evaluation Metrics: Measuring What Matters

Choosing the right metric is as important as choosing the right model. Different metrics emphasize different aspects of performance, and optimizing for the wrong metric can lead to poor real-world performance.

### 7.1 Classification Metrics

**Accuracy**: Fraction of correct predictions. It's intuitive but misleading with imbalanced data. If 95% of samples are class 0, a model that always predicts class 0 has 95% accuracy but is useless.

**Top-k accuracy**: Fraction of samples where the true label is in the top k predictions. On ImageNet, top-5 accuracy is more forgiving and better reflects human performance (many classes are visually similar).

**Precision and Recall**: For a binary or per-class basis:

```
Precision = TP / (TP + FP)
Recall = TP / (TP + FN)
```

Precision measures the fraction of positive predictions that are correct. Recall measures the fraction of actual positives that are detected. There's a trade-off—increasing the decision threshold increases precision but decreases recall.

**F1 score**: The harmonic mean of precision and recall:

```
F1 = 2 × (Precision × Recall) / (Precision + Recall)
```

F1 balances precision and recall, making it useful when you care equally about both. For imbalanced problems, macro-averaged F1 (average F1 across classes) is more informative than accuracy.

**Confusion matrix**: A C×C matrix where entry (i, j) is the number of samples with true class i predicted as class j. The diagonal shows correct predictions. Off-diagonal entries reveal which classes are confused. Analyzing the confusion matrix helps identify failure modes.

Example: In medical imaging, if your model confuses malignant tumors (class 1) with benign tumors (class 0), the confusion matrix shows this as a large off-diagonal entry at position (1, 0). This indicates you need more training data or better features for that distinction.

### 7.2 Detection Metrics

**Intersection over Union (IoU)**: Already discussed, but worth emphasizing. IoU thresholds determine what counts as a correct detection. Standard thresholds are 0.5 (lenient) and 0.75 (strict).

**Generalized IoU (GIoU)**: IoU is zero when boxes don't overlap, providing no gradient signal. GIoU addresses this:

```
GIoU = IoU - (|C \ (A ∪ B)|) / |C|
```

where C is the smallest box enclosing A and B. GIoU ranges from -1 to 1 and provides gradients even for non-overlapping boxes, making it a better loss function.

**Complete IoU (CIoU)**: Incorporates distance between box centers and aspect ratio difference:

```
CIoU = IoU - ρ²(center_A, center_B) / c² - αv
```

where `ρ` is Euclidean distance between centers, `c` is the diagonal of the smallest enclosing box, `v` measures aspect ratio difference, and `α` is a trade-off parameter. CIoU loss leads to faster convergence and better localization.

**mean Average Precision (mAP)**: The gold standard for detection. Compute AP for each class and average. On COCO, mAP@[0.5:0.95] averages over 10 IoU thresholds, making it more comprehensive than Pascal VOC's mAP@0.5.

### 7.3 Segmentation Metrics

**Pixel accuracy**: Fraction of correctly classified pixels. Like classification accuracy, it's misleading with imbalance. If 90% of pixels are background, predicting all background gives 90% accuracy.

**Mean Intersection over Union (mIoU)**: Compute IoU for each class and average:

```
IoU_class = |Predicted ∩ Ground Truth| / |Predicted ∪ Ground Truth|
mIoU = (1/C) Σ_c IoU_c
```

mIoU is the standard metric for semantic segmentation benchmarks like Cityscapes and PASCAL VOC.

**Dice coefficient**: Already discussed for loss, but also used as a metric. Dice is similar to IoU: `Dice = 2×IoU / (1 + IoU)`. They rank models similarly, but Dice gives slightly more weight to true positives.

For instance segmentation, metrics are more complex because you must match predicted instances to ground truth instances. The COCO metric uses IoU to match and computes AP over different IoU thresholds.

## 8. State-of-the-Art and Emerging Trends

The field moves rapidly. What's cutting-edge today becomes standard tomorrow, and what seems impossible today becomes routine next year. Let's survey current frontiers and where the field is heading.

### 8.1 Vision Transformers and Hybrid Models

ViT proved transformers can excel at vision when trained at scale. But pure transformers are inefficient for high-resolution images due to quadratic attention complexity.

**Swin Transformer** introduces hierarchical structure and shifted window attention. Instead of global attention over all patches, attention is computed within local windows (e.g., 7×7 patches). Between layers, windows are shifted, allowing cross-window communication. This reduces complexity from O(N²) to O(N) where N is the number of patches, making Swin Transformer practical for dense prediction tasks like segmentation.

**CoAtNet** combines convolutions and transformers. Early layers use convolutions for efficiency and local feature extraction. Later layers use transformers for global reasoning. This hybrid approach achieves better accuracy-efficiency trade-offs than pure CNNs or pure transformers.

**ConvNeXt** modernizes ConvNets by borrowing design choices from transformers (larger kernels, fewer activations, GELU, LayerNorm) and achieves competitive performance with Swin Transformer while being simpler and faster. This shows that architectural components matter more than the broad category (CNN vs. transformer).

**Numeric Example - Swin Transformer:**

Let's trace a 224×224×3 image through Swin-Tiny:

```

Step 1: Patch Partition + Linear Embedding
  Patch size: 4×4
  Number of patches: (224/4)² = 56×56 = 3,136 patches
  Each patch: 4×4×3 = 48 values
  Linear projection: 48 → 96 (embed_dim C=96)

  Result: 56×56×96 feature map (can view as 3136 tokens of dim 96)

Step 2: Stage 1 (2 Swin Transformer blocks)
  Window size: 7×7
  Number of windows: (56/7)² = 8×8 = 64 windows
  Tokens per window: 7×7 = 49

  Block 1 - Window Multi-Head Self-Attention (W-MSA):
    For each of 64 windows independently:
      Input: 49×96
      Attention: Q, K, V each 49×96
      Attention scores: 49×49 (within window only!)

    Complexity: 64 windows × 49² × 96 = 14.8M operations
    Compare to global attention: 3136² × 96 = 944M operations
    Savings: 64× fewer operations!

    Shift windows by (3, 3) pixels
    This allows cross-window communication

    Before shift:     After shift (cyclic):
    [W0][W1][W2]...   [...][W0][W1][W2]
    [W8][W9]...       [...][W8][W9]...

    Same complexity as W-MSA

  Linear layer: 384 → 192 (2C)
  Output: 28×28×192

  Number of windows: (28/7)² = 16 windows
  Tokens per window: 49

  Output: 28×28×192

  28×28×192 → 14×14×384

  Windows: (14/7)² = 4 windows
  Output: 14×14×384

Step 7: Patch Merging
  14×14×384 → 7×7×768

Step 8: Stage 4 (2 Swin blocks)
  Single window covers entire 7×7 feature map
  Output: 7×7×768

Step 9: Classification Head
  Global Average Pool: 7×7×768 → 768
  FC: 768 → 1000

Total parameters (Swin-Tiny): ~28 million
Compare to ViT-Base: ~86 million (3× larger for similar performance!)
```

**Shifted Window Attention Detail:**
```
Original windows (W-MSA):        Shifted windows (SW-MSA):
```

### 8.2 Self-Supervised Learning: Learning Without Labels

Labeling data is expensive and time-consuming. Self-supervised learning learns representations from unlabeled data by solving pretext tasks.

**Contrastive learning** (e.g., SimCLR, MoCo) learns by contrasting positive pairs (augmented views of the same image) against negative pairs (different images). The contrastive loss encourages representations of positive pairs to be similar and negative pairs to be dissimilar:

```
L_contrastive = -log[exp(sim(z_i, z_j)/τ) / Σ_k exp(sim(z_i, z_k)/τ)]
```

where `sim` is cosine similarity, `τ` is a temperature parameter, and the sum is over negatives.

**DINO** (self-distillation with no labels) uses a teacher-student framework where the student predicts the teacher's output. The teacher is an exponential moving average of the student. Without explicit negatives, DINO learns semantically meaningful features and discovers object parts without supervision.

**Masked Autoencoders (MAE)** apply the masked language modeling idea from BERT to images. Randomly mask patches (e.g., 75% of the image) and train the model to reconstruct them. This forces the model to understand context and relationships between patches. MAE achieves strong performance with simple reconstruction loss (MSE in pixel space) and can be pretrained on massive unlabeled datasets.

Self-supervised models pretrained on ImageNet or larger datasets transfer well to downstream tasks with minimal fine-tuning. They're becoming the default starting point for many applications.

**Numeric Example - SimCLR Contrastive Learning:**

Let's trace contrastive learning with a batch of 4 images:

```
Step 1: Data Augmentation (create positive pairs)
  Original images: [img_0, img_1, img_2, img_3]

  For each image, create 2 augmented views:
    img_0 → [view_0a, view_0b] (random crop + color jitter + flip)
    img_1 → [view_1a, view_1b]
    img_2 → [view_2a, view_2b]
    img_3 → [view_3a, view_3b]

  Batch of 8 views: [0a, 0b, 1a, 1b, 2a, 2b, 3a, 3b]

Step 2: Encoder (ResNet-50)
  Each view: 224×224×3 → 2048-dim feature vector
  Features h: shape (8, 2048)

Step 3: Projection Head (MLP)
  FC: 2048 → 2048 → ReLU → 2048 → 128
  Projected features z: shape (8, 128)

  Example values (L2 normalized):
    z_0a = [0.12, -0.08, 0.15, ..., 0.03]  (128 dims, ||z||=1)
    z_0b = [0.11, -0.09, 0.14, ..., 0.04]  (similar to z_0a)
    z_1a = [-0.05, 0.20, -0.12, ..., 0.08] (different from z_0)

Step 4: Compute Similarities (cosine similarity)
  Similarity matrix S[i,j] = z_i · z_j / τ  (τ=0.5 temperature)

  Example 8×8 similarity matrix (before /τ):
         0a    0b    1a    1b    2a    2b    3a    3b
    0a [ 1.0,  0.85, 0.12, 0.10, 0.08, 0.05, 0.15, 0.11]
    0b [ 0.85, 1.0,  0.14, 0.09, 0.06, 0.07, 0.13, 0.10]
    1a [ 0.12, 0.14, 1.0,  0.82, 0.20, 0.18, 0.11, 0.09]
    ...

  After dividing by τ=0.5:
    0a [ 2.0,  1.7,  0.24, 0.20, 0.16, 0.10, 0.30, 0.22]
    ...

Step 5: Contrastive Loss (InfoNCE)
  For view 0a, positive is 0b, negatives are all others:

  L_0a = -log[exp(S[0a,0b]) / Σ_k≠0a exp(S[0a,k])]

  Numerator: exp(1.7) = 5.47
  Denominator: exp(1.7) + exp(0.24) + exp(0.20) + ... = 5.47 + 1.27 + 1.22 + ...
             ≈ 5.47 + 5.5 = 10.97

  L_0a = -log(5.47 / 10.97) = -log(0.499) = 0.695

  Total loss = average over all 8 views

Step 6: Gradient Update
  Gradients push z_0a closer to z_0b (positive)
  Gradients push z_0a away from z_1a, z_2a, etc. (negatives)

Why temperature τ matters:
  τ=0.5 (typical): Moderate sharpness in softmax
  τ=0.1 (sharp): Almost hard negative mining, focuses on hardest negatives
  τ=1.0 (soft): More uniform distribution, gentler learning
```

**Numeric Example - Masked Autoencoder (MAE):**

```
Input: 224×224×3 image

Step 1: Patchify
  Patch size: 16×16
  Total patches: (224/16)² = 196 patches
  Each patch: 16×16×3 = 768 values

Step 2: Random Masking (75% mask ratio)
  Keep: 196 × 0.25 = 49 patches (visible)
  Mask: 196 × 0.75 = 147 patches (to reconstruct)

  Visible patch indices: [3, 7, 12, 25, 41, ..., 189] (49 random)
  Masked patch indices: [0, 1, 2, 4, 5, 6, ...] (147 remaining)

Step 3: Encoder (ViT)
  Only encode visible patches (massive efficiency gain!)
  Input: 49 patches × 768 dims
  After projection: 49 × 1024 (ViT-Large embed_dim)

  12-24 transformer blocks on only 49 tokens
  Output: 49 × 1024

  Compare to standard ViT: 196 tokens → 4× more compute!

Step 4: Decoder
  Add learnable mask tokens for 147 masked positions
  Full sequence: 196 × 512 (decoder is smaller)

  Add positional embeddings (so decoder knows where each patch goes)
  8 transformer blocks

  Output: 196 × 768 (predict pixel values)

Step 5: Reconstruction Loss (MSE on masked patches only)
  For each masked patch:
    Predicted: [0.52, 0.48, 0.61, ...] (768 normalized pixel values)
    Ground truth: [0.55, 0.45, 0.58, ...]

    Loss = (1/768) × Σ(pred - gt)²
         = (1/768) × [(0.52-0.55)² + (0.48-0.45)² + ...]

  Total loss = average over 147 masked patches

Key insight: By masking 75%, we force the model to learn
semantic understanding, not just local texture copying.
```

### 8.3 Foundation Models: CLIP and SAM

**CLIP (Contrastive Language-Image Pre-training)** learns a joint embedding space for images and text by training on 400 million image-text pairs from the internet. CLIP can perform zero-shot classification by comparing image embeddings to text embeddings of class names.

The training objective is a contrastive loss over batch pairs: for each image, maximize similarity with its text caption and minimize similarity with other captions. CLIP's representations are highly transferable and enable tasks like image retrieval, zero-shot detection, and text-to-image generation (when combined with diffusion models).

**SAM (Segment Anything Model)** is a foundation model for segmentation. Trained on a massive dataset of 11 million images and 1 billion masks, SAM can segment objects in any image given a prompt (point, bounding box, or mask). It uses a ViT encoder and a lightweight decoder, and it generalizes to novel objects without fine-tuning.

SAM democratizes segmentation—you can use it for interactive annotation, data augmentation, or as a component in larger systems. Foundation models like CLIP and SAM shift the paradigm from task-specific models to general-purpose models adapted via prompting.

**Numeric Example - CLIP Zero-Shot Classification:**

Let's classify an image of a dog using CLIP:

```
Step 1: Image Encoding (ViT-B/32)
  Input image: 224×224×3 (photo of a golden retriever)

  Patch embedding: 224/32 = 7×7 = 49 patches + 1 CLS token
  ViT encoder: 12 transformer blocks, embed_dim=512

  Output: 512-dimensional image embedding
  z_img = [0.023, -0.041, 0.018, ..., 0.055]  (L2 normalized)

Step 2: Text Encoding (Transformer)
  Create text prompts for each class:
    "a photo of a dog"
    "a photo of a cat"
    "a photo of a car"
    "a photo of a tree"

  Tokenize each prompt:
    "a photo of a dog" → [49406, 320, 1125, 539, 320, 1929, 49407, 0, 0, ...]
    (49406 = [SOS], 49407 = [EOS], 0 = padding)

  Text transformer: 12 blocks, embed_dim=512
  Take embedding at [EOS] position

  Output: 512-dimensional text embeddings
  z_dog = [0.031, -0.028, 0.022, ..., 0.048]
  z_cat = [0.025, -0.035, 0.019, ..., 0.051]
  z_car = [-0.012, 0.044, -0.033, ..., 0.029]
  z_tree = [0.008, 0.015, -0.027, ..., 0.038]

Step 3: Compute Similarities
  Cosine similarity (scaled by learned temperature τ=0.01):

  sim(img, dog) = (z_img · z_dog) / τ
                = 0.82 / 0.01 = 82.0

  sim(img, cat) = 0.71 / 0.01 = 71.0
  sim(img, car) = 0.15 / 0.01 = 15.0
  sim(img, tree) = 0.23 / 0.01 = 23.0

Step 4: Softmax to Get Probabilities
  logits = [82.0, 71.0, 15.0, 23.0]

  exp(logits) = [exp(82), exp(71), exp(15), exp(23)]
              ≈ [4.9×10³⁵, 7.5×10³⁰, 3.3×10⁶, 9.7×10⁹]

  P(dog) ≈ 4.9×10³⁵ / 4.9×10³⁵ ≈ 0.9999... ≈ 100%
  P(cat) ≈ 7.5×10³⁰ / 4.9×10³⁵ ≈ 0.00015 ≈ 0.015%

  Prediction: "dog" with near-certainty

Step 5: CLIP Training Objective
  During training with batch of N image-text pairs:

  Similarity matrix: N×N
         text_0  text_1  text_2  ...  text_N
  img_0  [0.95,  0.12,   0.08,  ...,  0.15]  ← should be high at (0,0)
  img_1  [0.10,  0.91,   0.14,  ...,  0.11]  ← should be high at (1,1)
  img_2  [0.07,  0.09,   0.88,  ...,  0.13]  ← should be high at (2,2)
  ...

  Loss = Image-to-Text CE + Text-to-Image CE
       = -Σᵢ log[exp(S[i,i]) / Σⱼ exp(S[i,j])]
       + -Σⱼ log[exp(S[j,j]) / Σᵢ exp(S[i,j])]

  This pushes diagonal elements high, off-diagonal low.
```

### 8.4 Multi-Modal Vision-Language Models

Integrating vision and language enables richer understanding and generation. **DALL-E** and **Stable Diffusion** generate images from text descriptions using diffusion models conditioned on CLIP embeddings. These models learn the relationship between textual concepts and visual appearance, enabling creative applications like concept combination ("a cat riding a bike in the style of Van Gogh").

**Flamingo** and **GPT-4V** extend large language models with vision, enabling them to answer questions about images, describe scenes, and reason about visual content. These models use cross-attention to integrate image features into language model representations.

Vision-language models are powerful for tasks requiring both modalities: visual question answering, image captioning, visual reasoning, and even robotics (where language instructions guide visual policies).

### 8.5 Diffusion Models for Vision

Diffusion models have revolutionized generative modeling. The idea is to gradually add noise to data until it's pure Gaussian noise, then learn to reverse this process. Mathematically, the forward process is:

```
q(x_t | x_{t-1}) = N(x_t; √(1-β_t) x_{t-1}, β_t I)
```

where `β_t` is a noise schedule. The reverse process is learned by a neural network:

```
p_θ(x_{t-1} | x_t) = N(x_{t-1}; μ_θ(x_t, t), Σ_θ(x_t, t))
```

Training minimizes the variational lower bound, which simplifies to predicting the noise added at each step:

```
L = E_t,x_0,ε [||ε - ε_θ(x_t, t)||²]
```

Diffusion models produce high-quality, diverse images and are controllable via conditioning (text, class labels, or spatial guidance). They're used for image generation, inpainting, super-resolution, and 3D generation.

**Numeric Example - Diffusion Model (DDPM/Stable Diffusion):**

Let's trace image generation from noise:

```
Goal: Generate a 64×64×3 image (simplified; Stable Diffusion uses 512×512)

Step 1: Forward Process (Training) - Adding Noise
  Start with clean image x₀: 64×64×3

  Noise schedule β_t for T=1000 timesteps:
    β₁ = 0.0001, β₂ = 0.0002, ..., β₁₀₀₀ = 0.02
    (linear schedule from 0.0001 to 0.02)

  Cumulative product: ᾱ_t = ∏(1 - β_s) for s=1 to t
    ᾱ₁ = 0.9999
    ᾱ₂₅₀ ≈ 0.75
    ᾱ₅₀₀ ≈ 0.25
    ᾱ₇₅₀ ≈ 0.05
    ᾱ₁₀₀₀ ≈ 0.0001

  Add noise to get x_t directly:
    x_t = √ᾱ_t × x₀ + √(1-ᾱ_t) × ε    where ε ~ N(0, I)

  Example at t=500 (ᾱ₅₀₀ = 0.25):
    x₅₀₀ = √0.25 × x₀ + √0.75 × ε
         = 0.5 × x₀ + 0.866 × ε

  At pixel (32, 32, 0):
    x₀[32,32,0] = 0.7 (original pixel value, normalized to [-1,1])
    ε[32,32,0] = 0.3 (sampled noise)
    x₅₀₀[32,32,0] = 0.5 × 0.7 + 0.866 × 0.3 = 0.35 + 0.26 = 0.61

  At t=1000: x₁₀₀₀ ≈ pure Gaussian noise

Step 2: Training the Denoiser (U-Net)
  Input: noisy image x_t, timestep t
  Output: predicted noise ε_θ(x_t, t)

  Network architecture (simplified):
    x_t: 64×64×3
    + timestep embedding: sinusoidal encoding of t → 512-dim
      t=500 → [sin(500/10000^(0/256)), cos(500/10000^(0/256)), ...]

    U-Net encoder:
      64×64×3 → 64×64×64 → 32×32×128 → 16×16×256 → 8×8×512

    U-Net decoder (with skip connections):
      8×8×512 → 16×16×256 → 32×32×128 → 64×64×64 → 64×64×3

    Output: predicted noise ε_θ, shape 64×64×3

  Loss:
    L = ||ε - ε_θ(x_t, t)||²

    If true noise ε[32,32,0] = 0.3 and predicted ε_θ[32,32,0] = 0.28:
      Loss contribution: (0.3 - 0.28)² = 0.0004

Step 3: Reverse Process (Sampling) - Removing Noise
  Start with pure noise x_T ~ N(0, I)

  For t = T, T-1, ..., 1:
    Predict noise: ε_θ(x_t, t)

    Compute x_{t-1}:
      x_{t-1} = (1/√(1-β_t)) × (x_t - β_t/√(1-ᾱ_t) × ε_θ) + σ_t × z

    where z ~ N(0, I) is fresh noise, σ_t = √β_t

  Example step from t=500 to t=499:
    β₅₀₀ = 0.01, ᾱ₅₀₀ = 0.25

    At pixel (32,32,0):
      x₅₀₀ = 0.61
      ε_θ = 0.28 (predicted noise)
      z = 0.1 (new random noise)

      x₄₉₉ = (1/√0.99) × (0.61 - 0.01/√0.75 × 0.28) + √0.01 × 0.1
           = 1.005 × (0.61 - 0.0115 × 0.28) + 0.01
           = 1.005 × (0.61 - 0.0032) + 0.01
           = 1.005 × 0.607 + 0.01
           = 0.610 + 0.01 = 0.62

  After 1000 steps: x₀ ≈ clean generated image

Step 4: Classifier-Free Guidance (for text conditioning)
  Text prompt: "a photo of a cat"

  Encode text with CLIP/T5: c = text_encoder("a photo of a cat")

  During sampling, compute two predictions:
    ε_uncond = ε_θ(x_t, t, ∅)         (unconditional)
    ε_cond = ε_θ(x_t, t, c)           (conditioned on text)

  Guided prediction:
    ε_guided = ε_uncond + w × (ε_cond - ε_uncond)

  where w is guidance scale (typically 7.5):
    w=1: Standard conditional generation
    w=7.5: Strongly follow the text prompt
    w=15: Very strong guidance (may reduce diversity)

  Example:
    ε_uncond[32,32,0] = 0.25
    ε_cond[32,32,0] = 0.30
    ε_guided = 0.25 + 7.5 × (0.30 - 0.25) = 0.25 + 0.375 = 0.625

  Higher guidance → images more aligned with text, less diverse
```

**Latent Diffusion (Stable Diffusion) Efficiency:**
```
Standard Diffusion:
  Work in pixel space: 512×512×3 = 786,432 dimensions
  U-Net processes full resolution → very expensive!

Latent Diffusion:

```

### 8.6 Efficient Models for Edge Deployment

Not all applications run in the cloud—autonomous vehicles, mobile apps, and IoT devices need efficient models. MobileNet, EfficientNet-Lite, and SqueezeNet use techniques like depthwise separable convolutions and channel pruning to reduce parameters and FLOPs.

**Quantization** reduces precision from 32-bit floats to 8-bit integers, speeding up inference with minimal accuracy loss. **Knowledge distillation** trains a small student model to mimic a large teacher model, transferring knowledge without transferring parameters.

**Neural Architecture Search (NAS)** automates model design for specific constraints (latency, memory, FLOPs). EfficientNet and MobileNetV3 were found via NAS and achieve state-of-the-art efficiency.

Edge deployment also involves optimizations like operator fusion, memory layout optimization, and hardware-specific kernels (e.g., TensorRT, Core ML). Understanding these tools is crucial for deploying models in production.

**Numeric Example - MobileNet Depthwise Separable Convolution:**

Let's compare standard vs depthwise separable convolution:

```
Task: 3×3 convolution, 64 input channels → 128 output channels

STANDARD CONVOLUTION:
  Kernel shape: 3×3×64×128
  Parameters: 3 × 3 × 64 × 128 = 73,728

  For 14×14 input feature map:
    Each output pixel: 3 × 3 × 64 = 576 multiplications
    Total output: 14 × 14 × 128 pixels
    FLOPs: 14 × 14 × 128 × 576 × 2 = 28.9 million

DEPTHWISE SEPARABLE CONVOLUTION:

  Step 1: Depthwise Convolution (spatial filtering per channel)
    Kernel shape: 3×3×64×1 (one 3×3 filter per input channel)
    Parameters: 3 × 3 × 64 = 576

    Each input channel processed independently:
      Channel 0: 14×14 input → 3×3 conv → 14×14 output
      Channel 1: 14×14 input → 3×3 conv → 14×14 output
      ...
      Channel 63: 14×14 input → 3×3 conv → 14×14 output

    Output: 14×14×64
    FLOPs: 14 × 14 × 64 × 9 × 2 = 226,000

  Step 2: Pointwise Convolution (channel mixing)
    Kernel shape: 1×1×64×128
    Parameters: 1 × 1 × 64 × 128 = 8,192

    Each output pixel: 64 multiplications
    FLOPs: 14 × 14 × 128 × 64 × 2 = 3.2 million

  Total Depthwise Separable:
    Parameters: 576 + 8,192 = 8,768 (8.4× fewer!)
    FLOPs: 226K + 3.2M = 3.4M (8.5× fewer!)

EFFICIENCY GAIN:
  Standard:     73,728 params, 28.9M FLOPs
  Depthwise Sep: 8,768 params,  3.4M FLOPs
  Ratio: ~1/9 the compute for similar accuracy!
```

**Numeric Example - Quantization (INT8):**

```
Original model: FP32 (32-bit floating point)
  Weight value: 0.0234375
  Storage: 32 bits
  Memory for 1M weights: 4 MB

Quantized model: INT8 (8-bit integer)
  Step 1: Determine quantization range
    Observe weight distribution during calibration
    Min weight: -0.5, Max weight: +0.5
    Scale: (0.5 - (-0.5)) / 255 = 0.00392
    Zero point: 128

  Step 2: Quantize weights
    q = round((w - min) / scale) = round((w + 0.5) / 0.00392)

    Example weight w = 0.0234375:
      q = round((0.0234375 + 0.5) / 0.00392)
        = round(133.5)
        = 134 (stored as uint8)

  Step 3: Quantize activations (during inference)
    Same process for each layer's outputs
    Calibration determines per-layer scales

  Memory savings:
    32-bit: 1M weights × 4 bytes = 4 MB
    8-bit:  1M weights × 1 byte  = 1 MB
    Savings: 4× smaller model!

  Speed improvement:
    INT8 multiply-accumulate: 1 cycle on many CPUs
    FP32 multiply-accumulate: 4+ cycles
    Typical speedup: 2-4× faster inference

  Accuracy impact:
    ResNet-50 FP32: 76.1% top-1 accuracy
    ResNet-50 INT8: 75.8% top-1 accuracy
    Loss: only 0.3%!
```

**Numeric Example - Knowledge Distillation:**

```
Teacher: ResNet-152 (60M params, 11.5 GFLOPs)
Student: MobileNetV2 (3.4M params, 0.3 GFLOPs)

Step 1: Teacher produces soft labels
  Input image (cat):
    Teacher logits: [2.1, 8.5, -1.2, 0.8, -0.3, ...]
    (100 classes, "cat" at index 1 has highest logit)

  Soft labels with temperature T=4:
    softmax(logits / T) = softmax([0.525, 2.125, -0.3, 0.2, ...])
    = [0.05, 0.72, 0.01, 0.04, 0.02, ...]

  Compare to hard label: [0, 1, 0, 0, 0, ...]
  Soft labels contain more information!
  (e.g., cat is 72% likely, but 5% similar to class 0)

Step 2: Student learns from soft labels
  Student prediction: [0.08, 0.65, 0.02, 0.06, 0.03, ...]

  Distillation loss (KL divergence):
    L_distill = T² × KL(teacher_soft || student_soft)
              = 16 × Σ p_teacher × log(p_teacher / p_student)
              = 16 × [0.72 × log(0.72/0.65) + 0.05 × log(0.05/0.08) + ...]
              = 16 × [0.072 + (-0.023) + ...]
              ≈ 0.8

  Hard label loss:
    L_hard = CrossEntropy([0,1,0,...], student_output)
           = -log(0.65) = 0.43

  Total loss:
    L = α × L_distill + (1-α) × L_hard
      = 0.7 × 0.8 + 0.3 × 0.43
      = 0.56 + 0.13 = 0.69

Step 3: Results
  MobileNetV2 trained normally:     71.8% top-1
  MobileNetV2 + distillation:       73.2% top-1
  Improvement: +1.4% (free accuracy!)

  Student is 18× smaller, 38× faster than teacher
  But captures ~96% of teacher's accuracy
```

## 9. Real-World System Design: Thinking Like a Staff Scientist

Building a computer vision system that works in production requires more than training a good model. You must consider the entire pipeline from data to deployment and maintenance.

### 9.1 Model Selection Trade-offs

Choosing a model involves balancing accuracy, latency, memory, and training cost. A ResNet-152 might achieve 2% better accuracy than a ResNet-50, but it's 3× slower. Is the accuracy gain worth it for your application?

Ask yourself: What's the acceptable latency? If you're building a real-time video analysis system, you need 30+ FPS, meaning <33ms per frame. This rules out large models unless you batch process or use powerful GPUs. For an offline image processing pipeline, latency matters less than throughput.

What's the acceptable accuracy? In medical imaging, even 1% improvement can save lives, justifying large models and ensemble methods. For a content moderation system, you might prioritize recall (catch all violations) at the cost of precision (some false positives), which affects model threshold choices.

What hardware will you deploy on? Edge devices have limited memory and compute. A model that fits on a server might need to be compressed or redesigned for a mobile device.

### 9.2 Data Quality and Diversity

Models are only as good as the data they're trained on. Garbage in, garbage out applies doubly to deep learning.

**Data collection**: Ensure your training data represents the deployment distribution. If your model will analyze images from smartphones, train on smartphone images, not high-quality DSLR photos. Consider edge cases—nighttime images, occluded objects, unusual lighting.

**Labeling quality**: Inconsistent labels hurt performance. Use multiple annotators and measure inter-annotator agreement (e.g., Cohen's kappa). For ambiguous cases, provide clear guidelines. Invest in quality control—review a sample of labels regularly.

**Dataset bias**: Datasets can encode societal biases (e.g., gender stereotypes, racial biases). A face detector trained mostly on lighter-skinned faces performs worse on darker-skinned faces. Audit your data for representation and balance.

**Data versioning**: Track which data version was used to train each model. As you collect more data or fix labeling errors, retrain and compare versions. Tools like DVC (Data Version Control) help with this.

### 9.3 Monitoring and Maintenance

Models degrade over time as the world changes. This is called **data drift** or **concept drift**. Your face recognition model trained in 2020 might fail when people start wearing masks in 2021.

**Monitoring**: Track key metrics in production—accuracy, latency, error rate. Set up alerts for anomalies. Monitor input distributions—if the mean pixel intensity suddenly shifts, investigate why.

**Feedback loops**: Collect predictions and outcomes. For a recommendation system, track which recommendations were clicked. Use this data to retrain periodically.

**A/B testing**: When deploying a new model, don't replace the old one immediately. Run both in parallel, route a fraction of traffic to the new model, and compare metrics. Gradually increase traffic if the new model performs better.

**Continuous learning**: Retrain models periodically on new data. Decide on a retraining schedule based on how quickly your domain changes. For news classification, retrain weekly. For general object detection, monthly or quarterly might suffice.

### 9.4 Debugging and Error Analysis

When your model underperforms, systematic debugging is essential.

**Visualize predictions**: For object detection, plot bounding boxes on test images. For segmentation, overlay predicted masks on images. This reveals failure modes—are all cars missed, or only small ones?

**Confusion analysis**: For classification, examine the confusion matrix. Which classes are confused? This suggests which features the model lacks.

**Error stratification**: Stratify errors by metadata (image resolution, object size, lighting condition). You might find the model fails on small objects, indicating you need more training data or better augmentation for that category.

**Ablation studies**: Remove components (dropout, augmentation, pretrained weights) and measure impact. This identifies which components contribute to performance.

**Human-in-the-loop**: For critical applications, have humans review uncertain predictions. A model that flags 10% of cases for human review can achieve better overall performance than a fully automated system.

### 9.5 Ethical Considerations

Computer vision systems have real-world impact. A biased hiring algorithm or a faulty medical diagnosis tool causes harm.

**Fairness**: Ensure your model performs equitably across demographic groups. Measure performance stratified by gender, race, age. If disparities exist, collect more balanced data or apply fairness constraints during training.

**Privacy**: Face recognition raises privacy concerns. Obtain informed consent before collecting facial data. Anonymize data when possible. Comply with regulations like GDPR.

**Transparency**: In high-stakes applications (hiring, lending, healthcare), explain model decisions. Use interpretability techniques like GradCAM or attention visualization to provide insights.

**Dual use**: Consider how your technology might be misused. A deepfake detector can be used for content moderation but also to improve deepfake generation. Think about safeguards and responsible disclosure.
