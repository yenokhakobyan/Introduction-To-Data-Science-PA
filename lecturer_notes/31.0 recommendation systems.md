## 1. Introduction to Recommendation Systems

### What Problem Are We Solving?

Imagine you are Netflix with fifteen thousand movies and TV shows, and two hundred million subscribers. Each user can only watch a tiny fraction of your catalog. How do you help each person find content they will love? This is the recommendation problem at its core.

We are trying to learn a function that predicts how much a specific user will like a specific item. We can express this mathematically as:

$$f(u, i) \rightarrow \hat{r}_{ui}$$

Where $u$ is a user, $i$ is an item, and $\hat{r}_{ui}$ is our predicted rating or relevance score. This predicted value might represent a star rating from one to five, a probability that the user will click on the item, or simply a score we can use to rank items in order of relevance.

### Types of User Feedback

Understanding your data type is absolutely crucial because it fundamentally determines which algorithms you should use and how you should train them.

**Explicit Feedback** occurs when users directly tell you their preferences. Think of Amazon's five-star rating system or YouTube's thumbs up and thumbs down buttons. The advantage of explicit feedback is its clarity. When a user gives five stars to a product, you know unambiguously that they loved it. When they give one star, they clearly disliked it. However, explicit feedback comes with a severe disadvantage: sparsity. In most real-world systems, less than one percent of all possible user-item pairs have ratings. Users simply do not bother to rate most things they interact with. This extreme sparsity makes building accurate models challenging because you have so little training data relative to the size of your problem space.

**Implicit Feedback** is inferred from user behavior rather than explicit statements of preference. Every click, purchase, video watch, scroll event, and dwell time generates implicit feedback. This data is abundant because you collect it passively for every single user interaction without requiring any extra effort from users. However, implicit feedback is fundamentally asymmetric in nature. You can observe positive signals very clearly. For example, when a user watches an entire video from start to finish, that is a strong positive signal. But the absence of interaction is deeply ambiguous. If a user has never clicked on a particular item, does that mean they actively dislike it, or have they simply never seen it? You cannot distinguish between these scenarios from the data alone. This asymmetry fundamentally changes how you train and evaluate models. With implicit feedback, you cannot treat missing data as negative examples the way you might with explicit feedback.

### The Three Paradigms

**Content-Based Filtering** operates on this principle: if you liked Item A, you will probably like items that are similar to Item A. The system uses item features such as genre, description, attributes, and metadata to find items whose feature vectors are similar to items you have enjoyed. The beauty of content-based filtering is that it does not require any information about other users. You can make personalized recommendations for a brand new user as soon as they interact with a single item. The weakness is that content-based systems struggle to discover surprising recommendations. They tend to recommend items that are very similar to what you already know you like, which can create a filter bubble.

**Collaborative Filtering** takes a fundamentally different approach based on collective wisdom. The core insight is beautifully simple: users who agreed in the past will tend to agree in the future. If Alice and Bob both loved the same fifteen movies, and Alice loved a sixteenth movie that Bob has not seen yet, there is a high probability that Bob will love it too. Collaborative filtering discovers these patterns in collective user behavior without needing to understand anything about the content of the items themselves. This allows it to surface surprising recommendations and capture subtle patterns that content features might miss. The weakness is that collaborative filtering requires substantial interaction data and struggles with new users and new items that lack interaction history.

**Hybrid Methods** combine both paradigms to get the best of both worlds. A well-designed hybrid system can use content features to handle cold start situations while leveraging collaborative patterns to make accurate predictions and discover surprising connections. In practice, most successful production systems use hybrid approaches that intelligently combine multiple sources of signal.

## 2. Content-Based Filtering

### The Core Idea

Content-based filtering formalizes a simple intuition. If you enjoyed The Dark Knight, you will probably enjoy other action movies, other films directed by Christopher Nolan, or other superhero movies. We represent items as feature vectors and find items whose vectors are similar to what you have already enjoyed. Let me show you exactly how this works with a complete numeric example.

### Building Item Feature Vectors: Step-by-Step

Let us build a movie recommender using genre features. We will use five binary features representing the genres Action, Comedy, Drama, Romance, and Sci-Fi. Each movie gets a binary vector where one indicates the movie belongs to that genre and zero indicates it does not.

**Our Movie Catalog:**

- **The Matrix**: This is an action-packed science fiction film, so its feature vector is `[1, 0, 0, 0, 1]`. The first position represents Action (yes), second position Comedy (no), third Drama (no), fourth Romance (no), and fifth Sci-Fi (yes).

- **Inception**: This film combines action, drama, and science fiction, giving us `[1, 0, 1, 0, 1]`.

- **The Hangover**: A pure comedy gets `[0, 1, 0, 0, 0]`.

- **Titanic**: A dramatic romance gives us `[0, 0, 1, 1, 0]`.

- **Interstellar**: This blends drama and science fiction for `[0, 0, 1, 0, 1]`.

Now we have mathematical representations of our movies as vectors in a five-dimensional feature space.

### Building a User Profile: Complete Mathematical Derivation

A user profile aggregates the features of items they have interacted with, weighted by their ratings. Let me show you the complete calculation for Alice, who has rated three movies.

**Alice's Rating History:**
- The Matrix: 5 stars
- Inception: 4 stars  
- The Hangover: 2 stars

**Step 1: Weight Each Movie by Its Rating**

We multiply each movie's feature vector by Alice's rating for that movie. This gives more influence to highly-rated items.

For The Matrix with rating 5:
$$5 \times [1, 0, 0, 0, 1] = [5, 0, 0, 0, 5]$$

For Inception with rating 4:
$$4 \times [1, 0, 1, 0, 1] = [4, 0, 4, 0, 4]$$

For The Hangover with rating 2:
$$2 \times [0, 1, 0, 0, 0] = [0, 2, 0, 0, 0]$$

**Step 2: Sum the Weighted Vectors**

We add all three weighted vectors element by element:

$$[5, 0, 0, 0, 5] + [4, 0, 4, 0, 4] + [0, 2, 0, 0, 0] = [9, 2, 4, 0, 9]$$

**Step 3: Normalize by Total Weight**

We divide by the sum of all ratings to get an average preference profile:

$$\text{Sum of ratings} = 5 + 4 + 2 = 11$$

$$\text{Alice's Profile} = \frac{1}{11}[9, 2, 4, 0, 9] = [0.818, 0.182, 0.364, 0.000, 0.818]$$

**Interpreting Alice's Profile:**

Alice's profile tells us she strongly prefers Action (0.818) and Sci-Fi (0.818), has moderate interest in Drama (0.364), minimal tolerance for Comedy (0.182), and has shown zero interest in Romance (0.000). This weighted profile captures her taste preferences in a mathematically precise way.

### Cosine Similarity: The Mathematical Foundation

To find items similar to Alice's preferences, we need a way to measure how close two vectors are. The most common choice is cosine similarity, which measures the cosine of the angle between two vectors. The formula is:

$$\text{similarity}(\vec{A}, \vec{B}) = \frac{\vec{A} \cdot \vec{B}}{||\vec{A}|| \times ||\vec{B}||}$$

Let me break down each component:

**The Dot Product** ($\vec{A} \cdot \vec{B}$) measures how much two vectors point in the same direction. For vectors $\vec{A} = [a_1, a_2, ..., a_n]$ and $\vec{B} = [b_1, b_2, ..., b_n]$, the dot product is:

$$\vec{A} \cdot \vec{B} = a_1 \times b_1 + a_2 \times b_2 + ... + a_n \times b_n$$

**The Magnitude** (or L2 norm) $||\vec{A}||$ measures the length of vector $\vec{A}$:

$$||\vec{A}|| = \sqrt{a_1^2 + a_2^2 + ... + a_n^2}$$

Dividing the dot product by the product of the magnitudes normalizes the similarity to range from negative one (opposite directions) to positive one (same direction), with zero meaning orthogonal or unrelated.

### Complete Numeric Example: Computing Similarity

Let us compute how well Interstellar matches Alice's preferences. Recall that Alice's profile is `[0.818, 0.182, 0.364, 0.000, 0.818]` and Interstellar's feature vector is `[0, 0, 1, 0, 1]`.

**Step 1: Compute the Dot Product**

$$\vec{A} \cdot \vec{I} = (0.818 \times 0) + (0.182 \times 0) + (0.364 \times 1) + (0.000 \times 0) + (0.818 \times 1)$$

$$= 0 + 0 + 0.364 + 0 + 0.818 = 1.182$$

**Step 2: Compute Alice's Profile Magnitude**

$$||\vec{A}|| = \sqrt{0.818^2 + 0.182^2 + 0.364^2 + 0.000^2 + 0.818^2}$$

$$= \sqrt{0.669 + 0.033 + 0.133 + 0.000 + 0.669}$$

$$= \sqrt{1.504} = 1.226$$

**Step 3: Compute Interstellar's Magnitude**

$$||\vec{I}|| = \sqrt{0^2 + 0^2 + 1^2 + 0^2 + 1^2} = \sqrt{2} = 1.414$$

**Step 4: Compute Cosine Similarity**

$$\text{similarity} = \frac{1.182}{1.226 \times 1.414} = \frac{1.182}{1.734} = 0.682$$

A similarity of 0.682 is reasonably high, suggesting Interstellar is a good match for Alice. Let us compare this to Titanic, which has feature vector `[0, 0, 1, 1, 0]`.

**For Titanic:**

$$\text{Dot Product} = (0.818 \times 0) + (0.182 \times 0) + (0.364 \times 1) + (0.000 \times 1) + (0.818 \times 0) = 0.364$$

$$||\text{Titanic}|| = \sqrt{0^2 + 0^2 + 1^2 + 1^2 + 0^2} = \sqrt{2} = 1.414$$

$$\text{similarity} = \frac{0.364}{1.226 \times 1.414} = \frac{0.364}{1.734} = 0.210$$

**Result**: Interstellar (similarity 0.682) is a much better match than Titanic (similarity 0.210). This makes intuitive sense because Interstellar has both Drama and Sci-Fi, which align with Alice's preferences, while Titanic has Romance which Alice has shown no interest in.

### Complete Implementation

```python
import numpy as np
from typing import Dict, List, Tuple

class ContentBasedRecommender:
    """
    Content-based recommendation system using item features.
    
    This implementation uses cosine similarity between user profiles
    and item features to make recommendations.
    """
    
    def __init__(self, feature_names: List[str]):
        """
        Initialize the recommender with feature names.
        
        Args:
            feature_names: List of feature names (e.g., genres)
        """
        self.feature_names = feature_names
        self.n_features = len(feature_names)
        self.items = {}  # Maps item_id to its feature vector
        self.item_names = {}  # Maps item_id to its readable name
        
    def add_item(self, item_id: str, name: str, features: np.ndarray):
        """
        Add an item with its feature vector to our catalog.
        
        Args:
            item_id: Unique identifier for the item
            name: Human-readable name for the item
            features: Feature vector (must match n_features length)
        """
        assert len(features) == self.n_features, \
            f"Feature vector must have exactly {self.n_features} dimensions"
        self.items[item_id] = features
        self.item_names[item_id] = name
    
    def build_user_profile(self, user_ratings: Dict[str, float]) -> np.ndarray:
        """
        Build a user profile from their ratings.
        
        The profile is a weighted average of rated items' features,
        where the weights are the ratings themselves. This gives us
        a vector that represents what features the user prefers.
        
        Mathematical formula:
        profile = (Σ rating_i × features_i) / (Σ rating_i)
        
        Args:
            user_ratings: Dictionary mapping item_id to rating value
            
        Returns:
            User profile vector (normalized by total weight)
        """
        profile = np.zeros(self.n_features)
        total_weight = 0
        
        for item_id, rating in user_ratings.items():
            if item_id in self.items:
                # Weight each item's features by its rating
                # Higher ratings contribute more to the profile
                profile += rating * self.items[item_id]
                total_weight += rating
        
        # Normalize by total weight to get average preferences
        if total_weight > 0:
            profile /= total_weight
            
        return profile
    
    def cosine_similarity(self, vec1: np.ndarray, vec2: np.ndarray) -> float:
        """
        Compute cosine similarity between two vectors.
        
        Formula: cos(θ) = (A·B) / (||A|| × ||B||)
        
        The result ranges from -1 (opposite) to 1 (identical),
        with 0 meaning orthogonal (no similarity).
        
        Args:
            vec1: First vector
            vec2: Second vector
            
        Returns:
            Cosine similarity value
        """
        # Compute dot product
        dot_product = np.dot(vec1, vec2)
        
        # Compute magnitudes (L2 norms)
        norm1 = np.linalg.norm(vec1)
        norm2 = np.linalg.norm(vec2)
        
        # Avoid division by zero
        if norm1 == 0 or norm2 == 0:
            return 0.0
            
        return dot_product / (norm1 * norm2)
    
    def recommend(self, user_profile: np.ndarray, n_recommendations: int = 5,
                 exclude_items: List[str] = None) -> List[Tuple[str, float]]:
        """
        Generate recommendations based on user profile.
        
        We compute the cosine similarity between the user's profile
        and each item's features. Items with higher similarity scores
        match the user's preferences better.
        
        Args:
            user_profile: User's feature preference vector
            n_recommendations: Number of items to recommend
            exclude_items: Items to exclude (e.g., already rated)
            
        Returns:
            List of tuples containing (item_id, similarity_score)
        """
        if exclude_items is None:
            exclude_items = []
            
        similarities = []
        
        for item_id, item_features in self.items.items():
            if item_id not in exclude_items:
                # Compute cosine similarity between profile and item
                sim = self.cosine_similarity(user_profile, item_features)
                similarities.append((item_id, sim))
        
        # Sort by similarity in descending order and return top N
        similarities.sort(key=lambda x: x[1], reverse=True)
        return similarities[:n_recommendations]


# Demonstration: Complete worked example
def demo_content_based():

        genres = [feature_names[i] for i, v in enumerate(movie_vec) if v == 1]
```

### Understanding TF-IDF for Text Features

When items have text descriptions instead of categorical features, we use Term Frequency-Inverse Document Frequency to create feature vectors automatically from the text. Let me explain each component mathematically.

**Term Frequency (TF)** measures how often a word appears in a document relative to the document's length:

$$\text{TF}(word, document) = \frac{\text{count}(word \text{ in } document)}{\text{total words in } document}$$

**Inverse Document Frequency (IDF)** measures how distinctive a word is across all documents:

$$\text{IDF}(word) = \log\left(\frac{\text{total documents}}{\text{documents containing } word}\right)$$

The logarithm dampens the effect so common words do not get penalized too heavily. Words that appear in every document get IDF close to zero, while rare distinctive words get high IDF values.

**TF-IDF** combines both measures by multiplication:

$$\text{TF-IDF}(word, document) = \text{TF}(word, document) \times \text{IDF}(word)$$

### Numeric Example: TF-IDF Calculation

Suppose we have one thousand product descriptions in our catalog, and we are analyzing this description for a laptop:

"This lightweight laptop has excellent battery life"

Let us compute TF-IDF for two words: "lightweight" and "this".

**For "lightweight":**

This word appears once in our 7-word description:
$$\text{TF} = \frac{1}{7} = 0.143$$

Suppose "lightweight" appears in fifty out of one thousand products:
$$\text{IDF} = \log\left(\frac{1000}{50}\right) = \log(20) = 2.996$$

Therefore:
$$\text{TF-IDF} = 0.143 \times 2.996 = 0.428$$

**For "this":**

This word also appears once in our description:
$$\text{TF} = \frac{1}{7} = 0.143$$

But "this" is very common, appearing in nine hundred fifty products:
$$\text{IDF} = \log\left(\frac{1000}{950}\right) = \log(1.053) = 0.051$$

Therefore:
$$\text{TF-IDF} = 0.143 \times 0.051 = 0.007$$

**Result**: The word "lightweight" gets a TF-IDF score of 0.428, while "this" gets only 0.007. TF-IDF automatically emphasizes distinctive words like "lightweight" that carry meaningful information, while downweighting common words like "this" that appear everywhere and carry little discriminative power. This happens automatically from the data without us having to manually specify which words are important.

## 3. Collaborative Filtering Fundamentals

### The Central Insight

Collaborative filtering is built on a powerful observation about human behavior: people who agreed in the past tend to agree in the future. This is not just a heuristic, but a deep pattern that emerges from the structure of human preferences. If Alice and Bob both gave five stars to the same fifteen movies, and Alice loved a sixteenth movie that Bob has not seen yet, there is a high probability that Bob will love it too. We do not need to understand anything about the movies themselves. The pattern of agreement is sufficient.

### The User-Item Rating Matrix

We represent all user-item interactions as a matrix $\mathbf{R}$ where rows correspond to users, columns correspond to items, and entries $r_{ui}$ are ratings. Most entries are missing because users only rate a tiny fraction of items. Here is a small example:

$$\mathbf{R} = \begin{bmatrix}
5 & 3 & ? & 1 & ? \\
4 & ? & ? & 1 & ? \\
? & 1 & 2 & ? & 4 \\
? & ? & 4 & ? & 5
\end{bmatrix}$$

This matrix has four users (rows) and five items (columns). Alice (first row) rated Item 1 as five stars, Item 2 as three stars, Item 4 as one star, but has not rated Items 3 and 5 (shown as question marks). Our goal is to predict these missing ratings.

### User-Based Collaborative Filtering: Complete Mathematical Derivation

The idea behind user-based collaborative filtering is beautifully intuitive. To predict Alice's rating for Item 3, we find users similar to Alice who have rated Item 3, then aggregate their ratings weighted by similarity.

**Step 1: Measuring User Similarity with Pearson Correlation**

Pearson correlation measures how two users' ratings vary together relative to their individual means. The formula is:

$$\text{sim}(u, v) = \frac{\sum_{i \in I_{uv}} (r_{ui} - \bar{r}_u)(r_{vi} - \bar{r}_v)}{\sqrt{\sum_{i \in I_{uv}} (r_{ui} - \bar{r}_u)^2} \times \sqrt{\sum_{i \in I_{uv}} (r_{vi} - \bar{r}_v)^2}}$$

Where:
- $I_{uv}$ is the set of items both users have rated
- $r_{ui}$ is user $u$'s rating for item $i$
- $\bar{r}_u$ is user $u$'s mean rating across all items they rated
- The numerator measures covariance (how ratings vary together)
- The denominator normalizes by the standard deviations

Let me show you why we subtract the mean. Users have different rating scales. Alice might be generous and rate most movies four or five stars, while Bob might be critical and rate most movies two or three stars. By subtracting each user's mean, we center their ratings around zero, which lets us compare their relative preferences rather than their absolute rating scales.

### Complete Numeric Example: Alice vs Bob Similarity

Let us compute the similarity between Alice and Bob from our rating matrix above. Both users have rated Item 1 and Item 4, so these are the items we will use for comparison.

**Their Ratings:**
- Item 1: Alice gave 5 stars, Bob gave 4 stars
- Item 4: Alice gave 1 star, Bob gave 1 star

**Step 1: Compute Mean Ratings**

Alice's mean (averaging over Items 1, 2, 4):
$$\bar{r}_{Alice} = \frac{5 + 3 + 1}{3} = \frac{9}{3} = 3.0$$

Bob's mean (averaging over Items 1, 4):
$$\bar{r}_{Bob} = \frac{4 + 1}{2} = \frac{5}{2} = 2.5$$

**Step 2: Center the Ratings**

Subtract each user's mean from their ratings:

Alice's centered ratings: 
- Item 1: $5 - 3.0 = 2.0$
- Item 4: $1 - 3.0 = -2.0$

Bob's centered ratings:
- Item 1: $4 - 2.5 = 1.5$
- Item 4: $1 - 2.5 = -1.5$

**Step 3: Compute the Numerator (Covariance)**

$$\text{Numerator} = (2.0 \times 1.5) + ((-2.0) \times (-1.5))$$
$$= 3.0 + 3.0 = 6.0$$

Notice both products are positive. This happens because when Alice rates above her mean (Item 1), Bob also rates above his mean. When Alice rates below her mean (Item 4), Bob also rates below his mean. They vary together, indicating positive correlation.

**Step 4: Compute the Denominator**

For Alice:
$$\sqrt{2.0^2 + (-2.0)^2} = \sqrt{4.0 + 4.0} = \sqrt{8.0} = 2.828$$

For Bob:
$$\sqrt{1.5^2 + (-1.5)^2} = \sqrt{2.25 + 2.25} = \sqrt{4.5} = 2.121$$

Combined:
$$\text{Denominator} = 2.828 \times 2.121 = 6.0$$

**Step 5: Final Similarity**

$$\text{sim}(Alice, Bob) = \frac{6.0}{6.0} = 1.0$$

Perfect correlation! Alice and Bob have identical relative preferences. When Alice rates something high relative to her average, Bob rates it high relative to his average. When Alice rates something low, Bob rates it low. This strong agreement means Bob's ratings will be highly informative for predicting Alice's missing ratings.

### Predicting Missing Ratings: The Mathematical Formula

Once we have similarities, we predict missing ratings using this formula:

$$\hat{r}_{ui} = \bar{r}_u + \frac{\sum_{v \in N(u)} \text{sim}(u,v) \times (r_{vi} - \bar{r}_v)}{\sum_{v \in N(u)} |\text{sim}(u,v)|}$$

Where:
- $\hat{r}_{ui}$ is our predicted rating for user $u$ on item $i$
- $\bar{r}_u$ is user $u$'s mean rating (baseline)
- $N(u)$ is the set of neighbors (users similar to $u$ who rated item $i$)
- We weight each neighbor's centered rating by the similarity
- We normalize by the sum of absolute similarities

The intuition is: start with the user's baseline (their mean), then adjust up or down based on whether similar users rated this item above or below their own baselines.

### Complete Numeric Example: Predicting Alice's Rating for Item 3

Let us predict Alice's rating for Item 3. Looking at our matrix, Carol and David have both rated Item 3. We need to compute Alice's similarity with each of them, then combine their ratings.

**Computing Alice-Carol Similarity:**

Items both rated: Only Item 2
- Alice: 3 stars (mean: 3.0, centered: 0.0)
- Carol: 1 star (mean: $(1+2+4)/3 = 2.33$, centered: $1-2.33 = -1.33$)

With only one common item, correlation is not well-defined, but we can compute:
$$\text{sim}(Alice, Carol) = \frac{0.0 \times (-1.33)}{1 \times 1.33} = 0.0$$

In practice with more items, let us assume we computed $\text{sim}(Alice, Carol) = 0.3$

**Computing Alice-David Similarity:**

Let us assume we computed $\text{sim}(Alice, David) = 0.7$ based on other common items not shown.

**Now We Can Predict:**

Carol rated Item 3 as 2 stars (mean: 2.33):
$$\text{Carol's contribution} = 0.3 \times (2 - 2.33) = 0.3 \times (-0.33) = -0.099$$

David rated Item 3 as 4 stars (mean: $(4+5)/2 = 4.5$):
$$\text{David's contribution} = 0.7 \times (4 - 4.5) = 0.7 \times (-0.5) = -0.35$$

Sum of absolute similarities:
$$|0.3| + |0.7| = 1.0$$

**Final Prediction:**

$$\hat{r}_{Alice, Item3} = 3.0 + \frac{-0.099 + (-0.35)}{1.0} = 3.0 + \frac{-0.449}{1.0} = 2.55$$

**Interpretation**: Alice's baseline is 3.0 stars. Both similar users rated Item 3 below their own baselines (Carol rated it 0.33 below hers, David 0.5 below his). This negative signal, weighted by similarities, pulls Alice's prediction down to 2.55 stars. The system predicts Alice would rate Item 3 slightly below her average, suggesting she would not love it but might find it acceptable.

```python
import numpy as np
from scipy.stats import pearsonr
from typing import Dict, List, Tuple

class UserBasedCollaborativeFiltering:
    """
    User-based Collaborative Filtering using Pearson correlation.
    
    This implementation finds similar users and aggregates their
    ratings to predict missing values.
    """
    
    def __init__(self):
        self.ratings = {}  # user_id -> {item_id: rating}
        self.user_means = {}  # user_id -> mean_rating
        
    def add_rating(self, user_id: str, item_id: str, rating: float):
        """Add a single rating to the system."""
        if user_id not in self.ratings:
            self.ratings[user_id] = {}
        self.ratings[user_id][item_id] = rating
        
    def add_ratings_bulk(self, ratings_dict: Dict[str, Dict[str, float]]):
        """
        Add multiple ratings at once.
        
        Args:
            ratings_dict: Nested dict mapping user_id -> item_id -> rating
        """
        for user_id, user_ratings in ratings_dict.items():
            for item_id, rating in user_ratings.items():
                self.add_rating(user_id, item_id, rating)
        
        # Precompute user means for efficiency
        self._compute_user_means()
    
    def _compute_user_means(self):
        """
        Compute mean rating for each user.
        
        This is used to center ratings in Pearson correlation
        and as the baseline for predictions.
        """
        for user_id, user_ratings in self.ratings.items():
            self.user_means[user_id] = np.mean(list(user_ratings.values()))
    
    def pearson_similarity(self, user1: str, user2: str) -> float:
        """
        Compute Pearson correlation between two users.
        
        Mathematical formula:
        r = Σ[(r_u1,i - r̄_u1)(r_u2,i - r̄_u2)] / 
            √[Σ(r_u1,i - r̄_u1)² × Σ(r_u2,i - r̄_u2)²]
        
        This measures how the users' ratings co-vary after
        centering around each user's mean. Values range from
        -1 (opposite preferences) to +1 (identical preferences).
        
        Args:
            user1: First user ID
            user2: Second user ID
            
        Returns:
            Pearson correlation coefficient
        """
        # Find items both users have rated
        items1 = set(self.ratings[user1].keys())
        items2 = set(self.ratings[user2].keys())
        common_items = items1.intersection(items2)
        
        # Need at least 2 common items for correlation
        if len(common_items) < 2:
            return 0.0
        
        # Get ratings for common items
        ratings1 = [self.ratings[user1][item] for item in common_items]
        ratings2 = [self.ratings[user2][item] for item in common_items]
        
        # Compute Pearson correlation using scipy
        correlation, _ = pearsonr(ratings1, ratings2)
        
        # Handle NaN case (can occur with zero variance)
        return correlation if not np.isnan(correlation) else 0.0
    
    def predict_rating(self, user_id: str, item_id: str, 
                      k_neighbors: int = 5) -> float:
        """
        Predict a user's rating for an item using similar users.
        
        Mathematical formula:
        r̂(u,i) = r̄_u + [Σ_v sim(u,v) × (r_v,i - r̄_v)] / [Σ_v |sim(u,v)|]
        
        Where v ranges over the k most similar users who rated item i.
        
        Args:
            user_id: User to predict for
            item_id: Item to predict rating for
            k_neighbors: Number of similar users to consider
            
        Returns:
            Predicted rating
        """
        if user_id not in self.ratings:
            # Cold start: return global mean
            return self._global_mean()
        
        # Find users who have rated this item
        users_who_rated = [
            other_user for other_user in self.ratings.keys()
            if item_id in self.ratings[other_user] and other_user != user_id
        ]
        
        if not users_who_rated:
            # No one else rated this item, return user's mean
            return self.user_means[user_id]
        
        # Compute similarities with all users who rated the item
        similarities = [
            (other_user, self.pearson_similarity(user_id, other_user))
            for other_user in users_who_rated
        ]
        
        # Sort by similarity magnitude and take top k
        similarities.sort(key=lambda x: abs(x[1]), reverse=True)
        top_neighbors = similarities[:k_neighbors]
        
        # If no neighbors have positive similarity, return user mean
        if not top_neighbors or all(sim == 0 for _, sim in top_neighbors):
            return self.user_means[user_id]
        
        # Compute weighted average of deviations from neighbors' means
        numerator = 0.0
        denominator = 0.0
        
        for neighbor_id, similarity in top_neighbors:
            if similarity != 0:  # Only include neighbors with non-zero similarity
                neighbor_rating = self.ratings[neighbor_id][item_id]
                neighbor_mean = self.user_means[neighbor_id]
                
                # Weighted deviation from neighbor's mean
                numerator += similarity * (neighbor_rating - neighbor_mean)
                denominator += abs(similarity)
        
        if denominator == 0:
            return self.user_means[user_id]
        
        # User's baseline plus weighted deviation
        prediction = self.user_means[user_id] + (numerator / denominator)
        
        # Clip to valid range (assuming 1-5 stars)
        return np.clip(prediction, 1.0, 5.0)
    
    def _global_mean(self) -> float:
        """Compute global mean rating across all users."""
        all_ratings = []
        for user_ratings in self.ratings.values():
            all_ratings.extend(user_ratings.values())
        return np.mean(all_ratings) if all_ratings else 3.0
    
    def recommend(self, user_id: str, 
                 n_recommendations: int = 5) -> List[Tuple[str, float]]:
        """
        Generate top-N recommendations for a user.
        
        Returns items the user hasn't rated, ranked by predicted rating.
        
        Args:
            user_id: User to generate recommendations for
            n_recommendations: Number of items to recommend
            
        Returns:
            List of (item_id, predicted_rating) tuples
        """
        if user_id not in self.ratings:
            return []
        
        # Get all items in the system
        all_items = set()
        for user_ratings in self.ratings.values():
            all_items.update(user_ratings.keys())
        
        # Get items user hasn't rated
        rated_items = set(self.ratings[user_id].keys())
        unrated_items = all_items - rated_items
        
        # Predict ratings for unrated items
        predictions = [
            (item_id, self.predict_rating(user_id, item_id))
            for item_id in unrated_items
        ]
        
        # Sort by predicted rating (descending)
        predictions.sort(key=lambda x: x[1], reverse=True)
        
        return predictions[:n_recommendations]
```

## 4. Matrix Factorization Methods

### The Core Insight

Matrix factorization is one of the most elegant and powerful techniques in recommendation systems. The fundamental insight is beautifully simple yet profound: we can approximate a large sparse ratings matrix as the product of two smaller dense matrices.

Suppose we have a ratings matrix $\mathbf{R}$ with dimensions $m \times n$ (m users by n items). Most entries are missing because users only rate a tiny fraction of items. Matrix factorization says we can approximate this as:

$$\mathbf{R} \approx \mathbf{P} \times \mathbf{Q}^T$$

Where:
- $\mathbf{P}$ is $m \times k$ (users by latent factors)
- $\mathbf{Q}$ is $n \times k$ (items by latent factors)
- $k$ is much smaller than both $m$ and $n$ (typically 10-200)

Each row of $\mathbf{P}$ is a user's embedding, which captures their preferences across $k$ latent factors. Each row of $\mathbf{Q}$ is an item's embedding, which captures its characteristics across those same latent factors. The predicted rating for user $u$ on item $i$ is simply:

$$\hat{r}_{ui} = \mathbf{p}_u \cdot \mathbf{q}_i = \sum_{f=1}^{k} p_{uf} \times q_{if}$$

### What Are Latent Factors?

The algorithm discovers latent factors automatically from the data. These factors are not predefined categories but abstract dimensions learned to best explain the observed ratings. For movies, a latent factor might represent action intensity, whether the film is artistic versus mainstream, the amount of humor, or other patterns that emerge from viewing behavior. The beauty is that the model discovers these patterns without us having to manually specify what they represent.

Let me show you a concrete example. Suppose we learn two latent factors for movies, and we discover these patterns in the learned embeddings:

**Latent Factor 1** (high values for blockbusters, low for independent films):
- The Avengers: 0.9
- Transformers: 0.8
- Moonlight: -0.7
- The Florida Project: -0.8

**Latent Factor 2** (high values for serious dramas, low for comedies):
- The Shawshank Redemption: 0.9
- Schindler's List: 0.8
- Step Brothers: -0.8
- The Hangover: -0.9

These factors emerged from the data because they help explain rating patterns. Users who rate blockbusters highly tend to rate other blockbusters highly. Users who rate serious dramas highly tend to rate other serious dramas highly.

### Complete Numeric Example: Learning Process

Let me walk you through a complete example showing how matrix factorization learns embeddings from data. We will use a tiny ratings matrix so you can see every calculation.

**Given Ratings Matrix:**

$$\mathbf{R} = \begin{bmatrix}
5 & 3 & ? \\
4 & ? & 1 \\
? & 2 & 4
\end{bmatrix}$$

Three users, three items. We want to approximate this using $k=2$ latent factors.

**Step 1: Random Initialization**

We initialize user and item embeddings with small random values:

$$\mathbf{P} = \begin{bmatrix}
0.5 & 0.3 \\
0.4 & 0.6 \\
0.2 & 0.8
\end{bmatrix} \quad \mathbf{Q} = \begin{bmatrix}
0.8 & 0.2 \\
0.3 & 0.7 \\
0.1 & 0.9
\end{bmatrix}$$

Each row of $\mathbf{P}$ is a user's embedding (their latent preferences). Each row of $\mathbf{Q}$ is an item's embedding (its latent characteristics).

**Step 2: Making a Prediction**

Let us predict Alice's rating for Item 1. Alice is user 1 with embedding $\mathbf{p}_1 = [0.5, 0.3]$. Item 1 has embedding $\mathbf{q}_1 = [0.8, 0.2]$.

$$\hat{r}_{11} = \mathbf{p}_1 \cdot \mathbf{q}_1 = (0.5 \times 0.8) + (0.3 \times 0.2)$$
$$= 0.40 + 0.06 = 0.46$$

The actual rating is 5 stars. Our initial prediction of 0.46 is way off! The error is:

$$\text{error} = r_{11} - \hat{r}_{11} = 5 - 0.46 = 4.54$$

**Step 3: Learning with Gradient Descent**

We need to update the embeddings to reduce this error. The loss function we want to minimize is:

$$L = \sum_{(u,i) \in \text{observed}} (r_{ui} - \mathbf{p}_u \cdot \mathbf{q}_i)^2 + \lambda(||\mathbf{P}||^2 + ||\mathbf{Q}||^2)$$

The first term is the squared error on observed ratings. The second term is L2 regularization with strength $\lambda$, which prevents overfitting by penalizing large embedding values.

The gradient descent update rules are:

$$\mathbf{p}_u \leftarrow \mathbf{p}_u + \alpha \times (\text{error} \times \mathbf{q}_i - \lambda \times \mathbf{p}_u)$$
$$\mathbf{q}_i \leftarrow \mathbf{q}_i + \alpha \times (\text{error} \times \mathbf{p}_u - \lambda \times \mathbf{q}_i)$$

Where $\alpha$ is the learning rate (step size), typically around 0.01.

Let me show you the complete calculation with $\alpha = 0.01$ and $\lambda = 0.02$:

**Update Alice's Embedding (user 1):**

Error × item embedding:
$$\text{error} \times \mathbf{q}_1 = 4.54 \times [0.8, 0.2] = [3.632, 0.908]$$

Regularization term:
$$\lambda \times \mathbf{p}_1 = 0.02 \times [0.5, 0.3] = [0.01, 0.006]$$

Gradient:
$$\text{gradient} = [3.632, 0.908] - [0.01, 0.006] = [3.622, 0.902]$$

Update with learning rate:
$$\mathbf{p}_1^{\text{new}} = [0.5, 0.3] + 0.01 \times [3.622, 0.902]$$
$$= [0.5, 0.3] + [0.036, 0.009]$$
$$= [0.536, 0.309]$$

**Update Item 1's Embedding:**

Error × user embedding:
$$\text{error} \times \mathbf{p}_1 = 4.54 \times [0.5, 0.3] = [2.27, 1.362]$$

Regularization term:
$$\lambda \times \mathbf{q}_1 = 0.02 \times [0.8, 0.2] = [0.016, 0.004]$$

Gradient:
$$\text{gradient} = [2.27, 1.362] - [0.016, 0.004] = [2.254, 1.358]$$

Update with learning rate:
$$\mathbf{q}_1^{\text{new}} = [0.8, 0.2] + 0.01 \times [2.254, 1.358]$$
$$= [0.8, 0.2] + [0.023, 0.014]$$
$$= [0.823, 0.214]$$

**Verify Improvement:**

New prediction with updated embeddings:
$$\hat{r}_{11}^{\text{new}} = [0.536, 0.309] \cdot [0.823, 0.214]$$
$$= (0.536 \times 0.823) + (0.309 \times 0.214)$$
$$= 0.441 + 0.066 = 0.507$$

Our prediction improved from 0.46 to 0.507! Still far from 5, but we are moving in the right direction. After many iterations over all observed ratings, the embeddings will converge to values that accurately predict the data.

### Adding Biases: SVD++

Basic matrix factorization assumes all users and items are equally easy to predict. But in reality, some users rate everything highly (generous raters), some rate everything low (critical raters), and some items are universally loved or hated. We can model these systematic biases:

$$\hat{r}_{ui} = \mu + b_u + b_i + \mathbf{p}_u \cdot \mathbf{q}_i$$

Where:
- $\mu$ is the global mean rating across all observed ratings
- $b_u$ is user $u$'s bias (how much they deviate from the global mean)
- $b_i$ is item $i$'s bias (how much it deviates from the global mean)
- $\mathbf{p}_u \cdot \mathbf{q}_i$ is the interaction term capturing personalized preferences

**Numeric Example:**

Suppose:
- Global mean $\mu = 3.5$ stars
- Alice's bias $b_{\text{Alice}} = +0.3$ (she rates 0.3 stars above average)
- Item 1's bias $b_1 = +0.8$ (it is universally loved, rated 0.8 above average)
- Interaction term $\mathbf{p}_{\text{Alice}} \cdot \mathbf{q}_1 = 0.4$

Prediction:
$$\hat{r}_{\text{Alice},1} = 3.5 + 0.3 + 0.8 + 0.4 = 5.0 \text{ stars}$$

The biases capture the baseline (Alice is generous, Item 1 is popular), while the interaction term captures Alice's specific affinity for Item 1 beyond these baselines.

### Complete Implementation

```python
import numpy as np
from typing import List, Tuple, Dict
import random

class MatrixFactorization:
    """
    Matrix Factorization using Stochastic Gradient Descent.
    
    This implementation learns user and item embeddings that
    predict ratings through their dot product. We optimize using
    gradient descent with L2 regularization.
    """
    
    def __init__(self, 
                 n_factors: int = 20,
                 learning_rate: float = 0.01,
                 regularization: float = 0.02,
                 n_epochs: int = 20,
                 random_seed: int = 42):
        """
        Initialize the matrix factorization model.
        
        Args:
            n_factors: Number of latent factors (k in our notation)
            learning_rate: Step size for gradient descent (α)
            regularization: L2 regularization strength (λ)
            n_epochs: Number of training passes through the data
            random_seed: Seed for reproducible initialization
        """
        self.n_factors = n_factors
        self.learning_rate = learning_rate
        self.reg = regularization
        self.n_epochs = n_epochs
        
        # Set random seed for reproducibility
        np.random.seed(random_seed)
        random.seed(random_seed)
        
        # These will be initialized during fit()
        self.user_factors = None  # P matrix
        self.item_factors = None  # Q matrix
        self.user_ids = {}  # Map user_id to integer index
        self.item_ids = {}  # Map item_id to integer index
        self.global_mean = 0.0
        
    def fit(self, ratings: List[Tuple[str, str, float]]):
        """
        Train the model on observed ratings.
        
        The algorithm:
        1. Initialize embeddings randomly
        2. For each epoch:
           a. Shuffle ratings (for stochastic gradient descent)
           b. For each rating:
              - Compute prediction
              - Compute error
              - Update embeddings using gradient descent
        
        Args:
            ratings: List of tuples (user_id, item_id, rating)
        """
        # Create integer indices for users and items
        unique_users = sorted(set(r[0] for r in ratings))
        unique_items = sorted(set(r[1] for r in ratings))
        
        self.user_ids = {user: idx for idx, user in enumerate(unique_users)}
        self.item_ids = {item: idx for idx, item in enumerate(unique_items)}
        
        n_users = len(unique_users)
        n_items = len(unique_items)
        
        # Compute global mean rating
        self.global_mean = np.mean([r[2] for r in ratings])
        
        # Initialize factor matrices with small random values
        # Using normal distribution with small std to break symmetry
        self.user_factors = np.random.normal(
            scale=0.1,  # Small values help training
            size=(n_users, self.n_factors)
        )
        self.item_factors = np.random.normal(
            scale=0.1,
            size=(n_items, self.n_factors)
        )
        
        # Training loop
        print(f"Training matrix factorization:")
        print(f"  {n_users} users, {n_items} items, {len(ratings)} ratings")
        print(f"  {self.n_factors} latent factors")
        print(f"  Learning rate: {self.learning_rate}, Regularization: {self.reg}")
        
        for epoch in range(self.n_epochs):
            # Shuffle ratings for stochastic gradient descent
            # This helps avoid getting stuck in local minima
            shuffled_ratings = ratings.copy()
            random.shuffle(shuffled_ratings)
            
            total_squared_error = 0.0
            
            for user_id, item_id, actual_rating in shuffled_ratings:
                # Get integer indices
                u_idx = self.user_ids[user_id]
                i_idx = self.item_ids[item_id]
                
                # Make prediction with current parameters
                predicted = self._predict_single(u_idx, i_idx)
                
                # Compute error
                error = actual_rating - predicted
                total_squared_error += error ** 2
                
                # Store current factors (needed for simultaneous update)
                user_factor = self.user_factors[u_idx].copy()
                item_factor = self.item_factors[i_idx].copy()
                
                # Gradient descent updates
                # Mathematical derivation:
                # L = (r - p·q)² + λ(||p||² + ||q||²)
                # ∂L/∂p = -2(r - p·q)q + 2λp
                # ∂L/∂q = -2(r - p·q)p + 2λq
                # Update: p ← p - α(∂L/∂p) = p + α(2(r-p·q)q - 2λp)
                #         Simplified: p ← p + α(error×q - λ×p)
                
                # Update user factors
                self.user_factors[u_idx] += self.learning_rate * (
                    error * item_factor - self.reg * user_factor
                )
                
                # Update item factors
                self.item_factors[i_idx] += self.learning_rate * (
                    error * user_factor - self.reg * item_factor
                )
            
            # Compute RMSE for this epoch
            rmse = np.sqrt(total_squared_error / len(ratings))
            
            # Print progress every 5 epochs
            if (epoch + 1) % 5 == 0:
                print(f"  Epoch {epoch + 1}/{self.n_epochs}, RMSE: {rmse:.4f}")
    
    def _predict_single(self, user_idx: int, item_idx: int) -> float:
        """
        Predict rating for a user-item pair using integer indices.
        
        Formula: r̂ = p_u · q_i = Σ_f (p_uf × q_if)
        
        Args:
            user_idx: User's integer index
            item_idx: Item's integer index
            
        Returns:
            Predicted rating
        """
        prediction = np.dot(
            self.user_factors[user_idx],
            self.item_factors[item_idx]
        )
        return prediction
    
    def predict(self, user_id: str, item_id: str) -> float:
        """
        Predict rating for a user-item pair using string IDs.
        
        Handles cold start by returning global mean for unknown
        users or items.
        
        Args:
            user_id: User identifier
            item_id: Item identifier
            
        Returns:
            Predicted rating (clipped to 1-5 range)
        """
        # Cold start handling
        if user_id not in self.user_ids:
            return self.global_mean
        if item_id not in self.item_ids:
            return self.global_mean
        
        # Get indices and make prediction
        u_idx = self.user_ids[user_id]
        i_idx = self.item_ids[item_id]
        prediction = self._predict_single(u_idx, i_idx)
        
        # Clip to reasonable range
        return np.clip(prediction, 1.0, 5.0)
    
    def recommend(self, user_id: str, n_recommendations: int = 5,
                 exclude_items: List[str] = None) -> List[Tuple[str, float]]:
        """
        Generate top-N recommendations for a user.
        
        Args:
            user_id: User to generate recommendations for
            n_recommendations: Number of items to recommend
            exclude_items: Items to exclude from recommendations
            
        Returns:
            List of (item_id, predicted_rating) tuples
        """
        if user_id not in self.user_ids:
            return []  # Cannot recommend for unknown user
        
        if exclude_items is None:
            exclude_items = []
        
        # Get user index
        u_idx = self.user_ids[user_id]
        
        # Predict ratings for all items
        predictions = []
        reverse_item_ids = {idx: item_id 
                           for item_id, idx in self.item_ids.items()}
        
        for i_idx in range(len(self.item_factors)):
            item_id = reverse_item_ids[i_idx]
            if item_id not in exclude_items:
                pred_rating = self._predict_single(u_idx, i_idx)
                predictions.append((item_id, pred_rating))
        
        # Sort by predicted rating (descending)
        predictions.sort(key=lambda x: x[1], reverse=True)
        
        return predictions[:n_recommendations]
    
    def get_user_embedding(self, user_id: str) -> np.ndarray:
        """
        Get the learned embedding for a user.
        
        This embedding captures the user's latent preferences.
        """
        if user_id not in self.user_ids:
            return None
        return self.user_factors[self.user_ids[user_id]].copy()
    
    def get_item_embedding(self, item_id: str) -> np.ndarray:
        """
        Get the learned embedding for an item.
        
        This embedding captures the item's latent characteristics.
        """
        if item_id not in self.item_ids:
            return None
        return self.item_factors[self.item_ids[item_id]].copy()
```

## 5. Neural Collaborative Filtering (NCF)

### Beyond Linear Interactions

Matrix factorization uses a linear dot product to model user-item interactions. The prediction is simply the sum of element-wise products:

$$\hat{r}_{ui} = \mathbf{p}_u \cdot \mathbf{q}_i = \sum_{f=1}^{k} p_{uf} \times q_{if}$$

But what if the relationship between users and items is more complex than a linear function can capture? What if there are non-linear patterns in how features interact? This is where Neural Collaborative Filtering comes in. NCF replaces the dot product with a neural network that can learn arbitrary interaction functions.

The key insight is that a neural network with sufficient capacity can approximate any function (universal approximation theorem). By replacing the simple dot product with a multi-layer neural network, we allow the model to discover complex, non-linear patterns in how users interact with items.

### The NeuMF Architecture

The seminal Neural Collaborative Filtering paper introduced an architecture called NeuMF (Neural Matrix Factorization) that combines two parallel pathways:

1. **GMF (Generalized Matrix Factorization)**: Computes element-wise products of user and item embeddings, similar to traditional matrix factorization but generalized
2. **MLP (Multi-Layer Perceptron)**: Learns complex non-linear interactions through dense layers with non-linear activations

The outputs from both pathways are concatenated and passed through a final prediction layer. This architecture gets the best of both worlds: the interpretability and efficiency of linear models through GMF, and the expressiveness of deep learning through MLP.

### Mathematical Formulation

Let me break down each component mathematically.

**GMF Component:**

$$\phi_{GMF} = \mathbf{p}_u^{GMF} \odot \mathbf{q}_i^{GMF}$$

Where $\odot$ denotes element-wise multiplication (Hadamard product). The output is then:

$$\text{output}_{GMF} = \mathbf{h}^T \times \phi_{GMF}$$

Where $\mathbf{h}$ is a learned weight vector. This generalizes matrix factorization by allowing different weights for different latent dimensions.

**MLP Component:**

$$\mathbf{z}_0 = [\mathbf{p}_u^{MLP} \,||\, \mathbf{q}_i^{MLP}]$$

Where $||$ denotes concatenation. Then we pass through multiple layers:

$$\mathbf{z}_1 = \text{ReLU}(\mathbf{W}_1 \mathbf{z}_0 + \mathbf{b}_1)$$
$$\mathbf{z}_2 = \text{ReLU}(\mathbf{W}_2 \mathbf{z}_1 + \mathbf{b}_2)$$
$$...$$
$$\mathbf{z}_L = \text{ReLU}(\mathbf{W}_L \mathbf{z}_{L-1} + \mathbf{b}_L)$$

Where ReLU is the Rectified Linear Unit activation function: $\text{ReLU}(x) = \max(0, x)$

**Final Prediction:**

$$\phi = [\phi_{GMF} \,||\, \mathbf{z}_L]$$
$$\hat{y} = \sigma(\mathbf{w}^T \phi)$$

Where $\sigma$ is the sigmoid function for binary classification (predicting whether user will interact), or identity for rating prediction.

### Complete Numeric Example: Forward Pass

Let me walk through a complete forward pass with actual numbers so you can see exactly how the network processes data.

**Setup:**

User Alice (index 0) and Item Matrix (index 1), both with 4-dimensional embeddings:
- $\mathbf{p}_{Alice}^{GMF} = [0.8, 0.3, 0.5, 0.2]$
- $\mathbf{q}_{Matrix}^{GMF} = [0.6, 0.9, 0.1, 0.7]$
- $\mathbf{p}_{Alice}^{MLP} = [0.7, 0.4]$
- $\mathbf{q}_{Matrix}^{MLP} = [0.5, 0.8]$

GMF weight vector: $\mathbf{h} = [0.5, 0.3, 0.4, 0.2]$

**Step 1: GMF Pathway**

Element-wise multiplication:
$$\phi_{GMF} = [0.8, 0.3, 0.5, 0.2] \odot [0.6, 0.9, 0.1, 0.7]$$
$$= [0.8 \times 0.6, \, 0.3 \times 0.9, \, 0.5 \times 0.1, \, 0.2 \times 0.7]$$
$$= [0.48, 0.27, 0.05, 0.14]$$

Apply weights:
$$\text{output}_{GMF} = [0.5, 0.3, 0.4, 0.2]^T \times [0.48, 0.27, 0.05, 0.14]$$
$$= (0.5 \times 0.48) + (0.3 \times 0.27) + (0.4 \times 0.05) + (0.2 \times 0.14)$$
$$= 0.240 + 0.081 + 0.020 + 0.028 = 0.369$$

**Step 2: MLP Pathway**

Concatenate embeddings:
$$\mathbf{z}_0 = [0.7, 0.4, 0.5, 0.8]$$

First hidden layer (dimension 4 → 3). Suppose weights are:
$$\mathbf{W}_1 = \begin{bmatrix}
0.5 & -0.2 & 0.3 & 0.1 \\
0.2 & 0.4 & -0.1 & 0.3 \\
-0.3 & 0.1 & 0.5 & 0.2
\end{bmatrix}, \quad \mathbf{b}_1 = [0.1, 0.2, -0.1]$$

Matrix multiplication:
$$\mathbf{W}_1 \mathbf{z}_0 = \begin{bmatrix}
(0.5)(0.7) + (-0.2)(0.4) + (0.3)(0.5) + (0.1)(0.8) \\
(0.2)(0.7) + (0.4)(0.4) + (-0.1)(0.5) + (0.3)(0.8) \\
(-0.3)(0.7) + (0.1)(0.4) + (0.5)(0.5) + (0.2)(0.8)
\end{bmatrix}$$

$$= \begin{bmatrix}
0.35 - 0.08 + 0.15 + 0.08 \\
0.14 + 0.16 - 0.05 + 0.24 \\
-0.21 + 0.04 + 0.25 + 0.16
\end{bmatrix} = \begin{bmatrix}
0.50 \\
0.49 \\
0.24
\end{bmatrix}$$

Add bias:
$$\mathbf{z}_1^{\text{pre}} = [0.50, 0.49, 0.24] + [0.1, 0.2, -0.1] = [0.60, 0.69, 0.14]$$

Apply ReLU (everything is positive, so unchanged):
$$\mathbf{z}_1 = [0.60, 0.69, 0.14]$$

Second hidden layer (dimension 3 → 2). Suppose weights are:
$$\mathbf{W}_2 = \begin{bmatrix}
0.4 & 0.3 & -0.2 \\
-0.1 & 0.5 & 0.4
\end{bmatrix}, \quad \mathbf{b}_2 = [0.1, 0.2]$$

$$\mathbf{W}_2 \mathbf{z}_1 = \begin{bmatrix}
(0.4)(0.60) + (0.3)(0.69) + (-0.2)(0.14) \\
(-0.1)(0.60) + (0.5)(0.69) + (0.4)(0.14)
\end{bmatrix}$$

$$= \begin{bmatrix}
0.24 + 0.207 - 0.028 \\
-0.06 + 0.345 + 0.056
\end{bmatrix} = \begin{bmatrix}
0.419 \\
0.341
\end{bmatrix}$$

Add bias and apply ReLU:
$$\mathbf{z}_2 = [0.419 + 0.1, \, 0.341 + 0.2] = [0.519, 0.541]$$

**Step 3: Combine and Final Prediction**

Concatenate GMF and MLP outputs:
$$\phi = [0.369, 0.519, 0.541]$$

Final layer weights: $\mathbf{w} = [0.4, 0.3, 0.3]$

$$\text{logit} = (0.4)(0.369) + (0.3)(0.519) + (0.3)(0.541)$$
$$= 0.148 + 0.156 + 0.162 = 0.466$$

Apply sigmoid for probability:
$$\hat{y} = \sigma(0.466) = \frac{1}{1 + e^{-0.466}} = \frac{1}{1 + 0.627} = 0.614$$

**Interpretation**: The model predicts a 61.4% probability that Alice will interact with (like/click/watch) The Matrix. For rating prediction, we might skip the sigmoid and scale the logit to the rating range.

### Complete PyTorch Implementation

```python
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import Dataset, DataLoader
import numpy as np
from typing import List, Tuple, Dict

class RatingsDataset(Dataset):
    """
    PyTorch Dataset for user-item ratings.
    
    Converts user/item string IDs to integer indices that
    the neural network can process.
    """
    
    def __init__(self, ratings: List[Tuple[str, str, float]]):
        """
        Args:
            ratings: List of (user_id, item_id, rating) tuples
        """
        # Create mappings from IDs to integer indices
        unique_users = sorted(set(r[0] for r in ratings))
        unique_items = sorted(set(r[1] for r in ratings))
        
        self.user_to_idx = {user: idx for idx, user in enumerate(unique_users)}
        self.item_to_idx = {item: idx for idx, item in enumerate(unique_items)}
        
        # Reverse mappings for later use
        self.idx_to_user = {idx: user for user, idx in self.user_to_idx.items()}
        self.idx_to_item = {idx: item for item, idx in self.item_to_idx.items()}
        
        # Convert ratings to indices
        self.ratings = [
            (self.user_to_idx[user], self.item_to_idx[item], rating)
            for user, item, rating in ratings
        ]
        
    def __len__(self):
        return len(self.ratings)
    
    def __getitem__(self, idx):
        user_idx, item_idx, rating = self.ratings[idx]
        return (
            torch.tensor(user_idx, dtype=torch.long),
            torch.tensor(item_idx, dtype=torch.long),
            torch.tensor(rating, dtype=torch.float32)
        )
    
    @property
    def n_users(self):
        return len(self.user_to_idx)
    
    @property
    def n_items(self):
        return len(self.item_to_idx)


class NeuralCollaborativeFiltering(nn.Module):
    """
    Neural Collaborative Filtering (NeuMF) model.
    
    Architecture from: He et al. "Neural Collaborative Filtering" (WWW 2017)
    
    Combines two pathways:
    1. GMF: Generalized Matrix Factorization (element-wise product)
    2. MLP: Multi-layer perceptron (non-linear interactions)
    """
    
    def __init__(self,
                 n_users: int,
                 n_items: int,
                 embedding_dim: int = 32,
                 hidden_layers: List[int] = [64, 32, 16]):
        """
        Args:
            n_users: Number of unique users
            n_items: Number of unique items
            embedding_dim: Dimension of embeddings for GMF
            hidden_layers: List of hidden layer sizes for MLP
        """
        super().__init__()
        
        # GMF pathway embeddings
        self.user_embedding_gmf = nn.Embedding(n_users, embedding_dim)
        self.item_embedding_gmf = nn.Embedding(n_items, embedding_dim)
        
        # MLP pathway embeddings
        self.user_embedding_mlp = nn.Embedding(n_users, embedding_dim)
        self.item_embedding_mlp = nn.Embedding(n_items, embedding_dim)
        
        # Build MLP layers
        mlp_layers = []
        input_size = embedding_dim * 2  # Concatenated user and item
        
        for hidden_size in hidden_layers:
            mlp_layers.append(nn.Linear(input_size, hidden_size))
            mlp_layers.append(nn.ReLU())
            mlp_layers.append(nn.Dropout(0.2))  # Regularization
            input_size = hidden_size
        
        self.mlp = nn.Sequential(*mlp_layers)
        
        # Final prediction layer
        # Input is concatenation of GMF and MLP outputs
        final_input_size = embedding_dim + hidden_layers[-1]
        self.output_layer = nn.Linear(final_input_size, 1)
        
        # Initialize weights properly
        self._init_weights()
    
    def _init_weights(self):
        """
        Initialize model weights.
        
        Uses Xavier initialization for linear layers and
        small normal initialization for embeddings.
        """
        for module in self.modules():
            if isinstance(module, nn.Embedding):
                # Small random values for embeddings
                nn.init.normal_(module.weight, std=0.01)
            elif isinstance(module, nn.Linear):
                # Xavier initialization for linear layers
                nn.init.xavier_uniform_(module.weight)
                if module.bias is not None:
                    nn.init.zeros_(module.bias)
    
    def forward(self, user_indices, item_indices):
        """
        Forward pass through both GMF and MLP pathways.
        
        Args:
            user_indices: Tensor of user indices [batch_size]
            item_indices: Tensor of item indices [batch_size]
            
        Returns:
            Predicted ratings [batch_size]
        """
        # GMF pathway: element-wise multiplication
        user_emb_gmf = self.user_embedding_gmf(user_indices)  # [batch, embedding_dim]
        item_emb_gmf = self.item_embedding_gmf(item_indices)  # [batch, embedding_dim]
        gmf_output = user_emb_gmf * item_emb_gmf  # Element-wise product
        
        # MLP pathway: concatenation and dense layers
        user_emb_mlp = self.user_embedding_mlp(user_indices)  # [batch, embedding_dim]
        item_emb_mlp = self.item_embedding_mlp(item_indices)  # [batch, embedding_dim]
        mlp_input = torch.cat([user_emb_mlp, item_emb_mlp], dim=-1)  # [batch, 2*embedding_dim]
        mlp_output = self.mlp(mlp_input)  # [batch, last_hidden_size]
        
        # Concatenate both pathways
        combined = torch.cat([gmf_output, mlp_output], dim=-1)  # [batch, gmf_dim + mlp_dim]
        
        # Final prediction
        output = self.output_layer(combined)  # [batch, 1]
        return output.squeeze()  # [batch]


class NCFRecommender:
    """
    Complete recommender system using Neural Collaborative Filtering.
    
    Wraps the NCF model with training and inference methods.
    """
    
    def __init__(self, embedding_dim=32, hidden_layers=[64, 32, 16],
                 learning_rate=0.001, device='cpu'):
        """
        Args:
            embedding_dim: Size of embeddings
            hidden_layers: Architecture of MLP pathway
            learning_rate: Learning rate for Adam optimizer
            device: 'cpu' or 'cuda' for GPU
        """
        self.embedding_dim = embedding_dim
        self.hidden_layers = hidden_layers
        self.learning_rate = learning_rate
        self.device = torch.device(device)
        
        self.model = None
        self.dataset = None
        
    def fit(self, ratings: List[Tuple[str, str, float]],
            n_epochs=20, batch_size=32):
        """
        Train the model on ratings data.
        
        Uses Mean Squared Error loss and Adam optimizer.
        
        Args:
            ratings: List of (user_id, item_id, rating) tuples
            n_epochs: Number of training epochs
            batch_size: Batch size for mini-batch SGD
        """
        # Create dataset
        self.dataset = RatingsDataset(ratings)
        
        # Initialize model
        self.model = NeuralCollaborativeFiltering(
            n_users=self.dataset.n_users,
            n_items=self.dataset.n_items,
            embedding_dim=self.embedding_dim,
            hidden_layers=self.hidden_layers
        ).to(self.device)
        
        # Loss and optimizer
        criterion = nn.MSELoss()
        optimizer = optim.Adam(self.model.parameters(),
                              lr=self.learning_rate)
        
        # Create data loader
        dataloader = DataLoader(self.dataset, batch_size=batch_size,
                               shuffle=True)
        
        # Training loop
        print(f"Training NCF model:")
        print(f"  {self.dataset.n_users} users, {self.dataset.n_items} items")
        print(f"  Embedding dim: {self.embedding_dim}")
        print(f"  Hidden layers: {self.hidden_layers}")
        print(f"  Learning rate: {self.learning_rate}")
        
        self.model.train()
        
        for epoch in range(n_epochs):
            total_loss = 0.0
            n_batches = 0
            
            for user_batch, item_batch, rating_batch in dataloader:
                # Move to device
                user_batch = user_batch.to(self.device)
                item_batch = item_batch.to(self.device)
                rating_batch = rating_batch.to(self.device)
                
                # Forward pass
                predictions = self.model(user_batch, item_batch)
                loss = criterion(predictions, rating_batch)
                
                # Backward pass and optimization
                optimizer.zero_grad()
                loss.backward()
                optimizer.step()
                
                total_loss += loss.item()
                n_batches += 1
            
            avg_loss = total_loss / n_batches
            
            # Print progress every 5 epochs
            if (epoch + 1) % 5 == 0:
                print(f"  Epoch {epoch+1}/{n_epochs}, Loss: {avg_loss:.4f}")
    
    def predict(self, user_id: str, item_id: str) -> float:
        """
        Predict rating for a user-item pair.
        
        Args:
            user_id: User identifier
            item_id: Item identifier
            
        Returns:
            Predicted rating (clipped to 1-5 range)
        """
        # Handle cold start
        if user_id not in self.dataset.user_to_idx:
            return 3.0
        if item_id not in self.dataset.item_to_idx:
            return 3.0
        
        self.model.eval()
        with torch.no_grad():
            user_idx = torch.tensor([self.dataset.user_to_idx[user_id]]).to(self.device)
            item_idx = torch.tensor([self.dataset.item_to_idx[item_id]]).to(self.device)
            prediction = self.model(user_idx, item_idx)
            return np.clip(prediction.cpu().item(), 1.0, 5.0)
    
    def recommend(self, user_id: str, n_recommendations=5,
                 exclude_items=None):
        """
        Generate top-N recommendations for a user.
        
        Args:
            user_id: User to recommend for
            n_recommendations: Number of items to recommend
            exclude_items: Items to exclude
            
        Returns:
            List of (item_id, predicted_rating) tuples
        """
        if user_id not in self.dataset.user_to_idx:
            return []
        
        if exclude_items is None:
            exclude_items = []
        
        exclude_indices = {self.dataset.item_to_idx[item]
                          for item in exclude_items
                          if item in self.dataset.item_to_idx}
        
        self.model.eval()
        with torch.no_grad():
            user_idx = self.dataset.user_to_idx[user_id]
            user_tensor = torch.tensor([user_idx] * self.dataset.n_items).to(self.device)
            item_tensor = torch.arange(self.dataset.n_items).to(self.device)
            
            predictions = self.model(user_tensor, item_tensor).cpu().numpy()
        
        # Create recommendations
        recommendations = []
        for item_idx, pred in enumerate(predictions):
            if item_idx not in exclude_indices:
                item_id = self.dataset.idx_to_item[item_idx]
                recommendations.append((item_id, pred))
        
        # Sort by predicted rating
        recommendations.sort(key=lambda x: x[1], reverse=True)
        return recommendations[:n_recommendations]

    """
    Demonstrate Neural Collaborative Filtering with complete
```

### When to Use NCF vs Matrix Factorization

Neural Collaborative Filtering shines when you have large amounts of training data and the relationship between users and items is genuinely non-linear. If you have millions of ratings and complex interaction patterns, NCF can discover sophisticated patterns that linear models cannot. However, on smaller datasets (tens of thousands of ratings), a well-tuned matrix factorization model often performs just as well or better, while being faster to train and more interpretable.

The key is to start simple with matrix factorization, establish a strong baseline, and then experiment with NCF to see if the added complexity yields better results on your specific data.

## 9. Evaluation Metrics

### Why Evaluation is Complex

Evaluating recommendation systems is fundamentally more nuanced than evaluating standard machine learning models. You might achieve excellent offline metrics during development but see poor online performance when you launch to real users. This happens because users respond to recommendations in complex ways that offline data cannot fully capture. Nevertheless, offline metrics remain essential for development, algorithm comparison, and rapid iteration. The key is understanding what each metric actually measures and when it provides meaningful signal.

### Two Paradigms: Rating Prediction vs Ranking

Recommendation systems tackle two related but distinct problems, each requiring different evaluation approaches.

**Rating Prediction** treats recommendation as a regression problem. Given a user and an item, predict the numerical rating the user would assign. This mirrors explicit feedback scenarios where users rate items on a scale, say one to five stars. We evaluate using standard regression metrics like Root Mean Squared Error or Mean Absolute Error.

**Ranking** treats recommendation as a ranking problem. Given a user, produce an ordered list of items that places the items the user will like at the top. This mirrors implicit feedback scenarios where we care about whether users click, purchase, or engage with recommended items. We evaluate using ranking metrics like Precision at K, NDCG, and Mean Reciprocal Rank.

### Rating Prediction Metrics

#### Root Mean Squared Error (RMSE)

RMSE measures the standard deviation of prediction errors. It is the square root of the average squared difference between predicted and actual ratings:

$$\text{RMSE} = \sqrt{\frac{1}{N} \sum_{i=1}^{N} (r_i - \hat{r}_i)^2}$$

Where $r_i$ is the actual rating, $\hat{r}_i$ is the predicted rating, and $N$ is the number of predictions.

The squaring operation means RMSE penalizes large errors more heavily than small errors. A prediction that is off by two stars contributes four times as much error as a prediction off by one star. This makes RMSE sensitive to outliers.

**Complete Numeric Example:**

Suppose we made predictions for five movies:

| Movie | Actual Rating | Predicted Rating | Error | Squared Error |
|-------|--------------|------------------|-------|---------------|
| A     | 5.0          | 4.5              | 0.5   | 0.25          |
| B     | 3.0          | 3.2              | -0.2  | 0.04          |
| C     | 4.0          | 3.8              | 0.2   | 0.04          |
| D     | 2.0          | 2.5              | -0.5  | 0.25          |
| E     | 5.0          | 4.2              | 0.8   | 0.64          |

Step-by-step calculation:

$$\text{Sum of squared errors} = 0.25 + 0.04 + 0.04 + 0.25 + 0.64 = 1.22$$

$$\text{Mean squared error} = \frac{1.22}{5} = 0.244$$

$$\text{RMSE} = \sqrt{0.244} = 0.494$$

**Interpretation**: On average, our predictions are off by about 0.5 stars. This RMSE of 0.494 is reasonably good for a five-star rating system. For comparison, always predicting the mean rating typically gives RMSE around 1.0 to 1.2.

#### Mean Absolute Error (MAE)

MAE measures the average magnitude of errors without squaring, treating all errors equally:

$$\text{MAE} = \frac{1}{N} \sum_{i=1}^{N} |r_i - \hat{r}_i|$$

Using our same example:

$$\text{MAE} = \frac{|0.5| + |-0.2| + |0.2| + |-0.5| + |0.8|}{5} = \frac{0.5 + 0.2 + 0.2 + 0.5 + 0.8}{5} = \frac{2.2}{5} = 0.44$$

**RMSE vs MAE**: Notice RMSE (0.494) is higher than MAE (0.44) because RMSE penalizes the large error on Movie E more heavily. If you care more about avoiding large mistakes, optimize RMSE. If all errors are equally problematic, optimize MAE.

### Ranking Metrics

For ranking metrics, we need to define what we mean by relevant. Typically, an item is considered relevant if the user rated it highly (say four or five stars for explicit feedback) or if they interacted with it (clicked, purchased, watched) for implicit feedback.

#### Precision at K

Precision at K answers this question: "Of the K items I recommended, what fraction were actually relevant?"

$$\text{Precision@K} = \frac{\text{Number of relevant items in top K}}{K}$$

**Complete Numeric Example:**

Suppose we recommend five movies to Alice, and Alice actually likes movies A, C, F, and H (based on her hidden test set preferences). Our recommendations are: A, B, C, D, E.

Let me mark which are relevant:
- A: Relevant ✓
- B: Not relevant ✗
- C: Relevant ✓
- D: Not relevant ✗
- E: Not relevant ✗

Hits in top 5: Two movies (A and C)

$$\text{Precision@5} = \frac{2}{5} = 0.40$$

**Interpretation**: Forty percent of our recommendations were relevant to Alice. This is the recommendation system's precision, analogous to precision in binary classification. High precision means users are unlikely to encounter irrelevant recommendations, which improves user experience.

#### Recall at K

Recall at K answers this question: "Of all the relevant items that exist, what fraction did I include in my top K recommendations?"

$$\text{Recall@K} = \frac{\text{Number of relevant items in top K}}{\text{Total number of relevant items}}$$

**Continuing Our Example:**

Alice likes four movies total: A, C, F, H. We recommended five movies: A, B, C, D, E. We successfully recommended two of the four movies she likes (A and C), but we missed F and H.

$$\text{Recall@5} = \frac{2}{4} = 0.50$$

**Interpretation**: We found fifty percent of the movies Alice would like. Recall measures coverage. High recall means users will discover most of the relevant items in the catalog. There is always a precision-recall tradeoff. By recommending more items (increasing K), we can improve recall but typically hurt precision.

#### Normalized Discounted Cumulative Gain (NDCG)

NDCG recognizes that position matters tremendously in recommendations. Users pay much more attention to the first few items than items lower in the list. NDCG measures both relevance and position, giving more credit for placing relevant items higher.

The formula has three components. First, Discounted Cumulative Gain at position K:

$$\text{DCG@K} = \sum_{i=1}^{K} \frac{\text{relevance}_i}{\log_2(i + 1)}$$

The logarithm in the denominator creates the discounting. Items at position one are not discounted at all (since we add one before taking the log). Items at position two are discounted by $\log_2(3) \approx 1.585$. Items at position three are discounted by $\log_2(4) = 2$, and so on. Relevant items far down the list contribute less to the score.

Second, Ideal Discounted Cumulative Gain (IDCG) represents the best possible DCG if we ranked all relevant items first:

$$\text{IDCG@K} = \sum_{i=1}^{\min(K, |\text{relevant}|)} \frac{1}{\log_2(i + 1)}$$

Finally, Normalized DCG divides actual DCG by ideal DCG to get a score between zero and one:

$$\text{NDCG@K} = \frac{\text{DCG@K}}{\text{IDCG@K}}$$

**Complete Numeric Example:**

Using the same recommendations for Alice: A (relevant), B (not relevant), C (relevant), D (not relevant), E (not relevant). Alice has four relevant items total: A, C, F, H.

**Step 1: Compute DCG@5**

For binary relevance (relevant equals one, not relevant equals zero):

Position 1 (A, relevant): $\frac{1}{\log_2(1+1)} = \frac{1}{\log_2(2)} = \frac{1}{1} = 1.000$

Position 2 (B, not relevant): $\frac{0}{\log_2(2+1)} = 0$

Position 3 (C, relevant): $\frac{1}{\log_2(3+1)} = \frac{1}{\log_2(4)} = \frac{1}{2} = 0.500$

Position 4 (D, not relevant): $0$

Position 5 (E, not relevant): $0$

$$\text{DCG@5} = 1.000 + 0 + 0.500 + 0 + 0 = 1.500$$

**Step 2: Compute IDCG@5**

In the ideal ranking, we place all four relevant items first. But since K equals five, we compute IDCG for four relevant items:

$$\text{IDCG@5} = \frac{1}{\log_2(2)} + \frac{1}{\log_2(3)} + \frac{1}{\log_2(4)} + \frac{1}{\log_2(5)}$$

$$= \frac{1}{1} + \frac{1}{1.585} + \frac{1}{2} + \frac{1}{2.322}$$

$$= 1.000 + 0.631 + 0.500 + 0.431 = 2.562$$

**Step 3: Compute NDCG@5**

$$\text{NDCG@5} = \frac{1.500}{2.562} = 0.585$$

**Interpretation**: Our NDCG of 0.585 indicates reasonably good ranking. A perfect ranking (all relevant items at the top) would give NDCG of one point zero. A random ranking would give NDCG around zero point three to zero point four. Our ranking is good because we placed relevant items A and C in positions one and three respectively, which are high-value positions.

Notice how NDCG captures something that Precision and Recall miss. Suppose we had the same two relevant items in our top five, but they were at positions four and five instead of positions one and three. We would still have Precision at five equals zero point four and Recall at five equals zero point five, but our NDCG would be much lower because the relevant items appeared late in the ranking.

#### Hit Rate at K

Hit Rate is a binary metric that simply asks: "Did we recommend at least one relevant item in the top K?" It equals one if yes, zero if no:

$$\text{Hit Rate@K} = \begin{cases} 
1 & \text{if } |\text{relevant items in top K}| \geq 1 \\
0 & \text{otherwise}
\end{cases}$$

**Our Example:**

We recommended A and C which are both relevant, so:

$$\text{Hit Rate@5} = 1$$

Hit Rate is often averaged across many users to get an overall success rate. It is useful for scenarios where recommending even one good item counts as success, such as when users are likely to engage with multiple recommendations.

#### Mean Reciprocal Rank (MRR)

MRR measures how far down you have to scroll before finding the first relevant item. It returns one divided by the position of the first relevant item:

$$\text{MRR@K} = \begin{cases}
\frac{1}{\text{position of first relevant item}} & \text{if there is a relevant item in top K} \\
0 & \text{otherwise}
\end{cases}$$

**Our Example:**

The first relevant item is A at position one, so:

$$\text{MRR@5} = \frac{1}{1} = 1.0$$

This is the best possible MRR! If our first relevant item had been at position three, MRR would be one-third equals zero-point-three-three. MRR is particularly important for scenarios where users are likely to click on only the first relevant result, such as web search or question answering systems.

```python
import numpy as np
from typing import List, Set, Dict, Tuple
import math

class RecommenderMetrics:
    """
    Comprehensive evaluation metrics for recommendation systems.
    
    Includes metrics for both rating prediction (RMSE, MAE) and
    ranking tasks (Precision, Recall, NDCG, Hit Rate, MRR).
    """
    
    @staticmethod
    def rmse(actual: np.ndarray, predicted: np.ndarray) -> float:
        """
        Root Mean Squared Error for rating prediction.
        
        Formula: RMSE = sqrt(mean((actual - predicted)²))
        
        RMSE penalizes large errors more heavily due to squaring.
        Lower is better.
        
        Args:
            actual: Array of actual ratings
            predicted: Array of predicted ratings
            
        Returns:
            RMSE value
        """
        squared_errors = (actual - predicted) ** 2
        mean_squared_error = np.mean(squared_errors)
        return np.sqrt(mean_squared_error)
    
    @staticmethod
    def mae(actual: np.ndarray, predicted: np.ndarray) -> float:
        """
        Mean Absolute Error for rating prediction.
        
        Formula: MAE = mean(|actual - predicted|)
        
        MAE treats all errors equally regardless of magnitude.
        Lower is better.
        
        Args:
            actual: Array of actual ratings
            predicted: Array of predicted ratings
            
        Returns:
            MAE value
        """
        absolute_errors = np.abs(actual - predicted)
        return np.mean(absolute_errors)
    
    @staticmethod
    def precision_at_k(recommended: List, relevant: Set, k: int) -> float:
        """
        Precision@K: What fraction of recommendations are relevant?
        
        Formula: Precision@K = (relevant items in top K) / K
        
        Measures the quality of recommendations. High precision means
        few wasted recommendations.
        
        Args:
            recommended: Ordered list of recommended item IDs
            relevant: Set of items the user actually liked
            k: Number of recommendations to consider
            
        Returns:
            Precision@K value between 0 and 1
        """
        if k == 0:
            return 0.0
        
        # Take top K recommendations
        top_k = recommended[:k]
        
        # Count how many are relevant
        hits = sum(1 for item in top_k if item in relevant)
        
        return hits / k
    
    @staticmethod
    def recall_at_k(recommended: List, relevant: Set, k: int) -> float:
        """
        Recall@K: What fraction of relevant items are recommended?
        
        Formula: Recall@K = (relevant items in top K) / (total relevant)
        
        Measures the coverage of recommendations. High recall means
        users discover most items they would like.
        
        Args:
            recommended: Ordered list of recommended item IDs
            relevant: Set of items the user actually liked
            k: Number of recommendations to consider
            
        Returns:
            Recall@K value between 0 and 1
        """
        if len(relevant) == 0:
            return 0.0
        
        # Take top K recommendations
        top_k = recommended[:k]
        
        # Count how many relevant items we found
        hits = sum(1 for item in top_k if item in relevant)
        
        return hits / len(relevant)
    
    @staticmethod
    def ndcg_at_k(recommended: List, relevant: Set, k: int) -> float:
        """
        Normalized Discounted Cumulative Gain@K.
        
        NDCG considers both relevance and position. Items that
        appear earlier in the ranking are weighted more heavily.
        
        DCG = sum over positions i of: relevance_i / log2(i + 1)
        IDCG = DCG for perfect ranking
        NDCG = DCG / IDCG
        
        Values range from 0 (worst) to 1 (perfect ranking).
        
        Args:
            recommended: Ordered list of recommended item IDs
            relevant: Set of items the user actually liked
            k: Number of recommendations to consider
            
        Returns:
            NDCG@K value between 0 and 1
        """
        # DCG: Discounted Cumulative Gain
        dcg = 0.0
        for i, item in enumerate(recommended[:k]):
            if item in relevant:
                # Relevance is 1 for relevant items, 0 otherwise
                # Position discount: 1/log2(i+2) where i is 0-indexed
                # We use i+2 because: i+1 for 1-indexing, +1 to avoid log2(1)=0
                dcg += 1.0 / math.log2(i + 2)
        
        # IDCG: Ideal DCG (if we ranked all relevant items first)
        n_relevant_in_k = min(len(relevant), k)
        idcg = sum(1.0 / math.log2(i + 2) for i in range(n_relevant_in_k))
        
        # Avoid division by zero
        if idcg == 0:
            return 0.0
        
        return dcg / idcg
    
    @staticmethod
    def hit_rate_at_k(recommended: List, relevant: Set, k: int) -> float:
        """
        Hit Rate@K: Did we recommend at least one relevant item?
        
        Binary metric: 1 if there's at least one relevant item
        in the top K, 0 otherwise.
        
        Useful when recommending even one good item counts as success.
        
        Args:
            recommended: Ordered list of recommended item IDs
            relevant: Set of items the user actually liked
            k: Number of recommendations to consider
            
        Returns:
            1.0 if there's a hit, 0.0 otherwise
        """
        top_k = recommended[:k]
        for item in top_k:
            if item in relevant:
                return 1.0
        return 0.0
    
    @staticmethod
    def mrr_at_k(recommended: List, relevant: Set, k: int) -> float:
        """
        Mean Reciprocal Rank@K.
        
        MRR = 1 / (position of first relevant item)
        
        Measures how far down users must scroll before finding
        their first relevant item. Higher is better.
        
        Args:
            recommended: Ordered list of recommended item IDs
            relevant: Set of items the user actually liked
            k: Number of recommendations to consider
            
        Returns:
            Reciprocal rank (1/position), or 0 if no hit
        """
        top_k = recommended[:k]
        for i, item in enumerate(top_k):
            if item in relevant:
                # Return reciprocal of position (1-indexed)
                return 1.0 / (i + 1)
        return 0.0
```

### Offline vs Online Evaluation

A crucial insight about recommender evaluation: **offline metrics are necessary but not sufficient**. You can achieve excellent Precision at ten and NDCG at ten on historical data, yet see poor engagement when you deploy to production. This happens because offline evaluation has fundamental limitations.

First, offline evaluation suffers from selection bias. Your historical data only contains ratings for items that users chose to rate. You cannot measure how users would have responded to different recommendations because you never showed them those alternatives. Second, recommendations influence future behavior in complex ways. A mediocre recommendation today might lead to discovering a genre the user grows to love. Conversely, showing only super-safe obvious recommendations might bore users over time. Third, the temporal dynamics matter. User preferences evolve, item popularity changes, and seasonal effects exist. Your offline test set becomes stale quickly.

This is why A/B testing is essential. Once you have a baseline recommender that achieves good offline metrics, you must run controlled experiments with real users. Measure business metrics that actually matter: engagement time, conversion rate, retention, revenue per user. Trust the online results when they conflict with offline metrics. A system with slightly worse offline NDCG but better online engagement is the better system, period.

The workflow is: develop and iterate quickly using offline metrics, then validate with expensive online experiments. Use offline metrics as a compass during development, but let online A/B tests be your final judge of success.
