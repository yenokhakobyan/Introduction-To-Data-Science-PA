## ANSWER KEY AND EXPLANATIONS

### Question 1: **Answer: B**
**Explanation:** Normalization is a database design technique that organizes data to minimize redundancy and dependency. The primary goal is to eliminate data redundancy and reduce the possibility of data anomalies such as insertion, update, and deletion anomalies. While normalization might sometimes impact performance, its main purpose is data integrity, not performance optimization.

### Question 2: **Answer: B**
**Explanation:** The WHERE clause filters individual rows before any grouping occurs, while the HAVING clause filters groups after the GROUP BY operation has been performed and aggregate functions have been calculated. You cannot use aggregate functions in a WHERE clause, but you can use them in a HAVING clause. For example, you would use HAVING to find groups where COUNT(*) > 5.

### Question 3: **Answer: B**
**Explanation:** The fundamental difference between clustered and non-clustered indexes lies in how they organize and store data within the database. A clustered index physically reorders and stores the actual table data according to the index key values. Think of it like reorganizing books on a shelf by alphabetical order of their titles. Once you create a clustered index on a column, the database engine physically arranges all the rows in the table based on the values in that indexed column.

In contrast, a non-clustered index creates a separate data structure that points to the locations of rows in the original table, similar to an index at the back of a book that tells you which page numbers contain specific topics. The original table data remains in its current physical order, but the index provides a roadmap to find specific rows quickly.

This architectural difference has important implications. Since a table can only be physically ordered in one way, you can have only one clustered index per table, typically created on the primary key. However, you can create multiple non-clustered indexes because each one is just an additional lookup structure. The choice between clustered and non-clustered indexes affects query performance differently depending on whether you need to retrieve single rows or ranges of data.

### Question 4: **Answer: C**
**Explanation:** The COUNT(*) function with a WHERE clause that filters for NULL values will return the number of rows where the salary column contains NULL values. COUNT(*) counts all rows that meet the WHERE condition, including those with NULL values in other columns. If you wanted to count non-NULL values, you would use COUNT(salary) instead.

### Question 5: **Answer: B**
**Explanation:** JOIN is the SQL clause used to combine rows from two or more tables based on a related column between them. UNION combines the results of two queries vertically (adds rows), while JOIN combines tables horizontally (adds columns). MERGE is used for insert/update operations, and COMBINE is not a standard SQL clause.

### Question 6: **Answer: A**
**Explanation:** Isolation ensures that concurrent transactions do not interfere with each other. Each transaction should execute as if it were the only transaction running on the database. This prevents issues like dirty reads, phantom reads, and non-repeatable reads. The other options describe Atomicity (B), Durability (C), and Consistency (D).

### Question 7: **Answer: C**
**Explanation:** A foreign key constraint maintains referential integrity between related tables by ensuring that values in the foreign key column must match values in the referenced table's primary key column, or be NULL. This prevents orphaned records and maintains data consistency across related tables.

### Question 8: **Answer: D**
**Explanation:** Both approaches A and B are correct ways to find the second highest salary. Option A uses a subquery to find the maximum salary less than the overall maximum, while option B uses ORDER BY with LIMIT and OFFSET. Option C would return the two highest salaries, not specifically the second highest.

### Question 9: **Answer: B**
**Explanation:** LEFT JOIN returns all rows from the left (first) table and matching rows from the right table. If there's no match, NULL values are returned for the right table's columns. INNER JOIN only returns rows where there's a match in both tables. Performance differences depend on data and indexes, not the join type itself.

### Question 10: **Answer: D**
**Explanation:** Different database systems have slightly different syntax for creating indexes. Option A works in PostgreSQL, option B is standard SQL and works in most systems, and option C works in MySQL. The exact syntax can vary between database vendors, but all these approaches are valid in their respective systems.

### Question 11: **Answer: B**
**Explanation:** COALESCE returns the first non-NULL value from a list of expressions. It's useful for handling NULL values by providing fallback values. For example, COALESCE(nickname, first_name, 'Unknown') would return the nickname if it's not NULL, otherwise the first_name if it's not NULL, otherwise 'Unknown'.

### Question 12: **Answer: C**
**Explanation:** Many-to-many relationships require a junction table (also called a bridge table or associative entity) that contains foreign keys pointing to the primary keys of both related tables. This allows multiple students to be enrolled in multiple courses without violating normalization rules.

### Question 13: **Answer: C**
**Explanation:** A UNIQUE constraint ensures that all values in a column are different. If you attempt to insert a duplicate value into a column with a UNIQUE constraint, the database will reject the operation and return an error. The database does not automatically modify values or simply create warnings for constraint violations.

### Question 14: **Answer: B**
**Explanation:** The CASE...WHEN statement allows you to perform conditional logic within SQL queries. It's similar to if-else statements in programming languages. You can use it in SELECT, WHERE, ORDER BY, and other clauses to create conditional expressions that return different values based on specified conditions.

### Question 15: **Answer: C**
**Explanation:** GROUP BY groups rows that have the same values in specified columns into summary rows. It's typically used with aggregate functions like COUNT, SUM, AVG, etc., to perform calculations on each group. For example, GROUP BY department would group all employees by their department so you could calculate average salary per department.

### Question 16: **Answer: C**
**Explanation:** CONCAT() is a string function used to concatenate (join) strings together, not an aggregate function. Aggregate functions (COUNT, SUM, AVG, MIN, MAX) operate on multiple rows and return a single result value. They're used with GROUP BY to calculate summary statistics for groups of rows.

### Question 17: **Answer: B**
**Explanation:** A database transaction is a logical unit of work that consists of one or more SQL statements that are executed as a single unit. All statements in a transaction either succeed together (commit) or fail together (rollback). This ensures data consistency and follows the ACID properties.

### Question 18: **Answer: C**
**Explanation:** ALTER is the SQL command used to modify the structure of existing database objects like tables. You can use ALTER TABLE to add, drop, or modify columns, add or drop constraints, change data types, etc. UPDATE modifies data within tables, not the table structure itself.

### Question 19: **Answer: A**
**Explanation:** SQL stands for Structured Query Language. It's the standard language for managing and manipulating relational databases. SQL includes commands for querying data (SELECT), modifying data (INSERT, UPDATE, DELETE), and defining database structure (CREATE, ALTER, DROP).

### Question 20: **Answer: B**
**Explanation:** Denormalization is the process of intentionally introducing redundancy into a database design to improve query performance. While normalization reduces redundancy, denormalization strategically adds it back in specific places where the performance benefits outweigh the costs of maintaining redundant data. This is often done in data warehousing and reporting systems.
